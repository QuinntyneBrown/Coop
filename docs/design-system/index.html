Design system

Coop design system

The Coop admin site is where staff and board members of a housing co-operative for retired women look after maintenance requests, documents, members, the board and the co-op's public website. This system writes down every visual and interaction decision for that site once, so each screen is consistent, calm and accessible in both themes.

How to use

In the Angular admin app

  1. Load tokens/tokens.css first, then assets/components.css. Do not copy values out of them.
  2. Use the class names and attributes from each component page. States come from real attributes (disabled, aria-invalid, aria-pressed, aria-selected, aria-current, aria-busy); data-state exists only so these pages can show a state without a pointer.
  3. Theme with data-theme="light|dark" on <html>; with neither, the OS preference applies.
  4. Need a value in TypeScript? Read tokens/tokens.json (W3C DTCG format; dark values under $extensions).

The admin app does not use this system yet. It still renders its own green, Outfit-based styles. The admin mocks in docs/mocks are built on this system and show the target design. Moving the app onto this system is a separate production change; the README's drift log lists every difference it would close.

Changing the system

Change a brand hue in the primitives, a meaning in the semantic tier, a component look in its component tokens. After any colour change run check_contrast.py; after any page change run check_design_system.py. Both live in .claude/skills/extracting-design-systems/scripts/.

python .claude/skills/extracting-design-systems/scripts/check_contrast.py docs/design-system/tokens/tokens.css
python .claude/skills/extracting-design-systems/scripts/tokens_to_json.py docs/design-system/tokens/tokens.css

Provenance

On 20 October 2026 this system replaced Coop's earlier design system. Its visual language (violet accent, rounded system fonts, soft radii, pill buttons, light and dark themes) is adopted as-is from the Shelfie design system. Its components, examples, copy and sources are rewritten from the Coop admin mocks in docs/mocks: 20 pages, 19 dialogs and 9 notifications. The public app is out of scope. The README records what was kept, what was left out and every difference from the implemented admin.
