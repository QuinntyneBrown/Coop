Empty and error states

When an admin list has nothing to show, it says why and what to do next: there is nothing yet, nothing matches the search or filter, or something went wrong. Each case gets one icon, a plain heading, one sentence and one action.

Overview

A blank list worries people. Is the co-op's list really empty, did the search hide everything, or did the page fail to load? The admin answers that question in words, in the same place the list would be, and offers the one thing that moves the person forward.

  • First use: nothing exists yet. Explain what the list is for and offer the action that adds the first item ("New page", "Add director", "Upload file").
  • No results: items exist, but the search or filter hides them all. Name the search and offer "Clear search" or "Show all".
  • Error: the list could not be loaded. Say so, say the person's data is safe, and offer "Try again".
  • Inside a card: a dashboard card with nothing to show keeps its heading and says so in one muted line ("No maintenance requests yet."), with a link to the full list.

Built from empty state, alert, button and card. Whole-page failures (a missing page, no permission) use the error page.

Responsive behaviour

  • The empty state fills the width of the list it replaces and centres its content. Its text is capped at about 36 characters a line so it reads as a short note, not a paragraph.
  • Padding drops from --space-12 to --space-8 for no-results, so the search box and the message stay on one phone screen together.
  • Actions wrap and centre; on a 320px screen a long label ("Clear search") takes its own line rather than shrinking.
  • An error alert spans the column; its "Try again" button wraps under the text on narrow screens.

Accessibility

Role and pattern

An empty state is ordinary content: a heading at the right level for the page (usually <h2>), a paragraph and a button. An error that replaces a list after a request fails is a role="alert". A list region whose contents change after a search uses aria-live="polite" on its container so "No users match “nora”" is announced.

Keyboard

KeyAction
TabReaches the empty state's action, after the page header and search.
Enter / SpaceRuns the action ("New page", "Clear search", "Try again").

Focus

"Clear search" puts focus back in the search field. "Try again" keeps focus on itself while the list reloads, then moves to the list's heading. An empty state never takes focus on its own.

Labelling

The icon is decorative (aria-hidden="true"). The heading says what is missing in words, so the message does not depend on the icon or its colour.

Motion

Empty and error states appear without animation. The swap from spinner to empty state is instant, so nothing moves while someone is reading.

Touch

The action is a full 44px button, centred, with space around it. "Try again" inside an alert is at least 36px tall (.btn--sm) and sits apart from the text.

Drift from the implemented admin

  • One line for every empty case. Maintenance ("No maintenance requests found"), Documents ("No documents found"), Assets ("No assets uploaded yet") and Messages ("No conversations yet") use .empty-state.card with a Material Icons glyph and one paragraph, and show the same text for first use and for no results. The system separates the two and adds a heading and an action, as .pages-empty and .board-empty already do.
  • Empty table rows. Users shows td.empty-row "No users found" inside the table, with "Showing 0-0 of 0 users" below. The system replaces the table and pagination with an empty state.
  • Decorative icons read aloud. The .empty-state icons are Material Icons ligatures without aria-hidden, so "inbox" or "description" is read before the message. The system's icons are stroke SVGs with aria-hidden="true".
  • Missing error states. Only Pages, Board and Website have a load-failure state (.pages-alert--danger and its copies, role="alert", "Try again"). Maintenance, Documents, Users, Assets, Invitations and Messages have none captured; the system's error alert applies to all of them. Recorded, not added to the mocks.
  • Dashboard cards. "No recent requests" and "No recent notices" are bare .empty-state text; the system keeps them as one muted line but adds a link to the full list.
  • Messages. "Select a conversation to start chatting" becomes "Choose a conversation to read it."
  • Visual language. Green, Outfit and Material Icons give way to the system's violet icon circle (.empty__icon), stroke icons and token colours in both themes.
