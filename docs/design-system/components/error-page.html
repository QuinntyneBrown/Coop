Error page

When a whole admin page cannot be shown, the page body is replaced with a calm icon, a plain heading, one or two sentences and a way back to somewhere useful. Nobody should feel they broke something.

Overview

The Coop admin has no error pages today. The system keeps them as a core component so that, when the admin needs one, it looks and reads the same everywhere. Use an error page only when the route itself fails. When one region of a page fails to load (the board list, the pages list, the website content), keep the page and show a danger alert with Try again, as the admin already does, or an error empty state.

  • Page not found: an old link, or a page, document or request that was removed.
  • No access: the signed-in role cannot open this section, for example a BoardMember opening Users or Roles & Privileges.
  • Something went wrong: the server failed. Shows a short reference to mention when asking for help.
  • Offline: no connection, and nothing to show for this page.

The page keeps the normal admin shell: the sidebar on wide screens, the bottom tab bar on phones, so people can always go somewhere else.

Anatomy

  1. Icon.empty__icon, 64px, accent circle; decorative.
  2. HeadingThe page's <h1 class="empty__title">, set in the h2 size.
  3. Explanation.empty__text: what probably happened and that nothing is lost.
  4. Way back.empty__actions: Go to the dashboard, plus Try again where it helps.

Variants

Four pages, one layout. The examples use <h2>; in the admin the heading is the page's <h1>. The icon stays in the accent colour: these pages explain, they do not alarm.

Responsive behaviour

  • Centred in the main column at every width; the text stops at 36 characters.
  • On wide screens the sidebar stays on the left; on phones the bottom tab bar stays at the bottom, so navigation always works.
  • On phones the two actions wrap onto two centred rows. At 320px and at 400% zoom the heading wraps and nothing scrolls sideways.

Theming

Reads the same tokens as the empty state: --color-accent-subtle and --color-fg-accent for the icon, --color-fg-default and --color-fg-muted for the words, on --color-bg-canvas. The heading uses --text-h2. Nothing is theme specific.

Accessibility

Role and pattern

A normal page: skip link, sidebar navigation, main with one <h1>. The document <title> names the problem ("Page not found · OWN Housing Co-op admin") so it is announced on load. The server answers with the matching HTTP status (404, 403, 500).

Keyboard

KeyAction
TabSkip link, sidebar, then the page actions in order.
Enter, SpaceRuns Try again; follows Go to the dashboard.

Focus

On an in-app route change to an error page, focus moves to the <h1> (with tabindex="-1") so the heading is read first. The ring is the shared 2px focus ring.

Labelling

The icon is aria-hidden. The heading carries the whole message in words. The reference is plain text so it can be read aloud or copied.

Content

  • Headings are calm and plain: "We can't find that page", "Only system administrators can open Users", "Something went wrong on our side", "You're offline".
  • Say nobody is in trouble and nothing is lost: "Nothing you did caused this, and nothing was lost."
  • For no access, name the role and who can help: "You're signed in as tavi.moss, a BoardMember. If you need to add or change a user, ask a system administrator."
  • Give a reference only on the server error page, as something to mention: "mention reference COOP-4F2A".
  • Never use a status code or technical words as the heading ("404", "Forbidden", "Internal Server Error").

Drift from the implemented admin

  • No error pages: no mock captures a not-found, no-access, server-error or offline page for the admin. The four variants here are the system's standard, not a record of what the admin shows.
  • Region failures: Board, Pages and Website show .board-alert--danger, .pages-alert--danger and .website-alert--danger banners with role="alert", a Material Icons error_outline glyph and a Try again button. That pattern is right for a region and maps to the system's .alert.alert--danger; three per-screen classes become one.
  • Look: the implemented banners are green-and-Outfit with an icon font. The system's error page uses the 64px stroke-icon circle from the empty state, in the accent colour, with tokens throughout.
  • CSS gap: the inline top padding and heading font remain; there is no page-scale modifier class.
