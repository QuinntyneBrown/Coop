Skip link

The first thing a keyboard reaches on every admin page. It stays out of sight until it has focus, then lets the person jump past the sidebar's thirteen links straight to the page's content.

WCAG 2.2 AAStatus: stableNative <a href="#main">

Overview

Every admin page, signed in or not, starts with <a class="skip-link" href="#main">Skip to content</a> as the first element in <body>, and has a <main id="main"> for it to land on. It meets WCAG 2.4.1 (bypass blocks).

It matters most in the app shell: the sidebar holds the co-op's name and thirteen section links (Dashboard to Settings) before the content starts. Without the skip link, someone using a keyboard or switch presses Tab fourteen times on every page to reach the Users table. This documentation page has one too: press Tab from the address bar to see it.

Anatomy

  1. ContainerRaised surface, --radius-md, --shadow-3, placed --space-4 from the top left when focused, above everything else (--z-tooltip).
  2. Label"Skip to content" in --color-fg-default, no underline, with the shared focus ring around it.

Variants

One link, one target (#main), on every page.

Sizes

One size: body text with --space-2 × --space-4 padding.

States

Two states. At rest it sits above the top of the viewport (top: calc(-1 * --space-24)); on :focus-visible it moves to --space-4. The focused state is forced here with data-state="focus".

  • Focus shows the link and the shared focus ring together. It is the only state anyone sees; there is no hover state because a pointer cannot reach it.
  • Activated: the browser moves to #main, and the next Tab lands on the first control in the content, such as the Users search field.

Responsive behaviour

  • Same at every width: --space-4 from the top left, over whatever is there.
  • From 768px it skips the sidebar. On phones the sidebar is hidden and the tab bar is fixed to the bottom of the screen, so the link mostly skips nothing, but it stays so that every page behaves the same.
  • It fits on one line at 320px CSS width and at 400% zoom.
  • Hidden in print with the sidebar and tab bar.

Theming

Reads --color-bg-surface-raised, --color-fg-default and --shadow-3. The raised surface is lighter than the sidebar in the dark theme, so the link still stands out when it lands on top of it.

Accessibility

Role and pattern

A native link (<a href="#main">) to the <main> landmark. No ARIA. It is moved off screen, never hidden with display: none or visibility: hidden, so it stays in the tab order.

Keyboard

KeyAction
Tab (first press on a page)Focuses the skip link and shows it.
EnterJumps to #main; the next Tab goes to the first control in the content.
Tab again, without pressing EnterHides it and moves on to the co-op name in the sidebar.

Focus

The shared 2px --color-focus-ring with a 2px offset. Because the admin has no sticky top bar, nothing covers the content it lands on.

Labelling

"Skip to content" is the name. Do not add aria-label.

Contrast

Label on raised surface
Focus ring on raised surface

Motion

It slides into place over --duration-fast; reduced motion zeroes the duration so it simply appears.

Touch

Touch users do not see it; it only appears on keyboard focus. Its padded box is still larger than the 24px minimum for switch and keyboard-emulating devices.

Content

  • Always "Skip to content", with the same words on every page, including sign in and onboarding.

Sources

Checked against these mocks:

  • pages/admin-users/default (app shell: sidebar with thirteen links, then main.layout-main)
  • pages/admin-dashboard/default (app shell with the phone tab bar)
  • pages/admin-login/default (sign in: no sidebar and no <main> element)
  • pages/admin-onboarding/default (onboarding: no <main> element)

Drift from the implemented admin

  • No skip link. The implemented admin has none. The "Skip to content" link in the mocks is .mock-skip, added by the mock capture (white with green text) and not part of the app. The system adds .skip-link as the first element of every page.
  • No target id. The admin layout renders <main class="layout-main"> without an id; the capture adds id="main". The system requires <main id="main">.
  • No main landmark on sign in, register, forgot password and onboarding. These pages render no <main>; the capture puts role="main" and id="main" on the app root. The system uses main.auth-layout.
  • Long tab path on phones. Below 768px the admin's sidebar becomes a static block at the top of the page with all thirteen links, so the skip link would matter even more there. The system hides the sidebar on phones and uses the bottom tab bar.
