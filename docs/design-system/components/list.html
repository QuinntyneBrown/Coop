List

A list stacks rows that share one shape: an optional avatar, a title, a short meta line and a trailing status badge or count. Staff meet it on the Dashboard (recent maintenance requests and notices), in Messages (conversations) and in Profiles.

Overview

Use a list when each row is one thing with a name and a line of context, and staff scan down to find one. Use a table when people compare the same columns across rows, as on the Users page (username, role, status, actions). Use a picture list when the picture is how people recognise the thing, as in the Assets library. Use a description list for the labelled facts of one thing.

  • Recent maintenance requests (Dashboard): the request's title links to it, with the date it came in and a status badge.
  • Recent notices (Dashboard): the notice title and the date it was sent.
  • Conversations (Messages): the other person's avatar, the subject, the last message and an unread count.
  • Profiles (Profiles): each of a member's profiles, with the one in use marked Active and the one on screen marked as current.

A list sits flush inside a card (.card.card--flush) with the card's title as its heading, so the row dividers run edge to edge.

Anatomy

  1. Leading avatar (optional)A medium avatar (40px) with the other person's initials. Decorative, aria-hidden, because the row's text names them.
  2. Title.list__title, --text-label. The thing's name; a link when the row opens something.
  3. Meta.list__meta, --text-body-sm in --color-fg-muted. One line of context.
  4. Trailing badge, count or actionA status badge, an unread count (.badge--count) or a small button.
  5. Row.list__item: flex row, 12 × 16px padding, 12px gap, hairline divider except on the last row.

Variants

There is one list. What changes is what sits at either end of the row; choose by what staff need to decide.

Sizes

One size. Row height follows its content: two lines of text with 12px padding top and bottom give a row of about 64px, and a 40px avatar does the same. Do not tighten the padding to fit more rows on the Dashboard; show the four most recent and link to the full list.

  • Current marks the row whose details are on screen beside the list (Profiles, Messages on wide screens): aria-current="true" on its link and --color-accent-subtle behind the row.
  • Loading replaces the rows with one spinner row and a sentence saying what is loading, in role="status".
  • Empty replaces the rows with an empty state that says what will appear and offers the next step. On the Dashboard a short sentence is enough: "No maintenance requests yet."
  • No results after a search says what was searched for and offers Clear search; it never says "yet", because there are items.

Responsive behaviour

  • The row is one flex line at every width. .list__body has min-width: 0, so a long title wraps instead of pushing the badge off screen.
  • At 320 CSS px (400% zoom on a laptop) a row with an avatar, two lines of text and a badge still fits; titles and meta wrap onto more lines. Do not truncate titles: older eyes and screen magnifiers need the whole name.
  • In Messages and Profiles the list and the detail sit side by side from 768px; below that the list fills the screen and choosing a row opens its detail on its own screen, with a Back link.

Theming

The list reads --color-border-default for dividers, --color-fg-default for titles, --color-fg-link for title links, --color-fg-muted for meta and --color-accent-subtle behind the current row. It has no background of its own, so it takes the card's surface in both themes. Badges and avatars bring their own role tokens.

Accessibility

Role and pattern

A native <ul> of <li>, so a screen reader says "list, 4 items" and lets people jump between rows. No ARIA role. A row that opens something carries a real link on its title; never make the row a div with role="link" and tabindex="0".

Keyboard

KeyAction
Tab / Shift+TabMoves between the title links and any buttons, in reading order. Rows are not focus stops.
EnterFollows the focused link.
SpacePresses a focused button in a row.

Focus

Only links and buttons take focus, with the shared 2px --color-focus-ring ring. A row never gets tabindex.

Labelling

Wrap the list in a <section aria-labelledby> that points at its heading ("Recent maintenance requests"). A "View all" link names its destination: "View all requests". The unread count carries hidden text, so it reads "2 unread". The avatar is aria-hidden because the row's text already names the person. aria-current="true" tells a screen reader which profile is on screen.

Row dividers use --color-border-default. They are decorative grouping, so 1.4.11 does not apply; the rows are already separated by their text.

Motion

None in the list. The loading spinner turns on --duration-loop and stops after one turn under prefers-reduced-motion; the sentence beside it carries the meaning.

Touch

A title link is at least one line of 14px text, so give each row its full two-line height (about 64px) and keep 12px between a link and a trailing button. That keeps neighbouring targets well apart for unsteady hands.

Content

  • Title first, in the words people used: "Kitchen tap leak", "Autumn courtyard gathering", "Courtyard gathering".
  • Meta is one line of the most useful context: the date a request came in, when a notice was sent, the last message with its sender.
  • Dates follow the content rules: "8:00 am" today, then "Tue 13 Oct"; add the year only for last year and before.
  • Section headings in sentence case: "Recent maintenance requests", "Recent notices", "My profiles".
  • Newest first wherever time matters. The Dashboard shows the latest four and a "View all requests" link.

Drift from the implemented admin

  • The Dashboard builds its lists from divs (.request-list .request-item, .notices-list .notice-item), so nothing is announced as a list, and the request rows are not links. The system uses ul.list with a link on each request's title.
  • Card headings on the Dashboard are h3 under an h1, skipping a level, and use title case ("Recent Maintenance Requests"). The system uses the next heading level and sentence case.
  • "View all" does not say what it shows; the system says "View all requests".
  • Status badges use .badge .badge-warning/.badge-gray/.badge-info/.badge-success in the green, Outfit theme. The system maps New, Received, Started and Completed to .badge--warning, .badge--neutral, .badge--info and .badge--success.
  • Dates read "Oct 13, 2026" (month first, year always). The system writes "Tue 13 Oct" and drops the current year.
  • Conversation and profile rows are divs with role="link" and tabindex="0" (.conversation-item), or plain divs with no keyboard access at all (.profile-card). The system uses a real link on the title.
  • .conv-avatar shows the first letter of the subject ("C" for Courtyard gathering), which reads as a person's initial; the system shows the other person's initials. The preview and time lines are rendered empty; the system shows the last message and its time.
  • The unread count (.unread-badge) is a bare number; the system adds hidden text so it reads "2 unread".
  • The selected profile (.profile-card.selected) is shown by colour only; the system adds aria-current="true".
  • Messages shows "No conversations yet" for a search with no results; the system has a separate no-results state.
  • Loading uses the Material Icons sync glyph spinning (.spin) with no text; the system uses .loading with a spinner and a sentence in role="status".
  • Global: the implemented admin uses Outfit, Material Icons and a light theme only.
