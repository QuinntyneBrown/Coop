Pagination

A summary of the visible range with previous, page-number and next buttons, shown under a paged table.

WCAG 2.2 AAStatus: stableNative <button>

Overview

Pagination sits under a table and lets people move between pages of results. It shows a text summary on the left ("Showing 1-2 of 4 users") and previous, page-number and next buttons on the right. The admin users list shows two users per page.

  • Use it under a table whose data is paged. It is not used for infinite lists.
  • Only page numbers that exist are shown; the mocks show two pages.

Anatomy

  1. Container (.pagination)Row with space between, --space-3 by --space-5 padding, muted --text-body-sm text.
  2. SummaryRange and total: "Showing 1-2 of 4 users".
  3. Controls (.page-controls)Row of square buttons with --space-1 gap, inside a <nav>.
  4. Previous and nextChevron buttons; disabled at the first and last page.
  5. Page buttonMin 32px square, --radius-sm, 1px --color-border-strong edge.
  6. Current pageAccent fill with --color-fg-on-accent label.

Variants

One variant. The first and last pages differ only in which chevron is disabled.

First page

Showing 1-2 of 4 users
Previous is disabled; page 1 is current.
HTML
<div class="pagination" style="width: 100%;"><span aria-live="polite">Showing 1-2 of 4 users</span><nav aria-label="Pagination"><div class="page-controls"><button type="button" aria-label="Previous page" disabled><span class="material-icons" aria-hidden="true">chevron_left</span></button><button type="button" aria-label="Page 1" aria-current="page">1</button><button type="button" aria-label="Page 2">2</button><button type="button" aria-label="Next page"><span class="material-icons" aria-hidden="true">chevron_right</span></button></div></nav></div>

Last page

Showing 3-4 of 4 users
Next is disabled; page 2 is current.

Sizes

Pagination has one size: buttons are at least 32px square with a 14px label.

States

Hover and focus are forced with data-state.

DefaultHoverFocusCurrentDisabled
  • Current is aria-current="page"; the stylesheet also styles the mocks' .active class.
  • Disabled uses the native attribute at 50% opacity; the mocks use 40%.
  • No loading or ellipsis state is implemented: the mocks never show more than two page numbers.

Responsive behaviour

  • No @media rule targets the pagination in the captured CSS. The row is flex with space between.
  • With two pages the summary and controls fit side by side at 320px. If many pages are ever added, the control row is not designed to wrap and must be specified first.

Theming

The product ships one light appearance; there are no theme variants.

Accessibility

Role and pattern

A <nav aria-label="Pagination"> landmark with buttons. Page controls are buttons here because the app swaps table rows without navigating; if pages have their own URLs use links. The mocks use bare buttons with glyph labels and no landmark; the label and landmark are requirements.

Keyboard

KeyAction
Tab / Shift+TabMoves through previous, each page, and next. Disabled buttons are skipped.
Enter, SpaceGoes to that page.

Focus

Shared focus ring on :focus-visible. After going to a page, keep focus on the same control or move it to the table caption (requirement).

Labelling

Previous and next need aria-label, because the mocks' glyph labels (a single chevron character) are read as "less-than" or nothing. Page buttons label themselves "Page 2" when the visible text is only a digit. The current button has aria-current="page". The summary is a polite live region so the new range is announced.

Contrast

Summary text on surface
Page label on surface
Current label on accent
Button edge on surface
Focus ring on surface

Motion

None.

Touch

Buttons are at least 32px square with a 4px gap, above the 24px minimum (--target-min) but below the 44px comfortable target; keep to two or three controls beside each other on phones.

Content

  • Summary pattern: "Showing {first}-{last} of {total} {things}", for example "Showing 3-4 of 4 users".
  • Page buttons show the number; chevrons show previous and next. Their names are "Page 2", "Previous page" and "Next page".
  • Hide the control when there is only one page; show the summary alone.

Drift

Where the mocks differ from each other or fail WCAG 2.2 AA, the design system resolves it as follows.

  • Previous and next are a bare glyph with no label; the system requires aria-label and uses a Material chevron.
  • Current page is an .active class only; the system requires aria-current="page".
  • Button edge is the light divider colour (1.2:1); the system uses --color-border-strong (3:1).
  • Disabled opacity is 0.4 in the mocks; the system uses 0.5 like the other disabled controls.
  • Buttons are 6px 10px padded with no minimum size and a 13px label; the system sets a 32px minimum and 14px text.
  • No <nav> landmark or live region in the mocks; both are required.
