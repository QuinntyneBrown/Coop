Pagination

The row under a long table that says which part of the list is showing and moves between parts: "Showing 1–2 of 4 users", Previous, 1, 2, Next.

WCAG 2.2 AAStatus: stableNative <nav> + <button>

Overview

Use pagination at the foot of a table whose rows come a page at a time. In the admin that is the Users table, two people per page. The row says in words what is showing, and gives Previous, the page numbers and Next.

  • Show it only when there is more than one page. With one page the numbers say nothing; with no rows the empty state says it all ("No users found").
  • Use buttons when the page changes in place, as it does in the admin today. If a page number ever goes into the address, the same classes go on <a href> links instead.
  • Not for steps. Moving through a wizard uses Back and Next buttons with the step indicator.

Anatomy

  1. Summary"Showing 1–2 of 4 users" in --text-body-sm, --color-fg-muted. A polite live region, so a change of page is announced.
  2. PreviousA .pagination__link button with the word "Previous". Disabled on the first page.
  3. Current pagearia-current="page": accent fill, --color-fg-on-accent number.
  4. Other pageA 44px pill (--target-comfortable, --radius-full) with the number; "Page" is visually hidden so the name is "Page 2".
  5. NextThe word "Next". Disabled on the last page.

Variants

One variant: summary, Previous, every page number, Next. Admin lists are short, so all the numbers fit; there is no ellipsis and no page-size menu. If a list ever grows past seven pages, review this component before adding either.

Page 2 of 2: Next is disabled and Previous is live. The buttons keep their places, so nothing moves under the pointer.

Sizes

One size. Every button is at least 44px square (--target-comfortable) because the people paging through the list may tap less precisely.

States

Hover and focus are forced here with data-state; real pages get them from :hover and :focus-visible. Current uses aria-current="page"; disabled uses the native attribute.

Both themes

Showing 3–4 of 4 users

Showing 3–4 of 4 users

  • Loading: while the next page loads, the pressed button keeps focus and the table body shows a loading row. The summary changes when the rows arrive, not before.
  • One page or none: the whole row is left out. Do not show "Showing 0–0 of 0 users".

Responsive behaviour

  • The row wraps (flex-wrap). From about 30rem the summary sits on the left and the buttons on the right; narrower, the buttons drop under the summary.
  • The button list wraps too. Previous, two numbers and Next need about 15rem. In the Users card on a 320px screen they just fit on one line; where less room is left, as in the narrow example below, Next wraps to a second row and stays in reach. Nothing scrolls sideways at 320px CSS width or at 400% zoom.
  • The table above scrolls sideways inside .table-wrap on a phone; the pagination below it does not scroll and stays in view under the table.

Showing 1–2 of 4 users

In a narrow space the buttons wrap under the summary, and Next can wrap to its own row.

Theming

The current page reads --color-accent and --color-fg-on-accent, the same pair as a primary button, so it re-themes with the accent. Other buttons use --color-fg-default on transparent with a --color-bg-subtle hover; the summary uses --color-fg-muted. All are semantic tokens with light and dark values; the component has no colours of its own.

Accessibility

Role and pattern

There is no APG widget for pagination; it is a navigation landmark around a list of native buttons, as the APG navigation landmark example describes. The current page has aria-current="page", so it is announced as "Page 1, current page". The summary is a polite live region.

Keyboard

KeyAction
Tab / Shift+TabMoves through Previous, the numbers and Next. Disabled buttons are skipped.
Enter, SpaceShows that page. Focus stays on the pressed button.

Focus

The shared 2px --color-focus-ring with a 2px offset, which clears the round button. If the pressed button becomes disabled (Next on the last page), move focus to the current page number so it is not lost.

Labelling

Label the landmark with what it pages: aria-label="Pagination, users". Previous and Next show their words and add a visually hidden "page"; numbers add a visually hidden "Page" before the number. Visible text stays at the start of each name (WCAG 2.5.3).

Contrast

Current page fill on card

Disabled buttons use --color-fg-disabled; WCAG exempts inactive controls from contrast, and the word stays readable enough to show where Next will be.

Motion

The hover background fades over --duration-fast; reduced motion zeroes it. Changing page does not scroll the page or animate the table.

Touch

Every button is at least 44 × 44px with --space-1 between them, above the 24px minimum and the 44px comfortable target.

Content

  • Summary: "Showing 1–2 of 4 users", with an en dash in the range and the list's own noun ("users", "documents").
  • Buttons: "Previous" and "Next", in words. Never «, », "Prev" or arrows alone.
  • Numbers are plain digits with tabular figures, so the buttons do not change width.

Class / attributeEffect
.paginationOn the <nav>: wrapping row, summary and buttons pushed apart, small muted text.
.pagination__listOn the <ul>: wrapping row of buttons, --space-1 apart, no bullets.
.pagination__linkOn each <button> (or <a>): 44px pill, label font, tabular figures.
aria-current="page"The page showing: accent fill.
disabled / aria-disabled="true"Previous on the first page, Next on the last: disabled colour, no hover. Use aria-disabled on a link.
.visually-hiddenAdds "Page" and "page" to the names without showing them.
data-state="hover|focus"Documentation only: forces a state.

Gap: .pagination has no top border of its own. Inside a flush table card, add a hairline above it (border-top: var(--border-width-hairline) solid var(--color-border-default)), as the example does.

Drift from the implemented admin

  • Markup. The admin uses div.pagination with a span summary and div.page-controls of bare buttons: no <nav> landmark, no list and no live region. The system uses nav.pagination, ul.pagination__list, .pagination__link and a polite summary.
  • Labels. Previous and next are the characters « and » with no accessible name; numbers are bare digits. The system shows "Previous" and "Next" and names numbers "Page 1".
  • Current page. Marked only by button.active with a green fill. The system uses aria-current="page" and the violet accent.
  • Size. Buttons are about 30px tall (6px by 10px padding, 14px text), 4px apart, with a 6px radius and a grey border. The system uses 44px pills with no border.
  • Disabled. Disabled buttons get a grey fill and a darker grey border. The system only greys the label.
  • Empty list. The empty and no-results states still show "Showing 0-0 of 0 users". The system leaves the pagination out when there is one page or none.
  • Copy. The range uses a hyphen ("1-2"); the system uses an en dash ("1–2"). The admin font is Outfit; the system uses its own rounded system fonts.
