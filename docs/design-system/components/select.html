Select

Choose one value from a list the admin already knows: the role for a new user, the type of a document, the priority of a maintenance request. A native <select> with the system's border, chevron and states.

Overview

Put .select on a native <select> and wrap it in a form field for its label, help and error. The browser draws the open list, so it works with every keyboard, screen reader and phone picker without extra code.

Six admin screens use a select:

  • Role in the Add New User and Edit User dialogs.
  • Type in the Create Invitation dialog (Member, Board member, Staff).
  • Priority and Category in the New Maintenance Request dialog, each starting on an empty "choose" option.
  • Type (Notice, By-law, Report) and Status (Draft, Published) in the New Document dialog.
  • Scope (Global, Default) on the Theme tab of Settings.

Use a select when there is one answer from five or more options, or when space is tight. With two to four options that people should compare, a radio group shows them all at once. Never use a select to navigate or to run an action; use a menu or tabs. Changing a select never submits or moves the page by itself.

Anatomy

  1. LabelFrom the form field; always visible and tied with for.
  2. ValueThe chosen option, --text-body (16px) in --color-fg-default.
  3. ChevronTwo small triangles drawn in currentColor behind the text, so it always matches the value colour. The right padding keeps room for it.
  4. Container--field-bg and --field-border, --radius-md, hairline border, --control-height-md tall.

Variants

With a value chosen

Most admin selects open on a sensible default: a new user is a Member, a new document is a Draft Notice. Pre-select the option most people need, and the person only changes it when they mean to.

Published documents show on the home page and the members' documents page.
Role from Add New User; Type and Status from New Document. Help text is joined with aria-describedby.
HTML
<div class="field">
  <label class="field__label" for="role">Role</label>
  <select class="select" id="role" name="role">
    <option value="Member" selected>Member</option>
    <option value="BoardMember">Board member</option>
    <option value="SystemAdministrator">System administrator</option>
  </select>
</div>

With a "choose" option

When there is no safe default, start on an empty first option that says what to do, and mark the select required. The empty value="" means "nothing chosen", so the form can say so in plain words. New Maintenance Request does this for Priority and Category.

Priority keeps its natural order, lowest to most urgent. The Category value stays HVAC for the server while the text says what it means.
HTML
<select class="select" id="priority" name="priority" required>
  <option value="" selected>Choose a priority</option>
  <option value="Low">Low</option>
  <option value="Medium">Medium</option>
  <option value="High">High</option>
  <option value="Urgent">Urgent</option>
</select>

Sizes

Medium is the default and the only size the admin forms need. Small (.select--sm) fits a select into a toolbar or table header beside small buttons; no admin screen uses it today. There is no large select.

Small 36px (.select--sm, --font-size-sm) and medium 44px (--control-height-md, 16px text).

States

Hover and focus are forced with data-state; invalid and disabled use the real attributes. A select has no read-only state: browsers ignore readonly on it.

Both themes

  • Invalid adds a --color-danger-solid border plus an inset ring, so the edge reads as 2px without moving anything. It always comes with a .field__error such as "Choose a priority."
  • Disabled is the saving state: while a dialog saves, its selects are disabled so the choice cannot change under the request. The value stays visible in --color-fg-disabled on --color-bg-subtle.
  • Open is drawn by the browser or the phone's own picker and follows the theme through color-scheme.

Responsive behaviour

  • A select is width: 100% of its field at every width, so it reflows to one column at 320px and at 400% zoom. Cap it with an inline max-width only when the options are short, such as Scope.
  • On phones the native picker opens: a wheel on iOS, a sheet on Android. Nothing about the component changes.
  • The value is 16px at every width, so no phone zooms the page when the select gets focus.
  • A long option is cut off in the closed select by the browser. Keep options short so the chosen value is always readable.

Theming

The select shares the text field's two component tokens. --field-bg is --color-bg-surface by default and --color-bg-subtle when disabled. --field-border is --color-border-strong by default, --color-fg-muted on hover, --color-focus-ring on focus and --color-danger-solid when invalid. The chevron is currentColor, so it turns muted with the text when disabled and flips with the theme for free.

/* Each state only reassigns the two tokens */
.select:hover { --field-border: var(--color-fg-muted); }
.select[aria-invalid="true"] { --field-border: var(--color-danger-solid); }

Accessibility

Role and pattern

Native <select>: screen readers announce it as a combo box or pop-up button with its label and current value. The system does not build a custom listbox; the native control already meets the WAI-ARIA APG Listbox expectations and works with every phone picker.

Keyboard

KeyAction
Tab / Shift+TabMoves focus into and out of the select. A disabled select is skipped.
Space or Alt+↓Opens the list.
↑ / ↓Moves through the options. On Windows this changes the value even while the list is closed, which is why a change must never act on its own.
A letter keyJumps to the next option starting with that letter ("U" for Urgent).
Enter / EscChooses the highlighted option, or closes the list without changing it.

Focus

The border turns --color-focus-ring and the shared 2px ring hugs the box with no offset. In a dialog, focus starts on the first field, not on a select further down.

Labelling

Every select has a visible <label for>. Do not add an aria-label that repeats the label: the visible label is then not connected, clicking it does nothing, and the two can drift apart. Join help and error text with aria-describedby; set aria-invalid="true" while the error shows.

Disabled text is exempt from the minimums; it only shows while a form saves.

Motion

The border colour fades over --duration-fast; reduced motion sets it to zero. The open list has no animation of its own.

Touch

The medium select is 44px tall and as wide as its field. The small one is 36px tall, still above the 24px minimum.

Content

  • The label is a short noun: "Role", "Type", "Status", "Priority".
  • Option text is plain words in sentence case: "Board member", "System administrator", "By-law". Keep system names such as BoardMember in the value only.
  • Spell out short forms: "Heating and cooling", not "HVAC".
  • Keep a scale in its natural order (Low, Medium, High, Urgent); otherwise sort by how often people choose each option, with the default first.
  • A "choose" option starts with "Choose": "Choose a priority". It is never a real answer.
  • The options in a list match the names used elsewhere in the admin. If Roles & Privileges says "System administrator", so does the Role select.

Drift from the implemented admin

  • Look. The admin styles bare select elements inside .form-group (and .scope-group on Settings) with an 8px radius, a pale grey border, 14px Outfit text and the browser's own arrow. The system uses .select: --radius-md, a --color-border-strong edge that passes 3:1, 16px text and a drawn chevron. The admin's pale border is well under 3:1 against white.
  • Focus. The admin removes the outline and shows a green border with a faint green glow. The system keeps the shared 2px --color-focus-ring.
  • Labels. Every admin select has a <label> with no for and repeats its name in aria-label. The system ties the visible label with for and drops the copy.
  • Required and invalid. Priority and Category start on "Select priority" and "Select category" with value="", but are not required: the invalid mock shows them as valid, with no message. The system marks them required, sets aria-invalid and shows a .field__error; the "choose" text reads "Choose a priority".
  • Option names. The user dialogs offer "Member", "Board Member" and "Admin" (value Admin), while Roles & Privileges lists System administrator, Board member, Member, Staff and Support. Invitations offer "Staff" with the value StaffMember. The system shows the same plain names everywhere, in sentence case.
  • Saving. In New Document's busy state the Type and Status selects stay enabled while the Save button reads "Saving…". The system disables them until the answer arrives.
  • Short forms. Category shows "HVAC". The system shows "Heating and cooling" and keeps HVAC as the value.
  • Theme. The admin is light only. The system select follows both themes through tokens and color-scheme.
