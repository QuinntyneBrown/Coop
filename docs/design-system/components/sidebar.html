Sidebar navigation

The admin's main way around. A column beside every signed-in page that names the co-op, lists all thirteen sections in the same order every time, marks where you are, and shows who is signed in.

Overview

Every signed-in admin page sits in an .app-shell: the .sidebar on the left and the page in .app-shell__main. Staff and board members use it to move between sections; it never changes between pages, so people can rely on finding Maintenance in the same place every time.

  • Use it for the admin's top-level sections only: Dashboard, Maintenance, Documents, Pages, Board, Website, Messages, Users, Roles & Privileges, Profiles, Assets, Invitations and Settings.
  • Do not use it for views inside a section, such as the Theme, Content and Account parts of Settings; those are tabs. Filters such as New or Completed are pill tabs, not sidebar links.
  • Below 768px the sidebar is hidden. The top bar carries the brand and a link to My profile, and the tab bar carries the four busiest sections plus More, which opens this same list of thirteen links in a dialog.
  • Sign-in, registration and forgotten-password pages have no sidebar; they use the auth layout.
  • In these pages, .sidebar--static shows the sidebar in the flow of the page at every width, with a border and rounded corners.

Anatomy

  1. Brand.sidebar__brand: the co-op's logo mark (32px tile) and "OWN Housing Co-op" in --text-h4. A link to the Dashboard.
  2. Current link.nav-link with aria-current="page": --color-accent-subtle fill, accent label and icon.
  3. Link.nav-link: 20px stroke icon in --color-fg-subtle, label in --text-label, 44px tall, full width, --radius-md corners.
  4. Navnav.sidebar__nav with aria-label="Admin"; a column of links with 4px between them. Optional .sidebar__group headings.
  5. Footer.sidebar__footer above a hairline: the person's initial in a small avatar, their username (.sidebar__user-name, truncates) and role (.sidebar__user-role).

Sizes

One width, --layout-sidebar-width (256px), and full viewport height from 768px. Links are always 44px tall. The sidebar does not collapse to icons; labels stay visible because icons alone are hard to recognise.

States

The sidebar has no state of its own; its links do. Hover and focus are forced with data-state; current uses the real aria-current="page".

  • Current: the link for the section you are in has aria-current="page", an --color-accent-subtle fill and accent label and icon. A page inside a section, such as one maintenance request, keeps that section current.
  • No current link: a page outside the thirteen sections (for example your own profile or change password) marks nothing current rather than guessing.
  • Long name: the username truncates with an ellipsis; the role wraps. Nav labels never truncate.

Responsive behaviour

  • Base (phones, up to 767px): .sidebar is display: none. .app-shell is one column; the top bar shows the brand and a link to My profile, and the fixed tab bar shows Dashboard, Requests, Documents, Messages and More.
  • Every section on a phone: More is a <button aria-haspopup="dialog"> that opens a dialog titled "All sections". Its body reuses .sidebar__nav with the same thirteen .nav-links, icons, order and aria-current="page" as the sidebar, followed by My profile, so the nine sections without a tab are still two taps away. See the tab bar example. No extra CSS: the list is the sidebar's own.
  • From 768px (--layout-breakpoint-md): .app-shell becomes a two-column grid, --layout-sidebar-width then the page. The sidebar is sticky at the top, as tall as the viewport, and scrolls on its own if the window is short, so the footer is always reachable.
  • At 400% zoom a 1280px window is 320 CSS px wide, so the phone layout applies: no sidebar and no horizontal scrolling. Nothing in the sidebar has a fixed pixel height; links grow with text size.
  • .app-shell__main has min-width: 0 so wide tables scroll inside their own wrapper instead of pushing the page sideways.

Theming

The sidebar sits on --sidebar-bg, which aliases --color-bg-surface, with a hairline right edge in --color-border-default. Links read --color-fg-muted with --color-fg-subtle icons, --color-bg-subtle on hover, and the accent pair when current. The dark theme swaps only those semantic tokens. To tint the sidebar for one deployment, override --sidebar-bg; do not change .nav-link.

.sidebar { --sidebar-bg: var(--color-bg-surface-sunken); }

The logo mark is drawn with token fills (--color-accent, --color-accent-subtle, --color-accent-subtle-hover and --color-bg-surface), so it follows the theme.

Accessibility

Role and pattern

A <header class="sidebar"> placed outside <main> is the page's banner landmark. It holds a native <nav aria-label="Admin"> of links, following the APG landmark regions guidance. The current page is aria-current="page". No menu or tree roles: these are ordinary links and work with Tab alone. Below 768px the sidebar is display: none, so screen readers meet only the phone navigation.

Keyboard

KeyAction
Tab / Shift+TabSkip link, brand, then each of the thirteen links in order, then the page. The footer is not focusable.
EnterFollows the link.

Focus

The shared 2px --color-focus-ring with 2px offset on the brand and every link, including the current one (the ring is checked against --color-accent-subtle as well as the surface). The skip link lets keyboard users jump past all thirteen links straight to the page.

Labelling

Each link's visible word is its name; icons are aria-hidden. The logo mark is decorative, so the brand link reads "OWN Housing Co-op". The nav is labelled "Admin" so it is distinguishable from any other navigation on the page. The avatar initial is aria-hidden because the username beside it already says who is signed in.

Motion

Links fade their background and colour over --duration-fast. The sidebar itself never slides or collapses. Reduced motion zeroes the fade.

Touch

Every link is the full sidebar width and 44px tall (--target-comfortable), with 4px between links. On touch screens wider than 768px, such as a tablet, that keeps neighbouring sections from being tapped by mistake.

Content

  • Link labels are the section names, the same words as each page's heading, in sentence case: "Dashboard", "Maintenance", "Roles & Privileges" (the one label that keeps its capitals, because it names the screen).
  • One or two words per link. A label that wraps at 256px is too long.
  • Every section has its own icon, and the same icon means the same section everywhere: the tab bar, dashboard quick actions and empty states.
  • The brand is the co-op's name exactly as it is written: "OWN Housing Co-op".
  • The footer shows the person's display name and role in words, for example "Mira Fern" and "System administrator", never the stored role key.

Drift from the implemented admin

  • Classes: the admin renders aside.sidebar > .sidebar-header .logo, nav.sidebar-nav of a.nav-item, and .sidebar-footer .user-info .user-avatar .user-name .user-role, inside .layout .layout-sidebar .layout-main. The system uses header.sidebar, .sidebar__brand, .sidebar__nav, .nav-link, .sidebar__footer and .app-shell.
  • Current page: the admin marks it with .nav-item.active (a solid green fill with white text) and no aria-current, so it is visual only. The system uses aria-current="page" with the accent-subtle fill.
  • Landmark: the admin's nav.sidebar-nav has no accessible name, and the sidebar is an <aside> (complementary). The system uses a <header> banner and aria-label="Admin".
  • Brand: the admin's logo and co-op name are a plain div, not a link, and the logo uses its own terracotta, peach and cream palette. The system makes the brand a link to the Dashboard and draws the mark with theme tokens.
  • Phones: at 768px and below the admin turns the sidebar into a static block above the page and also shows the bottom tab bar, so a phone shows the brand, thirteen links and the user before the page heading, then a second navigation at the bottom. The system hides the sidebar below 768px and uses the top bar and the tab bar, whose More tab opens the full section list in a dialog.
  • Sizes: the admin sidebar is 260px wide and fixed; links are about 40px tall with a 10px radius, in Outfit, with Material Icons glyphs. The system uses 256px (--layout-sidebar-width), 44px links, --radius-md, the system font stack and stroke SVG icons.
  • Breakpoint: the admin switches at max-width: 768px, so at exactly 768px it shows the phone layout; the system switches with min-width: 48rem.
  • Theme: the admin is light only. The system adds the dark theme.
  • The user footer shows the raw username and role name in both; the system keeps that content and only restyles it.
