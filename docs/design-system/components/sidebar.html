Sidebar

A vertical list of page links with a logo header and, in the admin shell, a signed-in user footer.

WCAG 2.2 AAStatus: stableNative <nav> and <a>

Overview

The sidebar is the primary navigation for a signed-in area: a logo header, a vertical list of destinations and, on the admin shell, a footer showing who is signed in. It is a list of links to pages, so it is a <nav> of <a> elements, never buttons.

  • Admin shell uses .nav-item links with a leading Material icon, and a footer with the signed-in user.
  • Public shell uses .sidebar-link with the same look; it appears beside the page at 1024px and wider and becomes a drawer below that.
  • Use the bottom tab bar for the member app on compact screens and tabs to switch views inside one page.

Anatomy

  1. Container (.sidebar)260px wide (--layout-sidebar-width), white surface, 1px right border, column flex layout.
  2. Header (.sidebar-header)Logo mark and product name; hairline rule below, --space-5 padding.
  3. Nav list (.sidebar-nav)Grows to fill the height and scrolls on overflow; --space-3 padding.
  4. Item (.nav-item / .sidebar-link)20px icon, label, --radius-md corners, --space-3 padding and gap.
  5. Footer (.sidebar-footer)Avatar and user name and role, hairline rule above. Admin shell only.

Sizes

The sidebar has one width, 260px (--layout-sidebar-width), and one item size.

States

Items have four states. Hover and focus are forced here with data-state; real pages get them from :hover and :focus-visible.

ItemDefaultHoverFocusCurrent page
Nav item Documents Documents Documents Documents
  • Current page uses --color-accent-subtle with --color-fg-accent text. The mocks mark it with an .active class set by the router; the design system requires aria-current="page" as well, and the stylesheet styles both.
  • Hover lightens to --color-bg-subtle and darkens the label to --color-fg-default.
  • No disabled, loading, collapsed or badge state is implemented in the mocks.

Responsive behaviour

Behaviour differs between the two shells because the mocks implement it differently.

ShellWidthBehaviour
Admin769px and widerFixed 260px sidebar; the main column is offset by 260px.
Admin768px and narrowerThe sidebar is hidden (display: none) and the offset is removed. The mocks provide no replacement navigation: not implemented.
Public1024px and widerSidebar shown beside the page at z-index: 100.
Public1023px and narrowerThe sidebar is hidden until the top bar hamburger toggles .open, which shows it as a fixed 260px drawer at z-index: 200 over a backdrop at 199. The bottom tab bar carries navigation at rest.

The drawer layers are --z-sticky (100) for the docked sidebar, top bar and tab bar, and --z-drawer (200) for the open drawer. The drawer, backdrop and hamburger are page-level behaviour in the app; this stylesheet documents the docked sidebar only.

Theming

The product ships one light appearance; there are no theme variants.

Accessibility

Role and pattern

A <nav aria-label="Primary"> landmark containing links (WAI-ARIA landmark and the "Disclosure navigation" pattern without a menu role). Do not use role="menu"; the items are page links. The wrapping <aside> in the mocks has no label; the design system requires aria-label on it when it holds more than the nav.

Keyboard

KeyAction
Tab / Shift+TabMoves through the links in DOM order; each link is one stop.
EnterFollows the link.
EscRequirement for the public drawer: closes it and returns focus to the hamburger button. Not implemented in the mocks.

Requirement, not implemented in the mocks: when the public drawer is open, focus moves into it, stays inside until it closes, and the page behind is inert.

Focus

The shared ring (--focus-ring-width 2px, --focus-ring-offset 2px, --color-focus-ring) shows on :focus-visible. The mocks removed it; the design system restores it.

Labelling

The label text is the accessible name. Icons are aria-hidden="true". The current page carries aria-current="page"; the .active class alone is not announced.

Contrast

Motion

Background colour changes over --duration-base; the tokens drop to near zero under prefers-reduced-motion. The drawer slide, if added, must respect the same setting.

Touch

Items are about 44px tall (20px icon plus 24px padding) and full width of the list, above the 24px minimum (--target-min).

Content

  • Labels are one or two words naming the destination in title or sentence case: "Maintenance", "Users", "Roles & Privileges".
  • Use the same noun as the page title it opens.
  • The footer shows the user's handle and role as text; do not rely on the avatar initial alone.

Drift

Where the mocks differ from each other or fail WCAG 2.2 AA, the design system resolves it as follows.

  • Admin active item is white on #3D8A5A (4.2:1, fails AA); public active link is tinted green. The system uses --color-accent-subtle with --color-fg-accent for both.
  • Admin sidebar hides at 768px and below with no replacement; the public sidebar becomes a drawer at 1023px and below. Documented as implemented; unifying them is not decided.
  • Active page is marked with a .active class only; the system requires aria-current="page".
  • Item padding is 10px 14px (admin) or 10px 12px (public) and radius 10px; the system uses --space-3 and --radius-md.
  • No focus indicator in the mocks; the shared focus ring is applied.
  • Admin <aside> has no accessible name and the nav has no label; labels are required.
