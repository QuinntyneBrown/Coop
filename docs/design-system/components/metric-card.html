Metric card

A card that answers one question with one number: how many maintenance requests are open, how many messages are unread. The dashboard opens with four of them, so staff see what is waiting before they read anything else.

Overview

Use a metric card when a count is worth a card of its own: it is one of the first things staff check, and the number alone tells them whether to act. The dashboard shows four in a .metric-grid: open requests, unread messages, documents and active members. Do not add a fifth to fill space; four that matter beat eight that do not.

The metric card is built from two smaller pieces:

  • Stat (.stat): a label above a large number. It works on its own wherever a number belongs inside a larger card.
  • Metric card (.card.metric-card): a stat with a round icon, on its own card.

Use a badge for a status word, a count badge for a small number attached to something else (unread messages on one conversation), and a table when the numbers need to be compared.

Anatomy

  1. Icon.metric-card__icon: a 56px circle (--size-avatar-lg) in a status tint, holding a 20px stroke icon. Decorative, aria-hidden.
  2. Label.stat__label: --text-label in muted ink. Says what is counted. First in the DOM.
  3. Value.stat__value: --text-h2 with tabular numerals, so digits do not shift as they change.
  4. Card.card.metric-card: surface, hairline border, --radius-lg, --shadow-1, 20px padding (--space-5), 16px between icon and stat.

Variants

Dashboard metrics

The icon tint follows what the number asks of staff, the same rule as badges: warning for work waiting, info for messages, success for people, and the accent for neutral counts.

As a link

When the card should open the list it counts, make the whole card an <a>: a.card.metric-card gains a hover border and shadow. The admin's cards are not links today; the dashboard offers "View all" under Recent maintenance requests instead.

Sizes

One size: the value is --text-h2, the label --text-label, 4px apart; the icon circle is 56px. Width comes from the .metric-grid column (at least 14rem).

Responsive behaviour

  • .metric-grid fits as many 14rem columns as the width allows: four across on a laptop, two on a tablet, one on a phone. There is no fixed four-column step, so a card is never squeezed.
  • At 320px, and at 400% zoom, the cards stack in one column, and each card keeps its icon beside the number.
  • A long label wraps under itself (.metric-card .stat has min-width: 0); the number never truncates.

Theming

The card reads the card tokens (--color-bg-surface, --color-border-default, --shadow-1). The stat reads --color-fg-muted for the label and inherits --color-fg-default for the value. The icon circle reads --color-accent-subtle and --color-fg-accent, or the status pair for --warning, --success and --info. All are semantic tokens; nothing is set per theme in the component.

Accessibility

Role and pattern

A static card is plain text in a <div>, read in order: "Open requests 3". No role. The label comes first in the DOM so the number is never heard without its meaning. The link form is a native <a> (WAI-ARIA link pattern) whose name is the label and number.

Keyboard

KeyAction
TabSkips static cards; stops on link cards.
EnterOpens the list a link card counts.

Focus

Static cards are never focusable. A link card shows the shared 2px focus ring around the whole card.

Labelling

The visible label names the number; the icon is decorative and aria-hidden. Loading reads "Documents, loading"; a failed count reads "Active members, not available". The dashboard heading ("Hello, Mira") and the cards' order give the context, so labels do not repeat "on the dashboard".

Motion

None. Numbers do not count up. The loading skeleton shimmers, and stops under prefers-reduced-motion; the link card's hover shadow changes over --duration-fast.

Touch

A static card is not a target. A link card is the whole card, far above 44px tall.

Content

  • Label: a short noun phrase in sentence case that says what is counted ("Open requests", "Unread messages").
  • Value: a numeral. No units unless the label leaves them unclear.
  • Say what a word like "open" includes somewhere staff can find it: here, New, Received and Started.
  • Use the same words as the screen the number comes from: "Documents" on the card, "Documents" in the sidebar.

Sources

Extracted from these admin mocks:

  • pages/admin-dashboard/default (four metric cards)
  • pages/admin-dashboard/partial (open requests at 0, others filled)
  • pages/admin-dashboard/empty (every count at 0)
  • notifications/admin-dashboard-unread/info (the Unread messages card showing 2)

Drift from the implemented admin

  • The admin builds the card as .metric-card > .metric-card-inner with .metric-icon, .metric-info, .metric-count and .metric-label, styled inside the dashboard component. The system uses .card.metric-card, .metric-card__icon and the shared .stat.
  • The count comes before the label in the DOM, so it is read before its meaning. The system puts .stat__label first.
  • Labels are in Title Case ("Open Requests", "Unread Messages", "Active Members"); the system uses sentence case.
  • Icon tiles are 44px rounded squares tinted amber, blue, purple and green from fixed colour values, holding Material Icons glyphs. The system uses 56px circles from the accent and status tokens, with inline stroke icons.
  • The label is drawn in a semi-transparent near-black, and the card radius is 14px. The system uses --color-fg-muted and --radius-lg.
  • The grid is a fixed four columns that drops to one below 768px, so cards are cramped just above that width. The system's .metric-grid fits columns to the space.
  • Counts start at 0 and are set to 0 when a request fails, so loading, failure and a true zero look the same. The system shows a skeleton while loading and a dash with "Not available" on failure.
  • When every request is completed, the source falls back to the total number of requests (filter(…).length || list.length), so "Open requests" shows a number when none are open. The system's rule is that the card shows only New, Received and Started requests, and "0" when there are none.
  • The "unread" notification is not a separate message: it is the Unread messages card showing its count.
