Metric card

The metric card puts one number first: a count, a label and an accent icon, laid out four to a row on the dashboards.

Overview

A metric card shows one headline number with a label and an icon: open requests, unread messages, documents and active members on the dashboards. Four cards sit in a row at the top of each dashboard.

  • It is a summary, not a control. The mocks do not link the cards to anything.
  • Value first in the markup, label second, so the pair reads as "3, Open Requests".
  • An empty dashboard shows 0, not a different component.

Anatomy

  1. Card.card surface with --radius-lg and --shadow-1.
  2. Icon tile3rem rounded square, --color-accent-subtle fill, icon in --color-fg-accent, aria-hidden.
  3. Count--text-h1 with tabular numerals.
  4. Label--text-body-sm in --color-fg-muted.

Variants

One variant. The mocks tint each icon tile differently (amber, blue, violet, green); the design system uses the accent tile for all four (see Drift).

Sizes

The mocks show one size. The card grows with its grid cell; the icon tile is 3rem (the mocks use 44px and 48px, resolved to 48px).

States

The card is static. The only data states are the values themselves:

assignment
0Open Requests
chat
0Unread Messages
Empty dashboard: counts of 0. There is no loading or error presentation for metrics in the mocks.

No hover, focus, active or disabled state exists; the card is not interactive.

Responsive behaviour

From the dashboard styles, the cards sit in a four-column grid (.metric-cards, 16px gap). At a viewport of 768px or narrower the grid becomes one column. The card itself does not change.

ViewportLayout
Above 768pxFour columns.
768px and belowOne column.

Theming

The product ships one light appearance; there are no theme variants. The card reads surface, accent and muted tokens only.

Accessibility

Role and pattern

Static content in a group of divs; no role and no WAI-ARIA widget pattern. The mocks set data-testid only. The design system requires the icon to stay aria-hidden so the card reads as "3 Open Requests".

Keyboard

KeyAction
Not applicableThe card takes no focus. If a card becomes a link in future, it must be an <a> and use the shared focus ring.

Focus

None.

Labelling

The count and label are text and read in order. Do not set a separate aria-label; it would hide the label text.

None.

Not a target.

Content

  • The label is a short plural noun phrase in title case as in the mocks ("Open Requests", "Unread Messages"); keep the same casing across both dashboards.
  • The count is a whole number with no abbreviation. Show 0 rather than hiding the card.
  • Do not add trend arrows or units; the mocks have none.

Drift

  • Mocks: .metric-card is a standalone surface (white, 14px radius, 20px padding, border, shadow). The design system composes .card with .metric-card, so the radius resolves to 16px.
  • Mocks: .metric-icon is 44px on one dashboard and 48px on the other, with a different tint per card (requests, messages, documents, members) and tints that differ between dashboards. Resolved to 48px and one accent tile.
  • Mocks: the tinted icon colours (amber, violet) are below 4.5:1 on their tint; the accent tile passes.
  • Mocks: gap is 14px on one dashboard and 16px on the other. Resolved to 16px.
