Alert

Alerts report the outcome of an action in the page flow. Success and danger are in use; both are announced by role.

WCAG 2.2 AAInline, no toastsrole=status / alert

Overview

An alert is an inline message shown in the page flow, above the content it relates to. The mocks use it for save confirmations ("Profile updated successfully") and as a block for form-level errors. There are no toasts or floating notifications; every message is inline.

  • Success confirms a completed action (profile, password, theme saved).
  • Danger reports a failure for the whole form.
  • Field-level errors under a single input are not alerts; see form field.
  • Warning and info alert styles exist in the stylesheet, but no mock uses them, so only success and danger are documented here. The warning and info colours are in use for badges only.

Anatomy

  1. ContainerHairline border, --radius-sm, padding --space-3 by --space-4, tinted background, bottom margin --space-4.
  2. MessageOne sentence in --text-body-sm, coloured by the variant's foreground token.

Variants

Two variants are in use. The mocks' third message class, .success-message on the public profile, resolves to .alert-success.

Password updated successfully
Invalid username or password
Success announces politely; danger announces assertively.
HTML
<div class="alert alert-success" role="status">Password updated successfully</div>
<div class="alert alert-danger" role="alert">Invalid username or password</div>

Form error block

The mocks also show a standalone form error (.error-message outside a field, on the login and register screens). It has a lighter red fill and a smaller footprint, so the system keeps it as its own class, .error-message-block, rather than as an alert.

Registration failed. Please check your invitation token.
Form-level error with the danger-subtle fill.
HTML
<div class="error-message-block" role="alert">Registration failed. Please check your invitation token.</div>

Sizes

The mocks show one alert size; the alert is as wide as its container and as tall as its text.

States

An alert is shown or not shown. The mocks have no dismiss button, no auto-hide and no icon, so none are documented. The notification mocks show the alert present in the page after a successful save.

StateExample
Success shown
Profile updated successfully
Danger shown
Current password is incorrect
HiddenThe element is not rendered.

Responsive behaviour

No breakpoint rules apply. The alert fills its container at every width and wraps long text onto further lines.

Theming

The product ships one light appearance; there are no theme variants. Each variant sets three component tokens (--alert-bg, --alert-fg, --alert-border).

Accessibility

Role and pattern

WAI-ARIA alert pattern. Requirement: success alerts carry role="status" (polite) and danger alerts carry role="alert" (assertive). The mocks set neither role, so screen-reader users are not told that a save succeeded or failed. For the announcement to work, the role must be on the element when it is inserted or the container must exist before the text is added.

Keyboard

KeyAction
Not applicableThe alert is not focusable and has no controls. Do not move focus to it; the live region announces it.

Focus

None. When a form fails validation, focus stays on the submit button or moves to the first invalid field, not to the alert.

Labelling

The message text is the accessible content. Colour is never the only signal: the text states what happened ("updated successfully", "failed").

Contrast

Success text on tint
Danger text on tint
Form error text on danger-subtle

The mocks' success text (a mid green on a 10% green tint) and danger text (a bright red on its tint) are close to the limit; the design system uses the darker 800 foregrounds.

Motion

None.

Touch

Not a target.

Content

  • Success: past tense, names the object ("Profile updated successfully", "Password updated successfully").
  • Danger: say what failed and, if possible, what to do ("Registration failed. Please check your invitation token.").
  • One or two sentences, no title. The mocks have none.

Drift

  • Mocks: the public profile uses .success-message (centred, with a border and a different green) while the admin screens use .alert-success. Unified to .alert-success.
  • Mocks: .alert-success and .alert-danger have no border and use tinted rgba fills; the system adds a hairline border.
  • Mocks: no role on any message. Requirement: role="status" and role="alert".
  • Mocks: the form-level .error-message shares its class name with the field-level error under inputs. Renamed .error-message-block for the standalone case.
