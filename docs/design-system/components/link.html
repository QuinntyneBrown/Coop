Link

Links take people somewhere: to the forgot-password page, to the full list of maintenance requests, to a page as members see it, to the field that needs fixing. They are plain, underlined anchors with no class.

Overview

A link goes to another page or another place on the page. If activating it changes data (saves, sends, resets, removes), use a button instead. Links are styled by the bare a selector, so any anchor in running text looks right with no class.

  • Inline links sit inside a sentence: "Don't have an account? Sign up."
  • Standalone links stand on their own line or in a card header: "Forgot password?", "Back to sign in", "View all maintenance requests".
  • With a trailing icon: "Open on the website" on each page card, where the icon says the link leaves the admin for the public site.
  • New tab: a maintenance photo opens full size in a new tab, and says so.

Visited links are not styled separately. Staff return to the same screens every day; a visited colour would turn most dashboard and sidebar links a different colour for no useful reason. :visited keeps the default link colour.

Links with their own look have their own pages: the sidebar navigation, the tab bar, pagination and metric cards, menu items in menu, and anchors given .btn in button.

Anatomy

  1. TextSays where the link goes; it is the accessible name. --color-fg-link, inherits the surrounding font.
  2. UnderlineAlways on. --border-width-hairline thick, offset 0.15em; thickens to --border-width-thick on hover.

Variants

All variants use the same styles; they differ in where they sit and how much the text has to carry.

With a trailing icon

Open About us on the website

The icon follows the words, is aria-hidden, and inherits the link colour. Every page card has this link, so a hidden span adds the page name: it reads "Open About us on the website". It means "this leaves the admin"; the link still opens in the same tab, so Back returns.
HTML
<a href="/pages/about-us">Open<span class="visually-hidden"> About us</span> on the website<svg class="icon icon--sm" aria-hidden="true" …></svg></a>

Opens in a new tab

Photo links on a maintenance request open the full photo in a new tab. The image's alt is the link's name, so it ends with "opens in a new tab". Use a new tab only for files like these, never for admin pages.
HTML
<a href="/photos/tap.jpg" target="_blank" rel="noopener">
  <img src="/photos/tap.jpg" alt="Photo 1 of Kitchen tap leak, opens in a new tab">
</a>

Each link's href is its field's #id, so following it moves focus to the field. Links in an alert take the alert's colour.

Sizes

Links take the size of the text around them; there is no size modifier.

States

Hover and focus are forced with data-state; real pages get them from :hover and :focus-visible. Visited and active look the same as default on purpose. Links are never disabled: if a destination is not available to this person's role, do not render the link.

Responsive behaviour

  • Links wrap with their text and never truncate. A long document name in a link wraps onto a second line at 320px and at 400% zoom.
  • Standalone links under the sign-in, register and forgot-password forms stay centred at every width.
  • A card header's "View all" link sits beside the heading and wraps beneath it when the row is too narrow (.cluster wraps).
  • Link text never shows a raw web address; "Web address: /pages/about-us" on page cards is plain text, not a link.

Theming

Links read two semantic tokens: --color-fg-link and --color-fg-link-hover. In light they are deep violets on a pale page; in dark they switch to --palette-violet-300 and --palette-violet-200 so they stay readable on the dark surfaces. Underline thickness comes from the border-width tokens, so a theme never needs to touch it.

a { color: var(--color-fg-link); text-decoration-thickness: var(--border-width-hairline); }
a:hover { color: var(--color-fg-link-hover); text-decoration-thickness: var(--border-width-thick); }

Accessibility

Role and pattern

Native <a href> (the WAI-ARIA APG Link pattern is satisfied by the native element). Never an <a> without href, never a <div role="link" tabindex="0">, and never a link wrapped around another control.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the link.
EnterFollows the link. Space scrolls the page, as with every native link.

Focus

The shared focus ring (--color-focus-ring, offset --focus-ring-offset) on :focus-visible. Error-summary links move focus to their field because each href is the field's #id.

Labelling

The link text is the accessible name and must make sense alone (WCAG 2.4.4). Repeated short links add hidden context: "View all maintenance requests" reads as "View all maintenance requests". A link that opens a new tab says so in its name. Never "click here".

Contrast

Hovered link on card
Error-summary link
Focus ring on card

The underline is always present, so a link never relies on colour alone (WCAG 1.4.1).

Motion

None. Hover changes colour and underline thickness instantly.

Touch

Inline links are exempt from the 24px target rule (WCAG 2.5.8 inline exception). Standalone links sit alone on a line of body text, so their line box and spacing give at least a 24px target; nothing else is tappable within 24px of them.

Content

  • Say where the link goes: "Back to sign in", "View all maintenance requests", "Open About us on the website". A short question is fine when it is what the person is asking themselves ("Forgot password?").
  • Sentence case: "Back to sign in", not "Back to Sign In". No trailing full stop inside the link text.
  • Link the words that describe the destination, not the whole sentence: "Don't have an account? Sign up".
  • Error-summary links say what to do, in the same words as the field's error: "Give the page a title".
  • If the link opens a new tab, its name ends with "opens in a new tab".

Drift from the implemented admin

  • Colour and underline. Admin links are green (#3d8a5a) in the Outfit font, and .forgot-link and .view-all-link remove the underline. The system's links are --color-fg-link (violet) and always underlined.
  • Links without context. The dashboard's Recent maintenance requests card links a bare "View all", and every page card on Pages repeats "Open on the website". The system adds hidden context: "View all maintenance requests", "Open About us on the website".
  • New tab not announced. Maintenance photo links open a new tab but their alt ("Photo 1 of Kitchen tap leak") does not say so. The system ends the name with "opens in a new tab".
  • Link without href. Settings' "Reset to Default" is <a class="reset-link"> with no href. It changes data, so it is a .btn--ghost button here.
  • Card as a link. Each document card is <div role="link" tabindex="0"> wrapping its Delete button. The system puts a real <a href> on the document title and keeps Delete beside it, not inside it.
  • Casing. "Back to Sign In" becomes "Back to sign in".
  • Icon font. "Open on the website" uses the Material Icons open_in_new glyph (correctly hidden). The system uses the stroke SVG above.
