Button

Buttons let co-op staff and board members do something: add a page, save a director, send a notice, remove a user. One primary button per view says what matters most.

WCAG 2.2 AAStatus: stableNative <button>

Overview

Use a button when activating it changes something: it saves a form, opens a dialog, moves a director up the list or removes a page. Use a link when it only takes the person somewhere, such as "Back to sign in" or "Open on the website". Use an icon button for the compact Edit, Delete and Close actions in table rows and dialog headers.

  • Primary is the one action the view exists for: "New page", "Save page", "Add director", "Sign in". Never two per view.
  • Secondary (the default look) is for the other actions that still matter: "Edit", "Cancel", "Choose photo", "Move up".
  • Ghost is the quiet choice that should not compete: "Skip" in onboarding, "Reset to default" under the theme settings.
  • Danger removes something for good. It appears in the confirmation dialog that follows a "Remove" or "Delete" request ("Remove page", "Remove director", "Delete user"), and on the small icon-only Delete that opens such a dialog (see icon button). A labelled "Remove" in a row stays secondary, with a bin icon.

A .btn class on an <a href> is fine when the action is really navigation: "Cancel" on Change password goes back to the dashboard. The element stays a link; only the look changes. There is no link-style button.

Anatomy

  1. Leading icon (optional)1.25em square, 2px stroke, inherits the label colour, aria-hidden="true".
  2. LabelA short verb phrase in sentence case; it is the accessible name.
  3. ContainerHeight from --control-height-*, --radius-full corners (a pill), hairline border, padding from the spacing scale.

Variants

Variants change emphasis, not meaning. Pick by how much attention the action deserves on this view.

Primary, secondary, ghost, danger: highest to lowest emphasis, with danger kept for the confirmation step.
HTML
<button class="btn btn--primary" type="submit">Save page</button>
<button class="btn" type="button">Cancel</button>
<button class="btn btn--ghost" type="button">Skip</button>
<button class="btn btn--danger" type="submit">Remove page</button>

With icons and block

Icons lead the label and are aria-hidden. Repeated row buttons ("Move up", "Remove") keep a short visible label and name their item in aria-label, which starts with the visible words. Block buttons fill the sign-in card. Icon-only buttons have their own page: icon button.
HTML
<button class="btn" type="button" aria-label="Remove Our garden">
  <svg class="icon" aria-hidden="true" viewBox="0 0 24 24">…</svg>Remove
</button>
<button class="btn btn--primary btn--lg btn--block" type="submit">Sign in</button>

Sizes

Medium is the default and already a comfortable 44px target. Small lives inside panels and lists where space is tight ("Change avatar", "Add privilege"). Large is for the one action a whole screen leads to: "Sign in", "Create account", "Get started".

Small 36px, medium 44px, large 52px. Heights --control-height-sm/md/lg; padding --space-3/4/6; font --font-size-sm/md/lg.

Both themes

  • Loading keeps the button's width, hides the label behind a spinner and ignores clicks. Set disabled aria-busy="true" on the pressed button and disabled on its neighbours ("Cancel") so nothing is sent twice, as the page and director dialogs do. The label does not change to "Saving…"; that text goes in the dialog's live region. Because a disabled button drops focus, the page moves focus to the result when the request ends: the toast, the error summary or the updated list.
  • Disabled uses the native attribute: not focusable, 50% opacity. Use it for a request in flight and for the first "Move up" and last "Move down" on the Board list, where the move is impossible. Do not disable a submit button to signal missing fields; let it submit and show the error summary.
  • Pressed does not apply to .btn: the only toggles in the admin are the photo choices in the photo picker, documented in photo picker.

Responsive behaviour

  • On the sign-in, register and forgot-password screens the primary is .btn--lg.btn--block at every width; the card itself is capped at 26rem.
  • In page headers ("Pages" with "New page") the button sits beside the title and wraps beneath it when the row is too narrow (.page-header wraps).
  • In form actions and dialog footers buttons sit end-aligned on one row and wrap when the row is too narrow; the primary stays last.
  • Row actions on Pages and Board ("Edit", "Move up", "Move down", "Remove") wrap onto a second line on phones instead of shrinking.
  • Every size is at least 36px tall and medium is 44px, so no button needs extra hit area on touch screens.
  • Labels do not truncate. Ordinary buttons keep their label on one line; .btn--block lets a long label wrap, so nothing scrolls sideways at 320px or 400% zoom. A label that does not fit at 320px is too long; shorten the verb phrase.

Theming

The button reads semantic tokens through component tokens: --btn-bg, --btn-fg, --btn-border, --btn-bg-hover, --btn-bg-active, --btn-height, --btn-padding and --btn-font-size. Variants and sizes only reassign those; a context can do the same without touching .btn.

/* A context reassigns the component tokens; it never edits .btn */
.some-context .btn { --btn-height: var(--control-height-sm); --btn-font-size: var(--font-size-sm); }

In the dark theme the accent lightens to --palette-violet-300 and the primary label flips to --color-fg-on-accent (--palette-violet-950), so the label stays dark on a light button. Danger does the same with --palette-red-300 and --palette-red-950. The theme preview on Settings shows a primary button; it is a .btn--primary that reads these tokens, not a button with its own inline colours.

Accessibility

Role and pattern

Native <button type="button">, or type="submit" inside a form (the WAI-ARIA APG Button pattern, satisfied by the native element). A link that looks like a button is still an <a href>. Never an <a> without href and never a <div> with a click handler. No ARIA role is needed.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the button in DOM order.
Enter, SpaceActivates the button. Space activates on key up, so a mis-press can be cancelled by moving away first.
Enter in a text fieldSubmits the form through its type="submit" button ("Sign in", "Save page").
Esc in a dialogCloses the dialog as "Cancel" would; it never triggers the danger button.

Focus

One shared ring (--focus-ring-width of --color-focus-ring, offset by --focus-ring-offset) on :focus-visible only, so clicks do not show it. The offset gap shows the surface colour, which keeps the ring visible against the primary fill. In the remove-page and remove-director dialogs focus starts on "Cancel", never on the danger button.

Labelling

The visible label is the accessible name. Where the same short label repeats on a list ("Edit", "Remove", "Move up"), aria-label adds the item and starts with the visible words, so speech users can still say what they see (WCAG 2.5.3): "Edit About us", "Move Margit Halvorsen up". Icons are aria-hidden="true", so an icon's name is never read as part of the label. A loading button keeps its name.

Motion

Background, border and shadow transition over --duration-fast (120ms); the active state moves down 1px. The loading spinner turns once every --duration-loop/2 (700ms). Under prefers-reduced-motion the tokens zero the durations and loops stop after one pass.

Touch

Small 36px, medium 44px and large 52px all clear the 24px minimum; medium and large meet the 44px comfortable target. Small buttons sit at least --space-2 apart in rows.

Content

  • Labels are verb phrases in sentence case: "Add user", "New document", "Save page", "Update password", "Sign in". Never "OK", "Yes", "Submit" or Title Case.
  • Say what happens to what: "Remove page", "Remove director", "Delete user". The safe choice is "Cancel".
  • The confirmation dialog's title asks the question with the item's name ("Remove “Our garden”?") and its body says what follows ("It leaves the website menu straight away. You can add it again later.").
  • Sign-out is "Sign out", a secondary button. It loses nothing, so it is never a danger button.
  • Keep labels to about three words: "Remove director" and "Update password" are as long as they get.
  • Loading does not change the label; status text goes in the live region, toast or summary that follows.

Drift from the implemented admin

The look is adopted from the Shelfie design system. Every difference below is between the running admin and this page.

  • Classes and look. The admin uses .btn .btn-primary/.btn-secondary/.btn-danger/.btn-danger-outline/.btn-sm/.btn-block in green (#3d8a5a) with an 8px radius and the Outfit font. The system uses .btn (secondary by default) with .btn--primary, .btn--ghost, .btn--danger, .btn--sm, .btn--lg and .btn--block, the violet accent, pill corners (--radius-full) and the system font stack. .btn-secondary becomes plain .btn.
  • Outlined danger. Row "Remove" buttons on Pages, Board and the content editor use .btn-danger-outline. The system has no outlined danger: the row button is a secondary .btn with a trash icon, and the red .btn--danger appears in the confirmation dialog and on icon-only Delete triggers.
  • Sign out. Profile shows "Logout" as .btn-danger. Here it is a secondary "Sign out".
  • Casing. Labels are Title Case ("Add User", "New Document", "Sign In", "Create Account", "Update Password", "Edit Profile", "Get Started"). The system uses sentence case.
  • Busy state. Sign in, register and the document dialog set disabled and swap the label ("Signing in...", "Creating...", "Saving…") with no aria-busy; the page and director dialogs add aria-busy but still swap the label. The system keeps the label, sets disabled aria-busy="true", shows the spinner and puts the status in a live region.
  • Confirmations. The user, document and asset delete dialogs say "Confirm Delete" with a bare "Delete" and do not set initial focus. The page and director dialogs name the item, label the button "Remove page" and focus "Cancel". The system follows the page dialog everywhere.
  • Icon font. Buttons use the Material Icons font; on Users, Documents and Maintenance the ligature is not hidden, so "Add User" is announced "add Add User". The system uses inline stroke SVGs with aria-hidden="true".
  • Reset to default. Settings implements "Reset to Default" as <a class="reset-link"> with no href, which a keyboard cannot reach. It is a .btn--ghost button here.
  • Theme preview. The Settings preview "Button" carries inline green colours and a 6px radius. Here the preview is a .btn--primary that reads the theme tokens.
