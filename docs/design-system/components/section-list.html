Section list

The page editor's left pane: the page's sections in the order visitors see them, one selected, with Hide, Move up and Move down acting on it.

Overview

The section list is the left pane of the page editor: the page's sections in the order visitors see them, numbered, with one selected. The tools under the list act on the selected section: Hide (or Show), Move up and Move down. The list is the page: moving a section reorders the public page, hiding it removes it from the public page without losing its text. For a website page the first item is the fixed Page banner and the rest are body blocks, with Remove and an "Add to the page" row of block kinds.

  • Use it in the page editor for Home, Menu and footer and website pages.
  • Do not use it for lists inside a section (menu links, gallery photos): those keep the per-item Move up, Move down and Remove buttons of the form layout.

Anatomy

  1. ItemA <button class="section-list__button"> with a CSS counter for its position; the selected one has aria-current="true".
  2. Hidden badgeA neutral badge "Hidden" beside a struck-through name: the section stays in the list but not on the public page.
  3. ToolsA role="group" "Selected section" with Hide or Show, Move up and Move down; the first and last positions disable the move that cannot happen.

Variants

Home: nine movable, hideable sections. Menu and footer: two fixed sections and no tools. Website page: the fixed Page banner (.section-list__item--fixed, a bullet instead of a number), body blocks with Remove, and the "Add to the page" row (.section-list__add).

Sizes

One size: 44px items in --text-label, small buttons in the tools.

Items have default, hover, focus, selected and hidden states, forced here with data-state.

  • Moved: after Move up or Move down an inline status under the tools says "“Who we are” moved up to position 2." and focus stays on the same button while it is enabled, else on the other move button.
  • Saving: moving and hiding save the draft at once; the buttons are disabled while the API answers.

Responsive behaviour

  • From 64rem the list is the 16rem left pane of the page editor and sticks to the top while the form scrolls. Below 64rem, and at 400% zoom, it is the Sections tab, full width.
  • Long names wrap; the tools wrap onto several lines at 320px.

Theming

The same tokens as the sidebar link: --color-fg-muted for items, --color-bg-subtle on hover, --color-accent-subtle and --color-fg-accent when selected, --color-fg-subtle for numbers and hidden names.

Accessibility

Role and pattern

An ordered list of buttons, so the numbering is real list semantics and each item is a native button; aria-current="true" marks the selected section. The tools are a labelled role="group", and every button's visible label is completed with the section's name in visually hidden text ("Move up: Who we are"). This is deliberately not a drag-and-drop list: moving by button works with a keyboard, a switch and a shaky hand.

Keyboard

KeyAction
TabThrough the items in order, then the tools.
Enter / SpaceSelects the section and shows its form in the Edit pane; on a tool, performs it.

Focus

The shared focus ring. After a move, focus stays on the moved section's tool; after Hide, on the Show button that replaces it.

Labelling

The list is labelled "Sections in the order visitors see them". "Hidden" is a visible badge, not colour alone, and the name is also struck through.

Motion

Background fades over --duration-fast; a moved item simply re-renders in its new place.

Touch

44px items; the tools are small buttons but still 36px tall with --space-2 between them, and each has a wide label.

Content

  • Section names are the names visitors would use: "Welcome banner", "Numbers at a glance", "A look around". Never "hero", "glance block" or "CTA".
  • Body blocks are named by kind and start of text: "Heading: Who can apply", "Paragraph", "Bullet list", "Photo", "Link button: Send us a note", "Existing content".
  • Tools are "Hide section" and "Show section", "Move up", "Move down", "Remove".
