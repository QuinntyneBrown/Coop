Layout primitives

The classes that place everything else in the admin: the app shell (sidebar beside the page), the page header, vertical stacks, wrapping rows, the 4, 8 and 12-column grid with its spans, the sticky aside, and the centred card for sign in and onboarding.

Overview

Build every admin page from these primitives instead of writing page-level layout CSS. They read the layout tokens (--layout-columns, --layout-gutter, --layout-margin, --layout-sidebar-width), which change at 768px and 1024px, so pages respond without media queries of their own.

  • .app-shell: the frame of every signed-in page. On phones it is one column and the tab bar is fixed to the bottom; from 768px the sidebar sits beside the page in a 16rem column, full height and sticky.
  • .app-shell__main: on the page's <main id="main">. It sets the side margins (--layout-margin) and leaves --space-12 at the bottom.
  • .page-header: the page's <h1>, an optional .subtitle, and the page's actions (search, the main button). It wraps on phones.
  • .section: --space-8 between the blocks of a page.
  • .stack: children in a column, 16px apart (cards, forms, dialog bodies). .cluster: children in a wrapping row, 12px apart (buttons, filters). .cluster--between pushes the ends apart.
  • .grid with .span-4/5/7/8/full: the column grid; spans are full width until 1024px. .grid--auto fills with 18rem cards. .sticky-aside keeps a side column in view from 1024px.
  • .auth-layout + .auth-card: the centred 26rem column on sign in, register, forgot password and onboarding, with the logo mark above the card.
  • .container: a centred, 1280px-wide column with side margins, for a page outside the shell. Inside .app-shell__main do not add it; the margins are already set.

Related: the dashboard's counts use .metric-grid (see metric card), and lines between blocks are dividers.

Anatomy

The Users page, the shape most admin pages share.

  1. SidebarThe shell's first column from 768px: --layout-sidebar-width (16rem) wide, full height, sticky. Hidden on phones, where the tab bar takes over.
  2. Mainmain#main.app-shell__main: side padding --layout-margin, bottom padding --space-12, on --color-bg-canvas.
  3. Page header.page-header: the <h1> (and a .subtitle when there is one) on the left, --space-6 above and below.
  4. Page actionsOn the right of the header: the search field and the one primary button. They drop under the title when space runs out.
  5. ContentStacks, grids and cards. Sections are --space-8 apart (.section).

Sizes

Primitives have no size modifiers; gaps and widths come from the spacing and layout tokens listed below.

States

Layout primitives are not interactive and have no states; the only change is responsive (see below).

Responsive behaviour

WidthShellColumnsGutterMarginSpans
Base (phones)One column; sidebar hidden; tab bar fixed to the bottom, with room kept for it by .has-tabbar.4--space-4 (16px)--space-4 (16px)All full width; the aside goes under the main column.
768px (--layout-breakpoint-md)Sidebar (16rem) beside main, full height and sticky; tab bar hidden.8--space-6 (24px)--space-8 (32px)Still full width.
1024px (--layout-breakpoint-lg)As at 768px.12--space-8 (32px)--space-12 (48px).span-4/5/7/8 take their columns; .sticky-aside sticks.
  • Mobile first: base styles target phones and only min-width queries in rem (48rem, 64rem) add space, so the breakpoints move with the person's text size.
  • .page-header and .cluster wrap: on a phone the search and the main button drop under the title. Nothing scrolls sideways at 320px CSS width or at 400% zoom; only a wide table scrolls, inside its .table-wrap.
  • .auth-layout keeps --layout-margin around the card, so the card never touches the screen edge.
  • Put .has-tabbar on .app-shell, not on main: .app-shell__main's own bottom padding would win on the same element and the tab bar would cover the last row.

Theming

Most primitives draw no colour; layout tokens change by breakpoint, not by theme. The shell's colours come from semantic tokens: the page on --color-bg-canvas, the sidebar on --color-bg-surface with a --color-border-default edge, the subtitle in --color-fg-muted. Both themes come with them.

Accessibility

Role and pattern

No roles of their own; they go on the right native elements, following the APG landmark regions practice. The skip link comes first; the sidebar is a <nav aria-label="Admin">; .app-shell__main and .auth-layout go on <main id="main">; a .sticky-aside goes on a <section> or <aside> named by its heading.

Keyboard

KeyAction
Tab / Shift+TabFollows DOM order: skip link, sidebar, page header, content. Primitives add no tab stops. Never reorder columns visually with order or grid-row, so focus order matches reading order (list before the open request).

Focus

The admin has no sticky top bar, so nothing covers focused content at the top. On phones, .has-tabbar keeps the last controls clear of the fixed tab bar.

Labelling

The page header holds the page's only <h1>, named as the sidebar item ("Users", "Maintenance"). Sections and asides are named by their visible heading through aria-labelledby.

Contrast

Page title on canvas
Subtitle on canvas
Sidebar text on surface

The sidebar's edge and the card borders are decorative; the change from surface to canvas and the content itself show where one area ends.

Motion

None. html scrolls smoothly to in-page links, and that is turned off under prefers-reduced-motion.

Touch

.cluster puts 12px between neighbours, more than the spacing 24px targets need. Content reflows at 320px CSS width (WCAG 1.4.10), and the sidebar's links and the tab bar's items are 44px tall.

Content

  • The page title is the section's name as the sidebar says it: "Users", "Maintenance", "Digital assets". The dashboard may greet instead: "Hello, Mira".
  • The subtitle, when there is one, says what is here in a few words: "2 assets", "Here's your overview".
  • One primary action in the page header at most; it is the page's main job ("Add user", "New request", "Upload").

Drift from the implemented admin

  • Shell. The admin layout is div.layout (flex) with a fixed 260px .sidebar and .layout-main { margin-left: 260px }. The system uses .app-shell, a grid with a 16rem (256px) sticky sidebar column, and .app-shell__main.
  • Phones. At 768px and below the admin sidebar turns static and stacks above the page with all thirteen links, and the Dashboard, Maintenance, Documents and other pages also show .bottom-tab-bar, so both navigations appear. The system hides the sidebar below 768px and shows only the tab bar.
  • Page header. Each feature declares its own .page-header (flex, space-between, 20px or 24px below, 24px semibold title) and its own page padding (16px on phones, 24px from 769px, sometimes 80px or 100px at the bottom). The system has one .page-header and sets margins once in .app-shell__main.
  • Grids. Each feature writes its own grid: the maintenance .content-area (two equal columns when a request is open), the dashboard's four and two-column grids, and auto-fill grids of 220px to 420px. The system uses .grid with spans, .grid--auto and .metric-grid.
  • Breakpoints. Desktop-first queries in px: max-width 768px (16 times), 600px, 640px and 1023px. The system uses mobile-first min-width queries in rem.
  • Background. The admin repeats a warm off-white page background and min-height: 100vh in several feature styles, in light only. The system uses --color-bg-canvas once, in both themes.
  • Sign in and onboarding. Sign in is a two-panel page (.login-page, a coloured hero beside .login-form-panel) that also shows the phone tab bar to someone not yet signed in; onboarding is .onboarding-page with a 560px .onboarding-card and 40px padding. Neither has a <main>. The system uses main.auth-layout with a 26rem .auth-card and no tab bar.
