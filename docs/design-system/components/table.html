Table

A table lines up the same facts for every row so they can be compared down a column: who has which role, which invitations are still open, and what each role is allowed to do.

WCAG 2.2 AAStatus: stableNative <table>

Overview

Use a table when people compare one column across many rows. The Coop admin has three:

  • Users: username, role, status and row actions (Edit, Delete), with a search field above and pagination below.
  • Invitations: the invitation code, who it is for, when it expires and its status. Read only.
  • Privileges on Roles & Privileges: one row per kind of record (User, Maintenance request, Document, Profile) and a switch for Read, Write, Create and Delete.

Two wrappers: framed (.table-wrap) for a table on its own, with a border and rounded corners, and flush (.table-wrap--flush) inside a .card--flush, where the card is the frame. If each row is one item people open and act on one at a time, such as a maintenance request, use cards or a list instead; they read better on a phone.

Anatomy

  1. Header cell<th scope="col"> on --color-bg-surface-sunken, --text-label in muted ink, sticky to the top of the wrapper.
  2. Body cell--text-body-sm, 12 × 16px padding, hairline divider below. An initials avatar may lead the first cell.
  3. Status cellA badge with a word: Active, Expired, Used.
  4. Actions cellIcon buttons, each named with the row ("Edit mira.fern"). Its header has hidden text.
  5. Wrapper.table-wrap scrolls sideways when the table is wider than the screen; hairline border and --radius-lg unless flush.

Variants

Pick the wrapper by where the table sits, then add the columns the task needs. Inside a flush card use .table-wrap--flush so there are not two frames.

Responsive behaviour

  • The table never squeezes its columns into unreadable slivers. Below its natural width, .table-wrap scrolls sideways inside its frame; the page itself never scrolls sideways. This is the data-table exception to WCAG 1.4.10.
  • Header cells do not wrap (white-space: nowrap) and stick to the top of the wrapper when it scrolls.
  • td.truncate caps long text at 20rem with an ellipsis; the full text is one step away (the Edit dialog or the record itself).
  • Keep tables to four or five short columns. Users and Invitations fit a 360px phone with a little sideways scroll; anything people mostly open one at a time belongs in cards.
  • Pagination wraps under the table; the "Showing" line sits above the page links on a phone.

Theming

Reads --color-bg-surface (wrapper), --color-bg-surface-sunken (header), --color-bg-subtle (row hover), --color-border-default (dividers and frame) and the default and muted ink. In the dark theme the sunken header is darker than the surface, so it still reads as its own band. There are no table-specific colour tokens.

Accessibility

Role and pattern

A native <table> with <caption>, <thead>, <tbody>, <th scope="col"> and, where a column names each row, <th scope="row">. It is a static table, not the APG grid pattern: no role="grid" and no arrow-key navigation between cells.

Keyboard

KeyAction
Tab / Shift+TabMoves between the buttons, links and switches in the table, row by row; or to the scrolling wrapper when the table has none.
Enter / SpaceActivates the focused Edit or Delete button.
SpaceTicks or clears the focused privilege checkbox.
← →Scroll a focused wrapper sideways.
Screen reader table keysMove by cell; each cell is announced with its column and row headers.

Focus

Controls in cells show the shared 2px ring; cell padding keeps it clear of the dividers. After Delete is confirmed, focus moves to the next row's Delete button, or to the page heading when the table is empty.

Labelling

Every table has a <caption>; it may be visually hidden when a visible heading says the same. A header cell above controls still has hidden text ("Actions"). Icon buttons carry the row in their aria-label ("Delete mira.fern") so a list of controls makes sense on its own; a tooltip can show the same words to sighted people. Each privilege checkbox is named by its column and row ("Write, Document").

Motion

Row hover is a colour change; controls change over --duration-fast, which reduced motion zeroes.

Touch

Icon buttons are 40px square with 4px between them, and each privilege switch sits in a label at least 24px tall inside a 12px-padded cell. Hover highlighting is a pointer nicety only; nothing depends on it.

Content

  • Column headers are one or two words in sentence case: "Username", "Role", "Status", "Invitation code", "Expires".
  • Show roles as words, not code names: "System administrator", "Board member", "Member".
  • Status is a badge with a word (Active, Expired, Used), never a coloured dot alone.
  • Dates follow the system's format: "Fri 13 Nov".
  • The caption says what the rows are: "Users, page 1 of 2", "Invitations".
  • Counts say what is counted: "Showing 1–2 of 4 users".

Sources

The look comes from the adopted system (first written for Shelfie); the three tables and their states come from these admin mocks:

  • pages/admin-users/default, page-2, empty, no-results
  • pages/admin-invitations/default, empty
  • pages/admin-roles/default, member, no-privileges

Drift from the implemented admin

  • Header cells: none of the three tables has a <caption> or scope; the privileges table's record names are <td>, not row headers, and each row sits in its own <tbody>. The system adds captions, scope="col" and scope="row", and one <tbody>.
  • Unnamed row actions: the Users table's .icon-btn Edit and Delete buttons have no accessible name (Material Icons ligatures only). The system names them with the row.
  • Checkbox names: each .privilege-toggle is a native 28px checkbox tinted green with accent-color and named aria-label="privilege-read" (or write, create, delete) on every row. Each change saves at once, so the system uses a .switch (role="switch") with a hidden "Read, User" name.
  • Role names: the Users table shows the code names SystemAdministrator and BoardMember. The system shows words.
  • Avatars: .user-avatar gets a random inline background colour per user, with white initials whose contrast is not checked. The system uses .avatar.avatar--sm on --color-accent-subtle, hidden from screen readers because the username follows.
  • Empty and no results: Users shows "No users found" in a full-width row above "Showing 0-0 of 0 users", and no-results clears the search box, so the words searched for are lost. Invitations empty and a role with no privileges draw a header row with no body. The system uses an empty state and keeps the search words.
  • Scrolling: .users-table and .invitations-table scroll sideways with overflow-x: auto but cannot take focus, so a keyboard cannot scroll the read-only invitations. The system's wrapper takes focus when nothing inside can.
  • Look: header cells are 14px semibold muted text with 10 × 16px padding on white, in Outfit, and the invitation code uses the generic monospace family. The system uses --text-label on a sunken header band, 12 × 16px cells and --text-code, in both themes.
  • Pagination: the « and » buttons are glyphs with no words, and the current page is marked only by an .active class. The system uses .pagination links with words and aria-current="page".
