Component · Data display

Table

A table lists records of the same kind in rows and columns, so people can scan and compare. The product has one: the Users table, a card holding a header row, one row per user and pagination beneath.

WCAG 2.2 AAStatus: stableNative <table>

Overview

Use a table when each row is a record and each column is the same attribute of every record, and when the records are compared or managed (edited, deleted). Use list items for conversations and profiles that read as a sequence, cards for documents and requests that read as summaries, and a description list for one record's attributes.

The mocks implement a plain table only. They do not show sorting, row selection, a sticky header or column resizing; this system does not either.

Anatomy

  1. Container.card.table-card: card with no padding and hidden overflow so the header row follows the rounded corners.
  2. CaptionNames the table. Visually hidden by the system (.table caption); announced by screen readers.
  3. Header rowth scope="col": subtle fill, muted label text, 12px by 20px padding, hairline below.
  4. Celltd: --text-body-sm, same padding, hairline below (none on the last row), vertically centred.
  5. Avatar cell.user-cell: an avatar and the username, 12px apart.
  6. Badge cellA badge for status.
  7. Actions cellOne or more icon buttons, each labelled with the verb and the row's subject.
  8. PaginationBelow the table inside the card; see pagination.

Selection, sorting, sticky headers, loading skeletons and row expansion are not implemented and are not part of the system.

Responsive behaviour

  • The mocks have no @media rule for the table. The card's overflow: hidden clips columns that do not fit, so on a narrow phone the Actions column can be cut off. This is a gap.
  • Requirement: at widths where the table does not fit, the table scrolls horizontally inside its own card (overflow-x: auto), reachable by keyboard (the scroll container has tabindex="0", a role of region and a label), so that the page itself never scrolls sideways and no column is lost.
  • Four columns of this content fit from about 640px up. Below that, keep the username and actions visible by letting the secondary columns scroll.
  • Pagination wraps its two parts when narrow.

Theming

Table colours use semantic tokens only.

Accessibility

Role and pattern

A native <table> with <caption>, <thead>, <tbody> and th scope="col". It is a static data table, not an ARIA grid: there is no cell-by-cell keyboard navigation. The mocks' tables have neither a caption nor scope on headers; the system requires both so a screen reader can announce "Username, mira.fern" while moving through cells. Use th scope="row" for the first cell of a row only when it identifies the row.

Keyboard

KeyAction
Tab / Shift+TabMoves through the icon buttons in each row, then to pagination.
Enter, SpaceActivates the focused button (edit, delete).
Arrow keysNo table navigation; read with the screen reader's table commands.

Focus

The ring (2px --color-focus-ring) is drawn on the icon buttons. Because the card hides overflow, the 2px offset can clip at the edge of the last column; keep the actions cell padded by --space-5.

Labelling

Each icon button names its verb and its row: "Edit mira.fern", "Delete mira.fern". The mocks' buttons had no label at all. The avatar is decorative (aria-hidden) because the name follows it. Status is the badge's text, never colour alone.

Motion

None. Row hover is an instant fill change.

Touch

Icon buttons are 40px square with no gap between them in the mock; add --space-1 between neighbouring buttons so a mis-tap on Delete is less likely. Both exceed the 24px minimum.

Content

  • Column headings are single nouns: "Username", "Role", "Status", "Actions". No colons or units unless needed.
  • The caption names the data: "Users". It is not a sentence.
  • Status text is one word ("Active", "Pending"); the badge colour supports it.
  • The pagination summary says "Showing 1-2 of 4 users".
  • An empty result says what is missing: "No users found".

Drift

  • The mock's table was .users-table.card with component-scoped table styles; the system names the card .table-card and the table .table.
  • No caption and no scope on header cells; the system requires both.
  • Edit and delete icon buttons had no accessible name; the system requires "Verb subject" labels.
  • The avatar's colour was set per user with an inline style (random hues); the system uses the single --color-accent avatar.
  • No responsive rule: clipped by overflow: hidden. The system requires an in-card scroll region.
