Progress

A rounded bar that fills as a file uploads to the Assets library, with the percentage beside it in words. It turns green when the upload is done.

WCAG 2.2 AAStatus: stablerole="progressbar"

Overview

Use the progress bar when the admin knows how far along a task is: an upload where the browser reports how many bytes have been sent. In the admin that is the Upload File dialog on the Assets page.

  • Always pair the bar with a visible value in a .progress-row ("45%") and a line that says what is happening ("Uploading Courtyard plan.pdf").
  • When the time is unknown, such as loading a list or saving a form, use a spinner with text or a busy button. The system has no indeterminate bar on purpose: a bar that never moves looks broken.
  • When an upload fails, remove the bar and show a danger alert with a way to try again.

Anatomy

  1. CaptionWhat is happening, with the file name; it also names the bar through aria-labelledby.
  2. Fill.progress__bar; width from --value (a percentage), accent colour.
  3. Track.progress; 8px (12px with --lg), fully rounded, --color-bg-subtle-hover.
  4. Value.progress-row__label: "45%", tabular figures, never wraps.

Variants

Two variants: uploading (accent) and complete (success green, with a word, not only a colour).

Sizes

Default (8px) is the admin's size, used in the Upload File dialog. Large (12px) is for a bar that is the only thing on a screen or sheet, where it can afford more weight.

  • Starting shows the empty track only until the first progress event; if no event arrives, show a spinner instead of a bar stuck at 0%.
  • Uploading: each new value animates the fill over --duration-slow.
  • Complete adds .progress--complete at 100% and the label says "Uploaded". The dialog then closes and the new file appears in the Assets list.
  • Failed replaces the bar with a danger alert (role="alert" in the product); Upload becomes available again.

Responsive behaviour

  • The track fills whatever width is left in its row; the value keeps its width and never wraps.
  • On phones the Upload File dialog becomes a bottom sheet; the bar spans the sheet, and the caption wraps above it if the file name is long.
  • At 320px and at 400% zoom the row still fits: the value is short ("45%"), and the file name lives in the caption, not in the row.

Theming

The track reads --color-bg-subtle-hover, the fill --color-accent, the complete fill --color-success-solid, and the value --color-fg-muted. The value is a custom property, --value, set on the fill, so the component needs no inline width.

Accessibility

Role and pattern

The track is role="progressbar" with aria-valuenow, aria-valuemin="0" and aria-valuemax="100", named by the caption through aria-labelledby (or by aria-label when there is no caption). This follows the WAI-ARIA progressbar role (read only).

Keyboard

KeyAction
TabNot a stop; the bar is read only. Focus stays on Upload, which is busy.
Reading keys (screen reader)Reads "Uploading Courtyard plan.pdf, progress bar, 45%".

Focus

None of its own. While the upload runs, focus stays on the busy Upload button; when the dialog closes, focus returns to the Upload button on the Assets page.

Labelling

Name the bar with the file. Do not make the bar a live region: announcing every percent is noisy. Announce the end once, through the success toast or the danger alert.

Motion

The fill width transitions over --duration-slow; reduced motion zeroes it, so each new value appears at once.

Touch

No targets.

Content

  • Caption: "Uploading {file name}": "Uploading Courtyard plan.pdf".
  • Value: a whole percentage, "45%". Finished: "Uploaded".
  • Failure, in the alert: "We couldn't upload {file name}. Check your connection and try again."
  • Keep the size limit in the field help, not the bar: "Any file, such as a photo or a PDF, up to 28 MB."

Adopted from the Shelfie design system and rewritten for the Coop admin.

Drift from the implemented admin

  • Markup: the admin draws .progress-bar with .progress-fill and an inline width; it has no role="progressbar", no name, no value attributes and no visible percentage. The system uses .progress, .progress__bar with --value, the progressbar role and a .progress-row__label.
  • Behaviour: the implemented value is only ever set to 0; no progress events advance it, so the bar sits empty for the whole upload. The system shows a bar only when progress is reported, and a spinner with text otherwise.
  • Busy dialog: Upload stays enabled and unchanged while uploading. The system makes it a busy button and disables Choose a file until the upload ends.
  • Look: a 6px light grey track with a 3px radius, a green fill and a 0.3 s transition. The system uses the 8px rounded track, the violet accent fill, a success fill when complete, and --duration-slow.
  • No completion or failure state on the bar. The system adds .progress--complete with "Uploaded", and reports failure with a danger alert, as the photo picker already does.
