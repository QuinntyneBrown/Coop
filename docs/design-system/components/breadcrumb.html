Breadcrumb

A short trail above the page title that says where you are and leads back up: "Maintenance / Kitchen tap leak". The Coop admin has no breadcrumbs today; this is a core component, kept ready for the first page that sits under another.

Overview

The Coop admin is flat. Every section (Dashboard, Maintenance, Documents, Pages, Board, Website, Messages, Users, Roles & Privileges, Profiles, Assets, Invitations, Settings) is one item in the sidebar, and details open in a dialog or in a panel on the same page. So no admin screen shows a breadcrumb, and none should be added to a top-level page: the sidebar already says where you are.

The breadcrumb stays in the system as a core component for the day a page sits under another one, for example a maintenance request or a document opened on its own page. Then a trail of two items (the section as a link, this page as text) goes at the top of main, above the page header.

  • Use it on a page reached from a list in another section, so the way back survives a reload and a shared link.
  • Do not use it for tabs within a page (Settings: Theme, Content, Account), for filters (Maintenance: All, New, Received, Started, Completed) or for steps in a wizard. Those are tabs and the step indicator.
  • It is never the only way back. The sidebar item for the section, and on phones the tab bar, lead to the same place with a 44px target.

Anatomy

  1. Parent linkAn <a> in --color-fg-muted, underlined on hover. Named exactly as the section's own heading.
  2. SeparatorA "/" drawn by CSS (li + li::before) in --color-fg-subtle. It is not read aloud.
  3. Current pagePlain text in --color-fg-default, medium weight, with aria-current="page". Not a link.

Variants

One variant. A trail has two items in the admin and never more than three, so there is no collapsed form with an ellipsis menu. The examples show where a trail would go if these records got their own pages.

  • Hover darkens the link to --color-fg-default and underlines it, so it reads as a link even though it rests without an underline.
  • Loading: the trail is known before the record arrives, so it shows at once; only the current item may wait for the record's name.

Responsive behaviour

  • The list wraps (flex-wrap). A long current title drops to a second line at 320px instead of being cut off, so the full name is always visible.
  • No collapsing and no "…" item: two or three items wrap cleanly at 320px CSS width and at 400% zoom.
  • The trail sits inside .app-shell__main, so it takes the page's side margins and never runs under the phone tab bar.

Theming

Three text tokens and nothing else: --color-fg-muted for links, --color-fg-default for hover and the current page, --color-fg-subtle for separators. Each is defined for both themes, so the trail sits on --color-bg-canvas in either.

Accessibility

Role and pattern

The WAI-ARIA APG Breadcrumb pattern: <nav aria-label="Breadcrumb"> around an ordered list; the last item has aria-current="page". Separators are CSS generated content, so they are not announced.

Keyboard

KeyAction
Tab / Shift+TabMoves through the parent links in order. The current page is text, not a tab stop.
EnterFollows the link.

Focus

The shared 2px --color-focus-ring with a 2px offset around the link. The trail is the first thing in main, so after the skip link it is the first stop in the content.

Labelling

The landmark is labelled "Breadcrumb", which keeps it apart from the sidebar's navigation landmark. Link text is the section's name exactly as its heading and sidebar item say it.

Contrast

Separator on canvas

Motion

None.

Touch

The links are inline text in --text-body-sm, which WCAG 2.5.8 allows as an inline target. Because many people using the admin are older and may tap less precisely, the breadcrumb is only ever a second route: the sidebar item and the phone tab bar give the same destination a 44px target.

Content

  • Name each parent as its heading and sidebar item: "Maintenance", "Documents", "Users". Never "Home", "Back" or "Admin".
  • The current item is the record's own name as people know it: the request title ("Kitchen tap leak"), the file name ("Meeting notes.pdf"), the username ("mira.fern").
  • Sentence case, as everywhere in the admin.

Sources

No admin mock has a breadcrumb. These mocks show how the admin handles "where am I" and "back" today:

  • pages/admin-maintenance/detail-new (a request's detail opens beside the list on the same page; no trail is needed)
  • pages/admin-messaging/chat (an icon-only back button in the chat header)
  • pages/admin-forgot-password/default (a "Back to Sign In" text link)
  • pages/admin-users/default (a top-level section: the sidebar's .nav-item.active says where you are)

The component's look comes unchanged from the Shelfie design system.

Drift from the implemented admin

  • No breadcrumb. The implemented admin has no breadcrumb component or class. Nothing to fix; the system keeps .breadcrumb as a core component for pages that sit under another.
  • Unnamed back button. The chat header's button.back-btn holds only the Material Icons ligature arrow_back and has no aria-label, so assistive technology reads "arrow_back". The system uses a named icon button with a stroke SVG, or a breadcrumb when the chat gets its own page.
  • Title Case link. The forgot-password page's .back-link reads "Back to Sign In"; the system writes "Back to sign in" in sentence case.
  • Icons. The admin draws icons with the Material Icons font; the system uses inline stroke SVGs that are aria-hidden.
