Tab bar

The admin's main navigation on a phone: the four busiest sections and a More tab, in a bar along the bottom of the screen where a thumb can reach them. More opens the full list of thirteen sections. From 768px the bar hides and the sidebar takes over.

Overview

Use the tab bar on every signed-in admin page below 768px, in the same place and with the same five tabs every time: Dashboard, Requests (Maintenance), Documents, Messages and More. The first four are the sections staff open most from a phone: checking a leaking tap, sharing meeting notes, answering a member. More opens a dialog listing all thirteen sections, the same list as the sidebar, so Board, Users, Settings and the rest are reachable on a phone and at 400% zoom. The top bar sits at the top of the same screens and links the avatar to My profile, where Sign out lives.

  • The four section tabs are links, not ARIA tabs: each one goes to a different page. More is a button that opens a dialog. For views inside one page, use tabs.
  • Put it in the app shell once, not inside each page, so it is never missing from a page.
  • The page wrapper gets .has-tabbar so the last card and its buttons are not hidden behind the bar.
  • Never show it on sign-in, registration or forgotten-password pages; there is nowhere to go until you are signed in.
  • In these pages, .tabbar--static shows the bar in the flow of the page at every width.

Anatomy

  1. Barnav.tabbar, fixed to the bottom, --layout-tabbar-height (64px) plus the safe-area inset, surface background, hairline top edge.
  2. Icon24px (--size-icon-lg) stroke icon, the same icon the sidebar uses for that section; aria-hidden.
  3. LabelOne word in --text-caption, medium weight; the accessible name. The current tab is accent coloured.
  4. Count badge (optional).badge--count pinned to the icon's top right, only on Messages and only when something is unread.
  5. MoreA <button aria-haspopup="dialog"> in the last place, with a three-dot icon. Opens the All sections dialog.

Variants

One variant: four section tabs and More. What changes is which tab is current, whether Messages shows a count, and whether the More dialog is open. The admin does not show a count today; the badge is there for when it does.

More: every section in a dialog

More opens a dialog titled "All sections". Its body reuses .sidebar__nav with the same thirteen .nav-links, icons and order as the sidebar, then My profile under a "Your account" heading (.sidebar__group); the current page carries aria-current="page". Choosing a link goes to that page and closes the dialog. On a phone the dialog rises from the bottom as a sheet; from 640px it is centred.

One height, --layout-tabbar-height (64px) plus env(safe-area-inset-bottom); the five tabs share the width equally.

  • Current turns the icon and label --color-fg-accent and sets aria-current="page". A page inside a section keeps that section's tab current: one maintenance request keeps Requests current, a conversation keeps Messages current.
  • No current tab: on a page without its own tab (Users, Settings and the other seven), no tab is current. The page heading says where you are, and the More dialog marks that section current.
  • More open: aria-expanded="true" on the More button while the dialog shows; the button turns --color-fg-accent. The More button never takes aria-current; it is not a page.
  • Count: shows on Messages only while something is unread, and never shows "0".

Responsive behaviour

  • Base (phones, up to 767px): fixed to the bottom at --z-sticky, full width, five equal tabs. Padding includes env(safe-area-inset-bottom) so it clears the phone's home indicator.
  • .has-tabbar on the page wrapper adds bottom padding of --layout-tabbar-height + --space-6, so the last card, its buttons and any focused field stay above the bar.
  • From 768px (--layout-breakpoint-md) the bar is display: none, .has-tabbar drops its padding and the sidebar appears. .tabbar--static is exempt so these pages can show it.
  • At 320px (a phone, or 400% zoom) each tab is 64px wide, enough for "Dashboard" or "Documents" on one line. Labels never truncate; a sixth tab would not fit.
  • Every section at every width: the four tabs cover the busiest sections and More reaches all thirteen, so nothing the sidebar offers on a wide screen is lost on a phone or at 400% zoom. The More dialog is a bottom sheet below 640px and scrolls inside itself when the list is taller than the screen.
  • Toasts sit above the bar on phones (the toast region moves up by the bar's height).

Theming

The bar is --color-bg-surface with a hairline top edge in --color-border-default. Tabs read --color-fg-muted, --color-fg-default on hover and --color-fg-accent when current; the count badge reads the danger-solid pair. The dark theme swaps only those tokens.

Accessibility

Role and pattern

A native <nav aria-label="Admin, phone"> of links with aria-current="page", following the APG landmark regions guidance. Not the APG Tabs pattern: these change the page, so they are links and use plain Tab navigation. More is a <button aria-haspopup="dialog" aria-expanded aria-controls> that opens an APG modal dialog holding a second, labelled <nav aria-label="All admin sections">. Only one admin navigation is visible at a time (the sidebar is display: none on phones), so screen readers meet one navigation landmark.

Keyboard

KeyAction
Tab / Shift+TabMoves through Dashboard, Requests, Documents, Messages and More. The bar comes last in DOM order, after the page content. While the dialog is open, focus stays inside it.
EnterFollows a tab link, or a section link in the dialog.
Enter, Space on MoreOpens the All sections dialog and moves focus to the current section's link, or to the first link if no section is current.
Esc in the dialogCloses it and returns focus to More. The Close button does the same.

Focus

The shared ring around the whole tab. Because the bar is fixed, .has-tabbar padding keeps focused fields and buttons above it (WCAG 2.4.11, focus not obscured).

Labelling

The visible word is the name, including "More"; icons are aria-hidden. The dialog is named by its title, "All sections", and its close button by aria-label="Close". The count badge has its own aria-label ("2 unread"), so the link reads "Messages, 2 unread, current page".

Motion

The bar does not slide away or hide on scroll; it is always where people left it. The More dialog slides up over --duration-slow; reduced motion zeroes it.

Touch

Each tab is a fifth of the screen wide (64px at 320px) and at least 44px (--target-comfortable) of the 64px bar tall, with no gaps between tabs to miss.

Content

  • Five words, in this order: Dashboard, Requests, Documents, Messages, More.
  • Labels use the sidebar's section name wherever it fits a fifth of a phone. "Maintenance" does not, so its tab says "Requests", from the page heading "Maintenance Requests". The icon is always the sidebar's icon for that section, so the two are recognisably the same place.
  • One word per tab; a label that wraps at 320px is too long.
  • The badge shows a number only; its spoken label says what the number counts.
  • The dialog title is "All sections"; its links use exactly the sidebar's words.

Drift from the implemented admin

  • Classes: the admin renders nav.bottom-tab-bar of a.tab-item with a Material Icons glyph and .tab-label, wrapped in .mobile-only on some pages. The system uses nav.tabbar with stroke SVG icons and .has-tabbar.
  • Current page: the admin marks it with .tab-item.active (green text) and no aria-current; the nav has no accessible name. The system uses aria-current="page" and aria-label="Admin, phone".
  • Placement: the admin adds the bar inside each page component, so it is missing from Users, Roles, Assets, Invitations, Settings, Change password and Onboarding, and it appears under the sign-in form. The system renders it once in the app shell for signed-in pages only.
  • Routes: Messages goes to /messaging and Profile to /profile, while the sidebar uses /messages and /profiles, so on the Messages and Profiles pages no tab is current. The system points both at the same address.
  • Clearance: pages pad their own bottom by a fixed 72px or 80px; the bar has a stacking order of 1000. The system uses .has-tabbar and --z-sticky.
  • Breakpoint: the admin hides the bar from 769px (max-width: 768px elsewhere); the system hides it with min-width: 48rem.
  • Label size: the admin's labels are 14px; the system's --text-caption is 12px. Larger text is kinder to older eyes, so this is a gap in components.css to settle rather than a fix.
  • Theme: the admin is light only. The system adds the dark theme.
  • Phone navigation: at 768px and below the admin stacks the whole sidebar (brand, thirteen links, user) above the page and also shows the bottom tab bar, so a phone has two navigations and the page heading starts a long scroll down. The system hides the sidebar below 768px and reaches every section from the tab bar: four section tabs plus More, which opens the full list in a dialog.
  • Tabs: the admin's five tabs are Home, Requests, Documents, Messages and Profile. The system renames Home to Dashboard to match the sidebar, and replaces Profile with More. My profile is reached from the avatar in the top bar and from the More dialog; Sign out stays on the Profile page.
  • The More button uses the shared .tabbar button rule; its open state is aria-expanded="true".
