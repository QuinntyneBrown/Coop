Switch

An on or off setting that takes effect the moment it is flipped, with no Save button. On Roles & Privileges every access right a role has, such as Read or Delete, is one switch.

WCAG 2.2 AAStatus: stableinput[type=checkbox][role=switch]

Overview

Use a switch for a setting that is on or off and is saved as soon as it changes. The admin has one place like this: the privilege grid on Roles & Privileges. For the chosen role, each row is an area of the admin (User, Maintenance request, Document, Profile) and each column an access right (Read, Write, Create, Delete). Flipping a cell grants or removes that right straight away.

  • In a table cell: the privilege grid. The switch has no visible text; its name comes from its column and row headers.
  • With a label: a switch on its own line with the setting written beside it. No admin screen has one yet; it is the same component.

The implemented admin draws these as plain checkboxes (.privilege-toggle). A checkbox says "this will be saved when you press the button", which is not what happens, so the system draws them as switches. For a yes-or-no choice that waits for a form's button, such as "Remember me", use a checkbox. For one choice from several, use a radio group or a select.

Anatomy

  1. TrackThe checkbox itself, --size-icon-md tall and 1.75 times as wide, fully round. --color-border-strong when off, --color-accent when on.
  2. ThumbA --color-bg-surface circle with --shadow-1. Left when off, right when on.
  3. Label.switch__text in --text-body. In a table cell there is no visible label; the headers name the switch.

Variants

In a table cell (privilege grid)

Each cell holds a label.switch with only the input inside. aria-labelledby points at the column header and the row header, so the switch is read as "Read Maintenance request, switch, on". The grid sits in a .table-wrap so it scrolls inside itself on a narrow screen instead of moving the page.

With a label

A switch on its own line, with the setting written beside it as a short statement of what is true when it is on.

Sizes

One size: the track is --size-icon-md tall and the row is at least --target-min tall.

States

Hover and focus are forced with data-state; on and disabled use the real attributes.

OffOnHoverFocusDisabled offDisabled on

Both themes

  • Hover darkens the off track to --color-fg-muted and the on track to --color-accent-hover.
  • Focus draws the shared ring around the track, offset by --space-0-5 so it never touches the thumb.
  • Disabled uses --color-border-default for the track and --color-fg-disabled for the label. Use it for a right the person may not change, never as decoration.
  • Not saved: if the change cannot be saved, the switch moves back to where it was and an alert above the grid says what did not change (see Do and don't).

Responsive behaviour

  • The switch does not change size with the viewport. The track never shrinks (flex: none); a long label wraps beside it.
  • The privilege grid keeps its five columns. Under about 30rem, and at 400% zoom, it scrolls sideways inside its .table-wrap while the page itself does not scroll.
  • The whole label is the tap target, so a labelled switch is easy to hit on a phone.

Theming

Every colour is a token, so the switch follows the theme with no overrides. The on track uses the accent, the off track the strong border colour, and the thumb the surface colour, so it stays visible against both tracks in light and dark.

Accessibility

Role and pattern

A native checkbox with role="switch", following the WAI-ARIA APG Switch pattern. Screen readers say "switch, on" or "off", which matches a setting that is live, rather than "checked", which suggests a form still to be sent.

Keyboard

KeyAction
Tab / Shift+TabMoves to the next or previous switch, row by row across the grid. Disabled switches are skipped.
SpaceFlips the switch and saves the change.

Focus

The shared ring on :focus-visible, offset from the track. Focus stays on the switch after it flips, and stays there if the change is undone because it could not be saved.

Labelling

A labelled switch takes its name from the wrapping label. In the grid, aria-labelledby joins the column header and the row header, so each of the sixteen switches has its own name ("Delete Document"). Never name a switch after a test id or a field name.

Motion

The thumb springs across with --ease-spring over --duration-base, and the track colour fades with --ease-standard. Reduced motion sets both durations to zero, so the thumb jumps.

Touch

The label row is at least --target-min (24px) tall, and in the grid each switch sits in a cell with --space-3 by --space-4 padding, so neighbouring switches never crowd each other.

Content

  • A label says what is true when the switch is on: "Read maintenance requests". It never names the action ("Turn on reading").
  • Grid headers are plain words. The rows name parts of the co-op's work ("Maintenance request", "Document"); the header over them says "Area", not the developer word "Aggregate".
  • When a change cannot be saved, the alert says what is still true and what to do: "That change wasn't saved. Members still can't delete maintenance requests. Try again."

Sources

Extracted from these admin mocks:

  • pages/admin-roles/default (System administrator: sixteen rights, all on)
  • pages/admin-roles/member (Member: Read and Create on, Write and Delete off)
  • pages/admin-roles/no-privileges and empty (grid with no rows; no roles)

Drift from the implemented admin

  • Control. .privilege-toggle is a 28px browser checkbox tinted green with accent-color, with no role="switch". The system draws a token-coloured track and thumb and announces it as a switch, because each change saves at once.
  • Name. Every toggle is named by its test id (aria-label="privilege-read", privilege-write, and so on), identical in every row; in the Angular source it has no name at all. The system names each one from its column and row headers with aria-labelledby.
  • Failure. The roles component flips the box, then calls the API and ignores any error, so a failed save leaves the box showing a right the role does not have. The system moves the switch back and shows an alert.
  • Headers. The first column is headed "Aggregate" and the cells sit in plain <td>s. The system uses "Area" and row headers (<th scope="row">) so each switch can be named.
  • Narrow screens. The privileges panel sets overflow-x: auto on the whole card, so the heading and Add Privilege button scroll with the table. The system scrolls only the grid, inside .table-wrap.
  • Theme. The admin is light only and the toggle is green; the system switch is violet and follows both themes.
