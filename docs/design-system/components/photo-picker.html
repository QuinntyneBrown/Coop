Photo picker

Changes one person's photo. An extra-large avatar previews it, with a button to choose a photo and one to remove it. Staff use it for their own profile photo and for a board director's portrait.

WCAG 2.2 AAStatus: stableNative file input or dialog trigger

Overview

Use the photo picker wherever a form holds one person's photo. The preview shows exactly what others will see; with no photo, it shows the person's initials, which is also what the website shows.

  • From the device: on the profile, Choose a photo opens the device's own file chooser (and the camera on a phone). The photo uploads as soon as it is picked.
  • From the Assets library: in the Add or Edit director dialog, Choose a photo opens the Choose a photo dialog, which shows the library as a picture list and lets staff upload a new one. The chosen portrait becomes the preview and is saved with Save director.

Remove photo brings the initials back. The picker never crops or edits a photo, and it is not a general file field: for documents and other files, use the upload dialog on the Assets page.

Anatomy

  1. PreviewAn extra-large (64px) avatar with role="img": "Photo of Mira Fern", or "No photo yet. Showing the initials MF".
  2. Choose buttonPrimary. From the device: a label.btn around a visually hidden input type="file". From the library: a button that opens the Choose a photo dialog.
  3. Remove photoA ghost button, shown only when there is a photo.
  4. Help, status and errorWhat photos work, in a polite live region that also says "Uploading…"; a .field__error joined with aria-describedby when a photo is refused.

RA

Choose a portrait from the Assets library, or upload one. Without a photo, the website shows the director's initials.
  • Focus lands on the hidden file input, and its label button draws the shared focus ring (:has(input:focus-visible)). In the library variant the button itself takes focus.
  • Uploading sets aria-busy on the preview, dims the new photo under a turning ring, disables both buttons and says "Uploading…" in the status line. The dialog's Cancel waits too, as in the photo dialog.
  • Too large and wrong kind of file are caught in the browser before anything is sent, and again by the server. The old photo or initials stay.
  • Upload failed (network or server) keeps the old photo, says so in words and leaves Choose a photo ready to try again.
  • Disabled while the surrounding form saves.

Responsive behaviour

  • The preview and the body sit side by side and wrap: when the body has less than 12rem, it moves under the preview, and the buttons wrap under each other.
  • Nothing scrolls sideways at 320 CSS px, including at 400% zoom; the help line wraps.
  • On phones, Choose a photo offers the camera as well as the photo library.

Accessibility

Role and pattern

From the device: a native file input inside a label, so the button's visible text is the input's name and the browser's own file chooser handles the rest. From the library: a native button with aria-haspopup="dialog" that opens a modal dialog. The preview is role="img" with a label. Help, status and error are joined to the control with aria-describedby; aria-invalid is set while an error shows.

Keyboard

KeyAction
Tab / Shift+TabChoose a photo, then Remove photo.
Enter / SpaceOpens the file chooser or the Choose a photo dialog, or removes the photo.
EscIn the Choose a photo dialog: closes it without changing the photo.

Focus

After Remove photo, the Remove button disappears, so focus moves to Choose a photo. When the Choose a photo dialog closes, focus returns to the button that opened it.

Labelling and announcements

"Uploading…" is read from the status line; errors are read from the error line as it appears. The preview's label changes with the photo, so a screen reader user can check what was chosen.

Motion

The new photo fades in and the uploading ring turns; both stop under prefers-reduced-motion, and "Uploading…" still says what is happening.

Touch

Both buttons are 40px tall and wide with their labels, with 8px between them; on a phone the file chooser is the system's own, with large targets.

Content

  • Buttons: "Choose a photo" with no photo, "Choose another" with one, "Remove photo".
  • Help from the device: "JPEG, PNG or WebP, up to 10 MB." Help for a director: "Choose a portrait from the Assets library, or upload one. Without a photo, the website shows the director's initials."
  • Errors say what happened and what to do: "That photo is larger than 10 MB. Choose a smaller one." · "That file is not a photo we can use. Choose a JPEG, PNG or WebP photo." · "We couldn't upload the photo. Try again."
  • Never ask staff to paste a web address for a photo.

Drift from the implemented admin

  • The profile's avatar section is a 100px green .avatar-circle with a .btn.btn-secondary.btn-sm "Change Avatar" that has no file input, no remove and no help. The system uses the photo picker: a 64px avatar, Choose a photo and Remove photo.
  • The director editor asks for a "Photo address (optional)" as a URL text field, to be pasted from the Assets library, with no preview. The system uses the library variant: a preview and Choose a photo, which opens the Choose a photo dialog, as the website's hero photo already does with its "Choose photo" button.
  • In the Choose a photo dialog the upload is a bare native <input type="file"> in a .form-group; the system wraps it in a primary label.btn. Its help ("JPEG, PNG or WebP, up to 10 MB."), its "Uploading…" status in role="status" and its "We couldn't upload the photo. Try again." alert are kept word for word.
  • While uploading, the dialog disables the file input and Cancel; the system also sets aria-busy on the preview.
  • Buttons are the green, 8px-radius .btn-primary/.btn-secondary with Material Icons (photo_library); the system uses pill .btn--primary and .btn--ghost with stroke SVG icons.
  • Labels vary ("Change Avatar", "Choose photo", "Photo address"); the system uses "Choose a photo", "Choose another" and "Remove photo" everywhere.
  • Global: the implemented admin uses Outfit, Material Icons and a light theme only.
