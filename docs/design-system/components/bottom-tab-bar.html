Bottom tab bar

Five icon-over-label links fixed to the bottom of compact screens, with safe-area padding for the home indicator.

WCAG 2.2 AAStatus: stableNative <nav> and <a>

Overview

The bottom tab bar is the member app's primary navigation on compact screens: five destinations, each an icon above a short label, fixed to the bottom of the viewport. It replaces the sidebar below 1024px.

  • It navigates between pages, so items are links. For switching views inside a page use tabs.
  • Use three to five items. The product uses five: Home, Requests, Docs, Messages, Profile.

Anatomy

  1. Bar (.bottom-tab-bar)Sticky to the bottom, --z-sticky, white surface, hairline rule above, items spaced evenly.
  2. Item (.tab-item)Column: icon above label; minimum width 56px; --space-1 by --space-3 padding.
  3. Icon24px, aria-hidden.
  4. Label--text-caption (12px), medium weight.
  5. Safe-area paddingBottom padding is --space-2 plus env(safe-area-inset-bottom) so items clear the home indicator.

Variants

One variant. Items show their selection by colour: the current item uses --color-fg-accent, the others --color-fg-muted.

Sizes

The bar has one size; the label is 12px and the icon 24px.

States

Hover and focus are forced with data-state.

DefaultHoverFocusCurrent page
buildRequestsbuildRequestsbuildRequestsbuildRequests
  • The current item changes colour only. Colour alone is not enough for WCAG 1.4.1 in general, but here the label and position also stay stable and aria-current carries the state for assistive tech; a weight or indicator change is not implemented in the mocks.
  • No badge, disabled or loading state is implemented.

Responsive behaviour

  • Below 1024px the bar is shown, fixed to the bottom of the viewport; the page content reserves 72px of bottom padding so the last content is not covered.
  • At 1024px and wider the bar is hidden (@media (min-width: 1024px)) and the docked sidebar takes over.
  • Safe areas: padding adds env(safe-area-inset-bottom, 0px). The page must set viewport-fit=cover for the inset to be non-zero on notched devices.
  • Items spread evenly with justify-content: space-around; at 320px five 56px items still fit without scrolling.

Theming

The product ships one light appearance; there are no theme variants.

Accessibility

Role and pattern

A <nav aria-label="Main"> landmark of links. It is not an ARIA tablist: items navigate to new pages. Do not add role="tab".

Keyboard

KeyAction
Tab / Shift+TabMoves through the five links in order.
EnterFollows the link.

Focus

Shared focus ring on :focus-visible. The ring is drawn outside the item, with a 2px offset, so it is not clipped by the bar.

Labelling

Every item has a visible text label; the icon is aria-hidden. Mark the current item with aria-current="page"; the mocks only toggle .active, which is not announced.

Contrast

Label on surface

Motion

Colour changes only. The mocks transition colour over 0.2s; the tokens remove it under prefers-reduced-motion.

Touch

Each item is at least 56px wide and about 48px tall (24px icon, 12px label, padding), above the 24px minimum and the 44px comfortable target.

Content

  • One word per label: Home, Requests, Docs, Messages, Profile.
  • The mocks use 11px labels; the system size is 12px (--font-size-xs), the smallest on the scale.
  • Match each label to the page's heading where possible; use the same labels as the sidebar ("Documents", not "Docs").

Drift

Where the mocks differ from each other or fail WCAG 2.2 AA, the design system resolves it as follows.

  • Labels are 11px in the mocks; the system uses 12px (--font-size-xs).
  • Current item is marked with .active only; the system adds aria-current="page".
  • The mocks use inline SVG icons; the system uses the Material Icons font for consistency with the rest of the product.
  • Some mock builds use a fixed bar and others a sticky one; the system uses sticky with 72px of page bottom padding.
  • The bar sets no minimum width on one mock build; the 56px minimum from the other is kept.
