Icon button

A square, text-free button for common actions such as the notification bell, the menu toggle, edit and delete.

WCAG 2.2 AAStatus: stableNative <button>

Overview

Use an icon button where the icon is universally understood and space is tight: top bar (menu, notifications), table rows (edit, delete) and viewer close. Use a button with a label when the action is not obvious.

  • menu (hamburger) opens the sidebar on compact screens.
  • notifications is the bell in the top bar.
  • edit and delete open the matching dialog from a table row.
  • close leaves the document viewer.

Anatomy

  1. IconA Material Icons glyph at 1.5rem, aria-hidden, inherits --color-fg-default.
  2. ContainerTransparent, borderless, at least 2.5rem square (--icon-btn-size), --radius-sm corners.
  3. Accessible namearia-label with the verb and object. Required.

Variants

There is one look; only the glyph changes.

The glyphs used in the product.
HTML
<button class="icon-btn" type="button" aria-label="Edit user">
  <span class="material-icons" aria-hidden="true">edit</span>
</button>

Sizes

There is a single size: 2.5rem square with a 1.5rem glyph.

States

Hover and active forced with data-state; focus uses the shared ring.

DefaultHoverFocusActiveDisabled

Hover fills --color-bg-subtle; active fills --color-bg-subtle-hover; disabled is 50% opaque.

Responsive behaviour

The mocks define no @media rule for this component, so it does not change at the 640, 768 or 1024 breakpoints. The hamburger button is hidden or shown by the top bar layout, not by this component; see the top bar.

Theming

The product ships one light appearance, so this component has no theme variants. It reads semantic tokens only; see the tokens section.

Accessibility

Role and pattern

Native <button type="button">: the WAI-ARIA Button pattern.

Keyboard

KeyAction
TabMoves focus to the button.
Enter, SpaceActivates it.

Focus

One shared ring: --focus-ring-width solid --color-focus-ring at --focus-ring-offset, shown on :focus-visible. The mocks removed the browser outline (outline: none) and relied on a border-colour change; the design system restores a visible ring.

Labelling

Every icon button needs an aria-label describing the action and, in rows, its object ("Edit user"). The mocks of the admin pages ship icon buttons with a glyph name and no label; the design system requires the label. Some review-only labels in the mocks (for example "dashboard notification bell") restate the test id rather than the action and are replaced with "Notifications" and "Open menu".

Motion

Background colour transitions over --duration-base.

Touch

2.5rem square exceeds the 24px WCAG 2.2 minimum.

Content

  • The label is a verb, optionally with the object: "Edit user", "Delete document".
  • Do not put the glyph name in the label ("delete").
  • The bell and menu are labelled by purpose: "Notifications", "Open menu".
