Icon button

An icon button is a square button with only an icon: Edit and Delete at the end of a user's row, Delete on a document card, Close in a dialog header. Its name lives in aria-label, so every one says exactly what it acts on.

Overview

The icon button is a button with the .btn--icon modifier: it keeps the button's height, becomes a circle as wide as it is tall, and drops the visible label. There is no separate CSS; tone and size come from the usual button modifiers.

  • Use it for small, repeated actions whose icon is plain from context: Edit (pencil) and Delete (bin) on every row of Users, Delete on each document card, Close (×) in a dialog header.
  • Do not use it for the main action of a view, or for any action a person might not recognise from the icon alone. "New page", "Save page" and "Send" keep their words.
  • Prefer a labelled button when there is room. On Pages and Board, where each card has space, "Edit" and "Remove" are labelled buttons; icon buttons are for tables and tight headers.

Every icon button has an aria-label that names the action and, in a list, the item: "Edit mira.fern", "Delete Meeting notes.pdf". A tooltip that shows the same words on hover and focus is optional and recommended for anything less common than Close.

Anatomy

  1. ContainerA circle: width equals --btn-height (36, 44 or 52px), --radius-full, hairline border for the secondary tone.
  2. IconStroke SVG, 1.25em, currentColor, aria-hidden="true".
  3. Tooltip (optional).tooltip inside a .tooltip-anchor; repeats the accessible name on hover and focus.

Variants

Three tones, chosen by where the button sits and what it does.

Ghost (.btn--ghost.btn--icon), secondary (.btn.btn--icon) and danger (.btn--danger.btn--icon).
HTML
<button class="btn btn--ghost btn--icon" type="button" aria-label="Edit mira.fern">…</button>
<button class="btn btn--icon" type="button" aria-label="New conversation">…</button>
<button class="btn btn--danger btn--icon" type="button" aria-label="Delete Meeting notes.pdf">…</button>
  • Ghost is the default for icon buttons. It has no fill or edge until hover, so a row of them stays calm: Edit in a table row, Close in a dialog header, Back to the conversation list on a phone.
  • Secondary has the hairline edge of a secondary button. Use it when the button stands alone in a header and needs to look pressable at rest: "New conversation" beside the Messages heading.
  • Danger is the solid red fill. Use it only for an icon-only Delete that opens a confirmation dialog, where the colour and the bin are the only cues because there are no words. Never combine it with .btn--ghost: the ghost rule clears the fill but keeps the danger label colour, so the icon disappears.

Sizes

The circle is as wide as the button is tall. Small (36px) sits in table rows and on document cards; medium (44px) is for dialog headers and page headers; large (52px) is available but not used in the admin.

36, 44 and 52px squares from --control-height-sm/md/lg. The icon scales with the size's font (--font-size-sm/md/lg).

States

The same six states as a button. Pointer and focus states are forced with data-state; real pages get them from :hover, :focus-visible, :active, disabled and aria-busy.

Both themes

  • Disabled: Close is disabled while a dialog saves, as in the New document dialog, so the request cannot be abandoned half-way. Nothing else disables an icon button; an action a role cannot take is left out, not greyed.
  • Loading (aria-busy="true") hides the icon behind the spinner. It is rare for an icon button, because Edit and Delete open a dialog whose own buttons carry the busy state.
  • Pressed (aria-pressed) is supported by the button CSS but no icon button in the admin toggles.

Responsive behaviour

  • Icon buttons never shrink or wrap their content; the circle keeps its size at every width and at 400% zoom.
  • In a Users row the action cell keeps Edit and Delete side by side with --space-2 between them. Below 768px the table scrolls inside its .table-wrap rather than the page.
  • On a document card the Delete button stays at the end of the card's row; the title and date wrap instead.
  • Tooltips are hover and focus enhancements; on touch screens the aria-label is what assistive technology reads, and the icon must be clear without the tooltip.

Theming

An icon button reads exactly the same component tokens as a button: --btn-bg, --btn-fg, --btn-border, --btn-bg-hover, --btn-bg-active and --btn-height. .btn--icon only sets the width to --btn-height and removes the padding. In dark, ghost and secondary icons switch to the light --color-fg-default, and danger becomes --palette-red-300 with a dark icon. The tooltip reads --color-bg-inverse and --color-fg-inverse, which flip between themes so it always contrasts with the page.

Accessibility

Role and pattern

Native <button type="button"> (WAI-ARIA APG Button pattern) with aria-label. The SVG is aria-hidden="true" and contains no text, so the label is the only name. A tooltip follows the APG Tooltip pattern loosely: it appears on hover and focus, never holds a control and hides on Esc.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the button; focus shows the tooltip if there is one.
Enter, SpaceActivates the button: opens the edit or delete dialog, or closes the dialog.
EscHides a visible tooltip without moving focus. In a dialog, also closes the dialog, the same as Close.

Focus

The shared focus ring follows the circle (outline on a round element), offset by --focus-ring-offset. When an Edit or Delete dialog closes, focus returns to the icon button that opened it; if the row was deleted, focus moves to the next row's Edit button or, on the last row, to the table's heading.

Labelling

The aria-label is a verb plus the item: "Edit mira.fern", "Delete Meeting notes.pdf", "Delete tavi.moss". A bare "Edit" or "Delete" is not enough in a list, because a screen reader's button list shows them all at once. Close is the one exception: its dialog's name gives the context. Never let an icon font's ligature ("edit", "delete") become the name.

Icons are non-text graphics, so they need 3:1 (WCAG 1.4.11); every pair above also clears 4.5:1 in both themes. A ghost button has no edge at rest, so its icon alone must meet 3:1 against the surface.

Motion

Fill and edge transition over --duration-fast; the tooltip fades in after a short delay. Reduced motion zeroes the durations, so both simply appear.

Touch

Small icon buttons are 36px circles and medium are 44px, both above the 24px minimum; medium meets the 44px comfortable target. Adjacent icon buttons sit --space-2 apart so a tap meant for Edit does not land on Delete.

Content

  • The aria-label is a verb in sentence case plus the item's visible name: "Edit mira.fern", "Delete Courtyard plan.pdf".
  • Use one icon per meaning across the whole admin: pencil for Edit, bin for Delete and Remove, × for Close, plus for New. The same icon never means two things.
  • Tooltips repeat the label word for word, so what a sighted person reads is what a screen reader says.
  • If an action needs explaining, it is not an icon button; give it a label.

Drift from the implemented admin

  • Class. The admin uses .icon-btn: no fill or border, 4px padding around a 24px Material Icons glyph (a 32px target), a grey hover fill or none, and a square 8px radius on some screens. The system uses .btn.btn--icon with a tone and size modifier: a 36px or 44px circle with a stroke SVG.
  • No names. Users' Edit and Delete and the document viewer's Close have no aria-label; their names come from the icon-font ligature ("edit", "delete", "close") and never name the user or document. Only the New document dialog's Close is labelled. The system requires "Edit mira.fern", "Delete Meeting notes.pdf", "Close".
  • Quiet red Delete. Documents colours .delete-doc-btn red with a pale red hover. The system has no quiet danger tone; the Delete trigger is .btn--danger.btn--icon (solid), and Users' Delete matches it so the same action looks the same on both screens.
  • Nested in a link. Each document card is a div with role="link" and tabindex="0" that contains the Delete button, so one control sits inside another. Here the card's title is the link and Delete is a sibling; see link.
  • Messages. "New conversation" is an unnamed .btn-primary.btn-sm plus, and Send and Back are unnamed icon-only buttons. The system makes New conversation a named secondary icon button, Back a named ghost icon button, and Send a labelled primary button.
  • No tooltips. No admin icon button shows its name on hover. The system offers an optional .tooltip.
