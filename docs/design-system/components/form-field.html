Form field

A label above a text, password, select or textarea control, with optional hint and error text.

WCAG 2.2 AAStatus: stableNative form controls

Overview

Every form in the product (sign in, register, create user, change password, profile, maintenance request) is built from .form-group: a label above one control. Controls are full width. Use .form-row to put two groups side by side (first and last name).

  • Text and password input for names, usernames and credentials.
  • Select for a closed list (scope, role).
  • Textarea for long text (document content, request description).

Anatomy

  1. LabelAlways visible above the control, --text-label, --color-fg-muted. Linked with for.
  2. ControlFull width, minimum height 2.5rem, --radius-sm, 1px --color-border-strong border.
  3. Hint (optional).password-hint or .form-hint, --text-caption below the control.
  4. Error (optional).field-error (the mocks' .form-group .error-message) below the control, --color-danger-fg.

Variants

Variants are the control type.

Password must be at least 8 characters long

Text, password with a hint, select and textarea.
HTML
<div class="form-group">
  <label for="username">Username</label>
  <input id="username" type="text" placeholder="Enter your username">
</div>

Two fields in a row

.form-row splits the width equally with --space-4 between groups.

Sizes

There is a single size: inputs and selects are 2.5rem tall; a textarea is 6.25rem tall and resizes vertically.

States

Focus is forced with data-state; real pages use :focus and :focus-visible.

DefaultFocusInvalidDisabledRead-only

Name is required

Invalid is shown after the field is touched. Mocks mark it with .invalid or Angular's ng-invalid.ng-touched; the design system expresses it as aria-invalid="true" with an error linked by aria-describedby. The border turns --color-danger-solid. A submitting form disables its button, not its fields.

Responsive behaviour

The mocks define no @media rule for this component, so it does not change at the 640, 768 or 1024 breakpoints. Controls are always 100% wide. .form-row stays side by side at every width; keep it for short fields such as first and last name.

Theming

The product ships one light appearance, so this component has no theme variants. It reads semantic tokens only; see the tokens section.

Accessibility

Role and pattern

Native input, select and textarea with a label; no ARIA role. Errors follow the WAI-ARIA technique of aria-invalid plus aria-describedby.

Keyboard

KeyAction
Tab / Shift+TabMoves between fields.
Arrow Up / Arrow DownChanges the option in a focused select.
EnterSubmits the form from a single-line input.

Focus

One shared ring: --focus-ring-width solid --color-focus-ring at --focus-ring-offset, shown on :focus-visible. The mocks removed the browser outline (outline: none) and relied on a border-colour change; the design system restores a visible ring.

The field also shows --color-accent as its border while focused, as the mocks do; the ring is added, not substituted.

Labelling

The visible label is the name; some mocks omit the for association or rely on placeholder text, and the system requires for/id. Placeholder text is an example, never a label. Error text is linked with aria-describedby.

Motion

Content

  • Labels are nouns in sentence case: "Username", "Current password".
  • Placeholders give an example or prompt: "Enter your username".
  • Errors say what is wrong and how to fix it: "Current password is required", "Please confirm your new password".
  • Hints state the rule up front: "Password must be at least 8 characters long".

Drift

  • Mocks removed the outline (outline: none) and changed only the border colour on focus; the system adds a visible focus ring.
  • Invalid was .invalid or ng-invalid.ng-touched; documented as aria-invalid.
  • Field error was .form-group .error-message, which collided with the form-level .error-message; documented as .field-error.
  • Some controls had aria-label values equal to test ids or lacked a for association; the system requires a visible label with for.
  • Inputs were 12px 16px padded at 16px in some stylesheets and 14px elsewhere; the system uses --text-body-sm.
