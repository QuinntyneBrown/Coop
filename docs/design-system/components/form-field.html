Form field

The field wraps one control with everything around it: a visible label, an optional marker, help text and an error message that says how to fix the problem.

WCAG 2.2 AAStatus: stableNative <label>

Overview

Every text field, search field, textarea and select in the admin sits inside a .field. The field stacks its parts in a fixed order: label, help, control, error. It has no look of its own beyond spacing and type.

  • Required is the default. Only optional fields are marked, with <span class="optional">(optional)</span> inside the label, as the website editor already does: "Small heading above the title (optional)".
  • Help (.field__help) says why the field exists or what a good answer looks like: "For example President, Treasurer, Secretary or Member at large." It sits above the control so it is read before typing.
  • Error (.field__error) is added below the control when the value is wrong. It names the field and says how to fix it: "Give the director's role on the board."

For a group of checkboxes or radios, use a fieldset and legend instead (checkbox, radio group). How fields are arranged on a page, the error summary and the submit button are covered by form layout.

Anatomy

  1. Label<label class="field__label" for>, --text-label, always visible.
  2. Optional marker.optional, regular weight in --color-fg-subtle.
  3. Help (optional).field__help, --text-body-sm in --color-fg-muted.
  4. ControlAn .input, .textarea or .select.
  5. Error (when invalid).field__error in --color-danger-fg with a ⚠ glyph, so colour is not the only cue.

Sizes

The field takes its control's size; label, help and error text do not scale.

States

The field's state is its control's state, plus the error text when invalid. Focus and hover are forced on the control with data-state.

  • Errors appear after a submit attempt, never while typing. They clear when the field is next changed.
  • An invalid field keeps the value that was typed, so a typo can be fixed rather than retyped. The admin already does this on Change password ("Passwords do not match" keeps all three values).
  • Read-only is the saving state; see text field.

Responsive behaviour

  • The field is the full width of its container on phones, inside a page card or a dialog.
  • Label, help and error wrap freely; nothing truncates or overflows at 320px, so the field keeps working at 400% zoom.
  • Fields stack in a single column. From the md breakpoint, two short related fields may share a row, as the website editor does for a button's "Label" and "Address". Below md they stack again.

Theming

The field reads --color-fg-default (label), --color-fg-subtle (optional marker), --color-fg-muted (help) and --color-danger-fg (error). All four are re-mapped by the dark theme; the field itself has no component tokens. The gap between parts is --space-1.

Accessibility

Role and pattern

Native <label for> tied to the control's id; no ARIA pattern is needed. Help and error are tied with aria-describedby, error first, then help: aria-describedby="director-title-error director-title-help". An invalid control sets aria-invalid="true".

Keyboard

KeyAction
Tab / Shift+TabMoves between controls; label, help and error are not focusable.
Enter on an error-summary linkMoves focus straight to the field; see form layout.

Focus

Focus is shown on the control, not the field. Clicking or tapping the label also focuses the control.

Labelling

Every control has a visible label tied with for (WCAG 1.3.1, 3.3.2). Do not add an aria-label that repeats a visible label; it hides the real label from the accessibility tree and the two drift apart. A placeholder is never the label. "(optional)" is part of the label text and is read with it.

Motion

None. Errors appear without animation.

Touch

The label is part of the target: tapping it focuses the control, which helps anyone with a less steady hand.

Content

  • Labels are short nouns in sentence case: "Username", "Confirm new password", "Role on the board", "Page title". Not "Confirm New Password".
  • Help says why or how, in one sentence: "Describe the photo for people who cannot see it."
  • Errors say what to do, not what went wrong in system terms: "Enter your username", "Give the page a title". Not "Username is required" or "Invalid value".
  • An error that compares two fields names both: "The two new passwords are different. Type the new password again." Not "Passwords do not match".
  • "(optional)" in brackets, lower case, after the label.

Drift from the implemented admin

The implemented admin is green, set in Outfit, with Material Icons; this page adopts the system's violet, rounded system fonts and stroke icons. Field-specific drift:

  • Wrapper. The admin uses .form-group with a 16 to 20px bottom margin and a 6px gap under a block label. The system uses .field with a --space-1 gap and lets the form's .stack space the fields.
  • Labels. Admin labels are 14px medium, some at 80% opacity, and in title case ("Confirm New Password", "Invitation Token"). The system uses --text-label in --color-fg-default and sentence case.
  • Label association. Change password, Add user, Edit user, New invitation and New maintenance request render <label> without for and copy the text into aria-label. The system requires <label for> and no duplicate aria-label.
  • Errors. Sign in and Create account show .error-message in red under the input, mark the input with an .invalid class and do not link the message. Change password shows error text with no invalid style on the input. Add user and New maintenance request show only a red border on touched fields, with no text. The system always pairs aria-invalid="true", a .field__error and aria-describedby.
  • Help. The board, page and website editors already use .field-help and .field-error with aria-describedby, but put help below the control at 13px and draw the error icon with the Material error_outline glyph. The system moves help above the control at --text-body-sm (14px) and uses a ⚠ glyph.
  • Error copy. "Username is required" and "Passwords do not match" become instructions: "Enter your username", "The two new passwords are different. Type the new password again."
