Top bar

The header across the top of a signed-in admin page on a phone. It keeps the co-op's name and a way to your own profile in view while the sidebar is hidden, and it stays put as the page scrolls.

WCAG 2.2 AAStatus: stableNative <header> of links

Overview

The implemented admin has no top bar. On a wide screen the sidebar already shows the co-op's name and who is signed in. On a phone the sidebar is hidden, and those two things would disappear. The top bar brings them back in a single row, so a staff member on her phone can always see which co-op she is managing and reach her own profile.

  • Use it on every signed-in admin page below 768px, together with the tab bar at the bottom. Inside .app-shell it hides itself from 768px, where the sidebar takes over.
  • The brand links to the Dashboard. The avatar is a link to My profile (pages/admin-profile). There is no account menu: Edit profile, Change password and Sign out stay on the Profile page, as they are today.
  • Do not put page titles, search or page actions in the bar. The page header below it has the <h1> and the page's main button.
  • Sign-in, registration and forgotten-password pages have no top bar.
  • In these pages, .topbar--static keeps the bar visible at desktop widths. It is only a hook and adds no other styles.

Anatomy

  1. Brand.topbar__brand: the co-op's logo mark (a 32px tile, decorative) and "OWN Housing Co-op" in --text-h4; a link to the Dashboard.
  2. Spacer.topbar__spacer pushes the avatar to the right edge.
  3. Profile linka.avatar.avatar--sm (32px) with the person's initial; goes to My profile.
  4. Capsuleheader.topbar: a pill (--radius-full) floating --space-2 below the top of the screen, as wide as the page less its margins, 56px tall, translucent surface with a background blur, hairline border and --shadow-2.

With navigation links (core, not used in the admin)

The core component can also hold .topbar__nav, a row of .nav-links that appears from 768px. It suits a product with three or four sections and no sidebar. The admin has thirteen sections and a sidebar, so it does not use this variant; it is documented so the class is not reinvented.

Sizes

The bar is always at least --layout-topbar-height (56px) tall; it grows if the text is enlarged. Only its contents change with width.

States

The bar has no state of its own; its two links do. Hover and focus are forced with data-state.

  • On My profile: the avatar link takes aria-current="page", so screen readers announce it as the current page.
  • Long co-op name: the brand wraps to two lines rather than truncating; the bar grows taller to fit.

Responsive behaviour

  • Base (phones, up to 767px): brand, spacer, avatar. The bar is sticky at --space-2 from the top at --z-sticky, and as wide as the content column less --layout-margin on each side, so it lines up with the page.
  • From 768px the sidebar carries the brand and the person's name, so .app-shell .topbar is hidden. .topbar--static opts out of that rule; these pages use it to show the bar at every width.
  • Sticky, not fixed: the bar stays in the flow, so nothing starts hidden under it. scroll-padding-top on html equals its height plus --space-4, so in-page links and focused fields are never covered.
  • At 320px (a phone, or 400% zoom) "OWN Housing Co-op" and the avatar fit on one row; with larger text the brand wraps instead of pushing the avatar off screen.

Theming

The bar is --color-bg-surface at 90% (color-mix) over a 12px backdrop blur, with a hairline --color-border-default and --shadow-2, so it reads as floating above the page in both themes. Text contrast is measured against the opaque surface; the blur keeps content behind it from lowering the ratio noticeably. The brand reads --color-fg-default; the avatar reads the accent pair. The logo mark uses token fills, so the dark theme needs no separate artwork.

Accessibility

Role and pattern

A native <header> outside <main>, which is the page's banner landmark on phones (the sidebar's <header> is hidden there, so only one banner is exposed), following the APG landmark regions guidance. It holds two ordinary links; no ARIA widget is needed.

Keyboard

Focus

The shared 2px --color-focus-ring with 2px offset on the brand and the avatar. Because the bar is sticky, scroll-padding-top keeps the focused field below it (WCAG 2.4.11).

Labelling

The logo mark is aria-hidden; the words "OWN Housing Co-op" name the brand link. The avatar shows only an initial, so it has aria-label="My profile, mira.fern", which says where it goes and whose profile it is.

Motion

Nothing moves. The bar does not hide or shrink on scroll, so it is always where people expect it. Nav links in the core variant fade over --duration-fast, zeroed by reduced motion.

Touch

The brand link is the full bar height. The avatar is 32px (--size-avatar-sm), above the 24px minimum, and the spacer keeps it well away from the brand.

Content

  • The brand is the co-op's name exactly as written: "OWN Housing Co-op". No page titles in the bar.
  • The avatar shows the first letter of the username ("M" for mira.fern); its label says "My profile" and names the account.
  • Sign out is not in the bar. It stays on the Profile page with Edit profile and Change password.

Sources

Adapted from the Shelfie design system's top bar. The admin has no top bar, so this page is grounded in what the admin shows at the top of a phone screen:

  • pages/admin-dashboard/default (the brand block and user footer that the phone header replaces; view it below 768px)
  • pages/admin-maintenance/default (a working page whose heading sits below the stacked sidebar on phones)
  • pages/admin-profile/default (My profile, where the avatar goes and where Sign out lives)
  • pages/admin-login/default (signed-out page: no top bar)

Drift from the implemented admin

  • No top bar: at 768px and below the admin turns its whole sidebar (.sidebar-header .logo, all thirteen .nav-items and .sidebar-footer .user-info) into a static block above the page. The system replaces that block with this short bar and moves the sections to the tab bar and its More dialog.
  • Brand: the admin's .logo is a plain div with the logo in its own terracotta, peach and cream colours and the name in Outfit. The system makes it a link to the Dashboard with token fills.
  • Profile: the admin's .user-avatar in the sidebar footer is not a link; My profile is reached from the bottom tab bar's Profile tab. The system links the top bar's avatar to My profile. Sign out stays on the Profile page; no account menu is added.
  • Theme: the admin is light only. The system adds the dark theme.
  • Gap: components.css has no a.avatar rule, so the global link underline and hover colour would apply to the profile link. The examples here remove the underline inline; a shared a.avatar rule (no underline, the same hover ring as button.avatar) is still needed.
