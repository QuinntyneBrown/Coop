Top bar

A sticky header holding the logo and a few global icon buttons, such as notifications and the menu that opens the sidebar drawer.

WCAG 2.2 AAStatus: stableNative <header>

Overview

The top bar is a sticky strip across the top of the screen. In the public member app it holds the logo and two icon buttons: notifications and the menu (hamburger) that opens the sidebar drawer. The admin shell has no top bar: each admin page starts with its own page heading.

  • Use it for brand and global actions, not for page-level navigation; that belongs in the sidebar or bottom tab bar.
  • Its icon buttons are icon buttons.

Anatomy

  1. Bar (.top-bar)Sticky at the top, --z-sticky, white surface, hairline rule below.
  2. Inner (.top-bar-inner)Row with space between, centred, max width --layout-container-max (1440px), --space-3 by --space-4 padding.
  3. Logo (.logo)Mark and product name.
  4. Actions (.top-bar-actions)Icon buttons with --space-2 gap. Each needs an aria-label.

Variants

Two bars exist in the product. Both use the same surface and rule; they differ in content.

Admin: page title, search and bell

Users

Admin pages place a title and actions in .topbar (16px 24px padding). The layout properties here are the admin page's own; the shared stylesheet supplies only surface, rule and stickiness.

Sizes

The top bar has one size; its height comes from the 40px icon button plus vertical padding.

States

The bar itself has no states. Its icon buttons have hover, focus, active and disabled states documented on icon button.

Default, hover, focus and pressed. The menu button sets aria-expanded while the drawer is open.

An unread-count badge on the bell exists in the public stylesheet (.notification-badge, 16px circle on the error colour) but is not in the shared component stylesheet yet; see the request in the page handover.

Responsive behaviour

  • The bar is sticky at every width and fills the width up to 1440px (--layout-container-max), then centres.
  • The public bar and drawer swap at 1024px: the docked sidebar shows at 1024px and wider; below that the hamburger opens the drawer. No @media rule hides the hamburger itself in the captured CSS.
  • The admin .topbar has no breakpoint rule of its own.

Theming

The product ships one light appearance; there are no theme variants.

Accessibility

Role and pattern

A <header> banner landmark containing buttons. The hamburger is a disclosure button: aria-expanded reflects whether the drawer is open and aria-controls points to it (requirement; the mocks set neither).

Keyboard

KeyAction
Tab / Shift+TabMoves between the logo (if a link), bell and menu buttons.
Enter, SpaceActivates the focused button.
EscRequirement: closes an open drawer opened from the menu button and returns focus to it.

Focus

Shared focus ring on :focus-visible. Sticky bars must not hide a focused element: the top bar does not cover content because the page scrolls beneath it with the scroll padding of the bar height (requirement, WCAG 2.4.11).

Labelling

Icon-only buttons need aria-label. The mocks give "dashboard notification bell" and "dashboard hamburger menu", which repeat the page name; the system labels are "Notifications" and "Open menu".

Contrast

Icon on surface
Hover background keeps icon readable
Focus ring on surface
Logo mark on surface (non-text)

Motion

Hover background changes over --duration-base; no other motion in the bar.

Touch

Icon buttons are 40px square with 8px between them, above the 24px minimum.

Content

  • The logo text is the co-op's name ("OWN Housing Co-op"), not the page title in the public bar. The admin bar shows the page title as its heading.
  • Action labels name the action ("Notifications", "Open menu"), not the icon ("Bell", "Hamburger").
  • If a count is shown it is included in the name: "Notifications, 3 unread".

Drift

Where the mocks differ from each other or fail WCAG 2.2 AA, the design system resolves it as follows.

  • Hamburger and bell have page-prefixed labels ("dashboard hamburger menu"); the system uses "Open menu" and "Notifications".
  • Menu button sets no aria-expanded or aria-controls; both are required.
  • Admin uses .topbar (16px 24px padding) and public uses .top-bar (12px 16px); both classes share one rule here.
  • Icon buttons use 8px padding with no focus style; the system uses the 40px icon button and the shared focus ring.
