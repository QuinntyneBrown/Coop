Chip

A pill-shaped toggle button that narrows a list to one kind of thing: maintenance requests that are "New", or documents that are "Notices". One chip in a row is pressed at a time, and it says so with aria-pressed.

WCAG 2.2 AAStatus: stableNative <button>

Overview

Use a row of filter chips above a list when staff want to see one group at a time and there are five or fewer groups. The first chip, "All", is pressed when the screen opens. Pressing another chip shows only that group and un-presses the rest. A chip never saves, sends or deletes anything.

  • Use tabs when each choice shows a different panel of content, such as the Settings sections. Filter chips keep one list and change what is in it.
  • Use a select when there are more than five groups, or when the filter is one of several on a toolbar.
  • Use a badge to show a status that cannot be pressed.

Anatomy

  1. Label--text-label, one or two words. The accessible name.
  2. Pill36px tall (--control-height-sm), 12px side padding, --radius-full, 1px --color-border-strong. Accent tint and accent border when pressed.

Variants

The admin uses one variant, the filter chip. Removable "input" chips and static tags do not appear in the admin; a status that cannot be pressed is a badge.

Maintenance requests by status

From Maintenance. The list heading changes with the chip: "All requests", "Completed requests".

<div class="cluster" role="group" aria-label="Show requests">
  <button class="chip" type="button" aria-pressed="true">All</button>

Sizes

One size, 36px tall (--control-height-sm). Chips sit in a .cluster with 12px between them, which keeps neighbouring targets apart.

States

Pointer and focus states are forced with data-state; real pages get them from :hover, :focus-visible, aria-pressed and disabled.

ChipDefaultHoverFocusPressedPressed, focusDisabled
Filter

Both themes

  • Pressed uses aria-pressed="true": accent tint, accent border, accent label. Exactly one chip in a group is pressed.
  • Disabled uses the native attribute at 50% opacity. Keep chips enabled while the list loads, as the admin does, so staff can change their mind; disable only if a filter cannot work at all.
  • No results is a state of the list, not the chip: the chip stays pressed and the list shows its empty state ("No maintenance requests found").

Responsive behaviour

  • Chips wrap onto new lines inside the .cluster; they never scroll sideways and never shrink.
  • Labels do not wrap inside a chip. At 320px the five maintenance chips take two lines, which is fine.
  • At 400% zoom each chip may sit on its own line; the order stays the same, so "All" is always first.
  • On Documents the search field and New document button move to their own row under the chips on phones.

Theming

Unpressed chips read --color-bg-surface, --color-border-strong and --color-fg-default; hover adds --color-bg-subtle. Pressed reads --color-accent-subtle, --color-accent and --color-fg-accent. All are semantic tokens, so both themes come for free; re-theme by changing them, not by restyling .chip.

Accessibility

Role and pattern

Native <button type="button"> in the toggle form of the WAI-ARIA button pattern (aria-pressed). The set sits in role="group" with an aria-label such as "Show requests". The group acts as a single choice, so the script that presses one chip sets aria-pressed="false" on the others. Do not use role="tab": there are no separate panels.

Keyboard

KeyAction
Tab / Shift+TabMoves chip to chip; every chip is a tab stop.
Enter / SpacePresses the chip and filters the list. Pressing the chip that is already pressed does nothing.

Focus

The shared 2px focus ring with 2px offset, which stays at least 3:1 on the pressed accent tint. Focus stays on the chip after the list changes, so a keyboard user can try the next filter straight away.

Labelling

The visible text is the name. Screen readers announce "Completed, toggle button, pressed". The group's aria-label gives the context. The list heading below ("Completed requests") confirms the result when the person moves on; it is not a live region, so the filter does not interrupt with an announcement.

Motion

Background colour fades over --duration-fast (120 ms), zeroed under prefers-reduced-motion.

Touch

36px tall with 12px between chips: above the 24px minimum, and the gap keeps a finger from pressing two. Nothing depends on hover.

Content

  • One or two words, sentence case: "All documents", "Bylaws", "Completed".
  • Use the same words as the badges in the list, so "Started" the chip shows "Started" the badges.
  • "All" comes first, then the groups in the order work moves through them (New, Received, Started, Completed) or in the order staff use them most.
  • No more than five chips in a group; more than that is a select.

Drift from the implemented admin

  • The admin draws filters as .filter-btn inside .filters (Maintenance) or .filter-tabs (Documents), styled separately in each feature. The system uses one .chip inside a .cluster.
  • The pressed filter is marked only by the .active class (and data-active on Documents); there is no aria-pressed, so a screen reader cannot tell which filter is on. The system requires aria-pressed and a labelled role="group".
  • The pressed filter is solid green with white text and an 8px by 16px padding at 14px type. The system uses the accent tint with an accent border and label, 36px tall.
  • The unpressed border is a pale grey that does not reach 3:1 against white (1.4.11). The system uses --color-border-strong, at least 3:1 in both themes.
  • Maintenance chips animate with transition: all 0.2s, which ignores reduced motion. The system fades only the background, over --duration-fast, zeroed for reduced motion.
  • Documents labels use Title Case and a hyphen ("All Documents", "By-Laws"); the system writes "All documents" and "Bylaws".
  • The buttons have no type; the system always sets type="button".
