Picture list

A picture list shows photos and files as square thumbnails with their names, so staff can find one by eye. It is the Assets library, the grid in the Choose a photo dialog and the photos on a maintenance request.

WCAG 2.2 AAStatus: stableNative <ul> of thumbnails

Overview

Use a picture list when the picture is how people recognise the thing: a photo of the courtyard, a portrait, the leak under the sink. Each item is a square thumbnail with its name under it. Files that are not pictures, such as "Meeting notes.pdf", get a file icon in the same square so the grid stays even.

  • Library (Assets page): every uploaded file, each with Details, which opens the Asset details dialog (Download, Delete).
  • Choose one (Choose a photo dialog): each photo is a button; the one in use is pressed and says "Current". Below the grid, Upload a new photo.
  • Attached photos (a maintenance request): each thumbnail is a link to the full-size photo.

For one person's photo use the photo picker. For things without pictures use a list or a table.

Anatomy

  1. Thumbnail.picture-list__thumb: a square with --radius-md corners on --color-bg-subtle; the picture is cropped to fill it.
  2. File iconFor files that are not pictures: a 40px file icon, centred, in --color-fg-muted.
  3. NameThe file name in --text-label, wrapping anywhere.
  4. Note.picture-list__note: size and upload date in --text-caption, --color-fg-muted.
  5. Actions.picture-list__actions: a small Details button named for the file.

  • Current: the photo in use has aria-pressed="true", an accent ring and the word "Current" with a check, so it never rests on colour alone.
  • Hover outlines a choice in --color-accent; focus draws the shared ring.
  • Uploading disables the photo buttons and the upload, and says "Uploading…" in the status line, as the dialog does. Cancel waits too.
  • Failed and too large keep the grid as it was and say what to do; the upload stays ready to try again.
  • Empty and no results are different: empty invites an upload, no results names the search and offers Clear search.

Both themes

Responsive behaviour

  • The grid is repeat(auto-fill, minmax(8.5rem, 1fr)): two columns at 320 CSS px, three in a 32rem dialog, five or more on a wide Assets page. Nothing scrolls sideways.
  • Columns are in rem, so at 400% zoom the grid drops to one or two columns of the same large thumbnails.
  • Names wrap anywhere, so a long file name never widens its column.

Theming

Only role tokens: --color-bg-subtle behind thumbnails, --color-border-default around them and around choices, --color-accent for the current ring and hover, --color-fg-muted for notes and file icons, --color-danger-fg for errors. Photos look the same in both themes; their frame and the surface around them change.

Accessibility

Role and pattern

A native <ul> named with aria-label ("Assets", "Photos in the Assets library"), so a screen reader says how many there are. In the Choose one variant each photo is a native toggle button (aria-pressed), named by the file name under its picture; the picture has alt="" so the name is not read twice. Attached photos are links named by their image's alt.

Keyboard

KeyAction
Tab / Shift+TabMoves through the photo buttons, Details buttons or photo links in reading order, then to Upload a new photo.
Enter / SpaceChooses the focused photo, opens Details, or opens the file chooser.
EscIn the Choose a photo dialog: closes it and keeps the current photo.

Focus

Every button and link shows the shared 2px ring. After a photo is chosen the dialog closes and focus returns to the Choose a photo button that opened it. After an upload, focus stays on Upload a new photo.

Labelling

Details buttons say which file they open: "Details for tap.svg". An attached photo's alt says what it is and where it belongs: "Photo 1 of Kitchen tap leak". "Uploading…" is read from the status line; failures are read as they appear.

The thumbnail border is decoration; the current photo is marked by the 3:1 accent ring and the word "Current".

Motion

Pictures fade in over --duration-base; under prefers-reduced-motion they appear at once.

Touch

Each choice is a whole thumbnail, at least 136px square in the standard grid, with 12px between neighbours. Details buttons are 32px tall with their label.

Content

  • Show the file name as uploaded ("Courtyard plan.pdf") and a note with size and date: "2 KB · Tue 13 Oct".
  • Mark the photo in use with "Current". Buttons: "Details", "Upload a new photo".
  • Help: "JPEG, PNG or WebP, up to 10 MB." on photo uploads; "Any file, such as a photo or a PDF, up to 28 MB." on the Assets upload.
  • Empty: "No photos in the library yet. Upload one below." in the dialog, "No assets uploaded yet" on the Assets page. No results: "No assets match "garden"".
  • An attached photo's alt: "Photo 1 of Kitchen tap leak".

Drift from the implemented admin

  • Assets are div.asset-card.cards with role="link" and tabindex="0"; the whole card opens the details. The system puts a Details button, named for the file, in each item.
  • Every asset's thumbnail is the Material Icons insert_drive_file glyph, even for photos. The system shows photos as themselves and a stroke file icon only for other files.
  • The meta line reads "2 KB · Oct 13, 2026"; the system writes "2 KB · Tue 13 Oct".
  • A search with no results shows "No assets uploaded yet" while the header still says "2 assets". The system has a separate no-results state.
  • The Choose a photo dialog's .photo-option buttons already use aria-pressed and a "Current" tag with a check, as the system does. Their thumbnails are 150 by 112 landscape crops; the system crops to squares in the standard grid.
  • The upload under the grid is a bare native file input; the system wraps it in a label.btn (see photo picker).
  • Maintenance photos (.attachment-grid) open in a new tab with target="_blank" and no warning; the system opens them in the same tab. Their alt text ("Photo 1 of Kitchen tap leak") is kept.
  • Global: the implemented admin uses Outfit, Material Icons and a light theme only.
