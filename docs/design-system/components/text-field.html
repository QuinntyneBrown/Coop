Text field

A single-line input for the short things the admin asks for: a username, a password, a page title, a director's name, an expiry date.

WCAG 2.2 AAStatus: stableNative <input>

Overview

Put .input on a native <input> and wrap it in a form field for its label, help and error. Use a textarea when the answer can run to more than one line, a select when the answer is one of a fixed list (Role, Type, Priority), and a search field to filter a list.

The admin mocks use these input types. Each brings the right keyboard and autofill:

  • Text: Username, Invitation token, Title, Page title, Name, Role on the board.
  • Password: Sign in, Create account, Change password and Add user. Use autocomplete="current-password" to sign in and new-password to set one.
  • Date: "Expires" in New invitation.
  • URL: "Photo address" in the board editor.
  • E-mail: the profile step of onboarding, with autocomplete="email".

Anatomy

  1. LabelFrom the form field; always visible.
  2. Value--text-body (16px) in --color-fg-default. No placeholder.
  3. Container--field-bg and --field-border, --radius-md, hairline border, --control-height-md (44px) tall.

Variants

One look; the type, inputmode and autocomplete attributes do the work.

Text, password, date and URL, as in Create account, Change password, New invitation and the board editor.
HTML
<input class="input" id="username" type="text" autocomplete="username"
       autocapitalize="none" spellcheck="false" required>
<input class="input" id="new-password" type="password" autocomplete="new-password" required>
<input class="input" id="expires" type="date" required style="max-width: 14rem;">
<input class="input" id="photo" type="url" spellcheck="false">

With trailing button (show or hide password)

A password field can carry an icon-only ghost button inside the box. It switches the value between dots and plain text, so someone can check what they typed before pressing Sign in. .input-group positions the button; aria-pressed="true" colours the icon. The implemented admin has no such button yet.

Password hidden, then shown.
HTML
<div class="input-group">
  <input class="input" id="password" type="password" autocomplete="current-password" required>
  <button class="btn btn--ghost btn--icon input-group__btn" type="button"
          aria-label="Show password" aria-pressed="false"><svg class="icon" aria-hidden="true" …></svg></button>
</div>

Sizes

Medium (44px) is the size for every admin form. Small and large exist in the stylesheet; the admin screens do not use them today. Keep small out of forms that people fill in; it is for tight toolbars only.

Small 36px (.input--sm, --font-size-sm), medium 44px, large 52px (.input--lg, --font-size-lg).

Both themes

  • Invalid adds a --color-danger-solid border plus an inset ring, so the edge reads as 2px without shifting the layout. Always paired with a .field__error.
  • Read-only is what every field becomes while its form is saving ("Signing in…", "Saving…"): the value stays visible, selectable and focusable on a sunken background, and nothing can change under the request.
  • Disabled is for a field that does not apply right now. Do not use it as the saving state: focus is lost and the value is harder to read.

Responsive behaviour

  • Inputs are width: 100% of their field. An inline max-width may hint at the expected length: 14rem for a date, 20rem for a username.
  • The value is 16px at every width, so no phone browser zooms the page on focus, and the text stays readable at 400% zoom.
  • On a 320px screen the field, its label and its error all wrap inside the column; nothing scrolls sideways.

Theming

Two component tokens carry every state: --field-bg (default --color-bg-surface, read-only --color-bg-surface-sunken, disabled --color-bg-subtle) and --field-border (default --color-border-strong, hover --color-fg-muted, focus --color-focus-ring, invalid --color-danger-solid). The textarea, search field and select share both.

/* Each state only reassigns the two tokens */
.input:read-only:not(:disabled) { --field-bg: var(--color-bg-surface-sunken); }
.input[aria-invalid="true"] { --field-border: var(--color-danger-solid); }

Accessibility

Role and pattern

Native <input> with the right type; the browser provides the textbox or date field role. Labelled by a <label for> in a form field. The matrix above uses aria-label only because its cells have no room for labels.

Keyboard

KeyAction
Tab / Shift+TabMoves focus into and out of the field. Read-only fields stay in the tab order; disabled ones leave it.
↑ / ↓ in a date fieldChanges the focused day, month or year.
Tab to the trailing buttonFocuses the show or hide button, right after the input.
Space / Enter on the trailing buttonSwitches the password between hidden and shown. Does not submit.
Enter in the inputSubmits the form.

Trailing button

The show or hide button is a native <button type="button">, so pressing it never submits the form. Its aria-label stays "Show password" and aria-pressed switches between false and true; the script swaps the input type between password and text. Focus stays on the button.

Focus

The border turns --color-focus-ring and the shared ring is drawn with no offset, hugging the box. Focus moves to the first field on the sign-in pages and in dialogs (autofocus), and to the error summary after a failed submit.

Labelling

Every input has a visible label. Use autocomplete for the signed-in person's own details so password managers and autofill work (WCAG 1.3.5, 3.3.8): username (with autocapitalize="none" and spellcheck="false"), email, current-password, new-password. Fields about other people or about website content, such as a director's name or a page title, take autocomplete="off", as the board and page editors already do. Paste is always allowed.

Disabled text is exempt from contrast minimums, which is one more reason not to disable fields while saving.

Motion

Border colour and ring transition over --duration-fast; zeroed under reduced motion.

Touch

Medium inputs are 44px tall and large are 52px. Small (36px) still clears the 24px minimum but is kept out of forms. The trailing button is 36px square inside the box.

Content

  • No placeholders in forms. A hint belongs in .field__help, where it stays visible. "Enter your username" under a "Username" label adds nothing and disappears on the first keystroke.
  • Pre-fill what is known: Edit user opens with the username; the editors open with the saved title and text.
  • Keep what was typed after an error; only the person changes it.
  • Mask passwords with the browser's own masking; never echo them anywhere else on the page.

Drift from the implemented admin

The implemented admin is green, set in Outfit, with Material Icons, light theme only; this page adopts the system's violet, rounded system fonts, stroke icons and both themes. Input-specific drift:

  • Size and type. Admin inputs are 14px text with 10 to 12px by 14px padding, about 40px tall, and an 8px or 10px radius depending on the screen. The system uses 16px --text-body, 44px --control-height-md and --radius-md everywhere.
  • Border contrast. The admin's 1px pale grey border is well under 3:1 against white (WCAG 1.4.11). The system's --color-border-strong passes in both themes.
  • Focus. The admin removes the outline (outline: none) and shows focus only as a green border, with a faint 3px glow on Sign in. The system keeps the border change and adds the shared --color-focus-ring outline.
  • Invalid. Sign in and Create account mark inputs with an .invalid class; dialogs rely on Angular's .ng-touched.ng-invalid; Change password shows no invalid style at all. The system uses aria-invalid="true" only.
  • Placeholders and autofill. Sign in and Create account use placeholders that repeat the label ("Enter your username", "Create a password") and set no autocomplete. The system drops form placeholders and requires autocomplete on the person's own username and passwords.
  • Saving state. Sign in, Create account and Change password leave fields editable while the button says "Signing in..." or "Creating..."; the board and website editors disable every field. The system makes fields read-only while saving.
  • Labels. Title case ("Invitation Token", "Confirm New Password") and labels without for; see form field.
  • Show password. No admin password field has a show or hide button; the system offers .input-group for one.
