Avatar

The avatar marks a person with their initials. One accent fill, three sizes, always decorative.

Overview

An avatar is a filled circle holding a person's initials. The mocks use it for the signed-in user in the sidebar, for people in the admin user list, for a member on the profiles cards and for the large mark on the profile pages.

  • It is decorative. The person's name is always printed next to it, or the avatar sits in a labelled control.
  • There is one colour: the accent background with white initials.
  • There are no photos, no status dots and no stacked groups in the mocks; none are documented here.

Anatomy

  1. ContainerCircle (--radius-full) sized by --avatar-size, filled with --color-accent.
  2. InitialsOne or two capital letters, --text-label at semibold, --color-fg-on-accent.

Variants

There is a single variant. The mocks draw the circle in blue, amber and red on the admin user list; the design system resolves that to the accent (see Drift).

The member cards on the profiles screen use 60px and 64px circles. These one-off sizes are not added to the scale; use the large or default avatar there.

States

An avatar is a static, non-interactive element. It has no hover, focus, active, disabled or loading state. If an avatar must be clickable, wrap it in a button or link that carries the label.

Responsive behaviour

The avatar does not change size at any breakpoint. The circle keeps flex-shrink: 0 so a long name beside it wraps instead of squashing the circle into an oval.

Theming

The product ships one light appearance; there are no theme variants. The avatar reads --color-accent and --color-fg-on-accent only.

Accessibility

Role and pattern

Presentational. No WAI-ARIA widget pattern applies. Initials are decoration, so the element carries aria-hidden="true" and the person's name is read from the adjacent text. The mocks set no ARIA on the avatar; the design system requires it.

Keyboard

KeyAction
Not applicableThe component takes no focus and has no key handling.

Focus

None. When wrapped in a control, that control owns the shared focus ring.

Labelling

Where the avatar stands alone inside a control (for example a profile menu trigger), the control's aria-label names the person; the avatar stays aria-hidden.

Contrast

Initials on accent

The mocks' amber fill with white initials is below 4.5:1 and fails; that is why the design system keeps one accent fill.

Motion

None.

Touch

Not a target. The 32px small size is below 44px, which is acceptable only because it is never the control itself.

Content

  • Use the first letter of the first name and of the last name in capitals ("MF"). A single-word name gives one letter ("M").
  • Never more than two characters.
  • Always show the full name beside the avatar; the initials do not replace it.

Drift

  • Mocks: .user-avatar (32/36px), .avatar-circle (100px) and .member-avatar (60/64px) are three classes for one idea. Resolved to .avatar with -sm and -lg.
  • Mocks: admin-users sets arbitrary inline backgrounds (blue, amber, red); white initials on amber fail AA. Resolved to the single accent fill.
  • Mocks: no ARIA on the avatar. Requirement: aria-hidden="true" when the name is adjacent.
