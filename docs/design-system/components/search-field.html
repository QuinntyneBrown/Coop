Search field

A labelled box that narrows a long list as you type: users, documents, assets and conversations.

WCAG 2.2 AAStatus: stableNative <input type="search">

Overview

The .search wrapper holds three things: a leading magnifier .icon, an .input with type="search", and a ghost icon button (.search__clear) that empties the box. It sits in a form field for its label, like every other input.

The admin has four searches, each filtering the list right below it as the person types. There is no search button.

  • Users, in the page header beside "Add user".
  • Documents, in the toolbar under the All documents, Notices, By-laws and Reports filters, beside "New document".
  • Assets, in the page header beside "Upload".
  • Messages, at the top of the conversation list, beside the new conversation button.

To narrow a list by a fixed category (New, Received, Started, Completed), use filter chips or tabs instead. When nothing matches, show an empty state written for "no results", not the one for an empty list.

Anatomy

  1. Label<label for>; visible, or .visually-hidden in a page toolbar.
  2. MagnifierDecorative stroke icon, --size-icon-md, --color-fg-subtle, aria-hidden="true".
  3. Input.input with type="search", 44px, pill radius (--radius-full), padded for the icon and button.
  4. Clear button.btn.btn--ghost.btn--icon.search__clear, 36px; shown only once the box has text.

Variants

Two variants, which differ only in whether the label is seen.

Visible label: the default, and the right choice wherever there is room above the box.
HTML
<div class="field" role="search">
  <label class="field__label" for="documents-search">Search documents</label>
  <div class="search">
    <svg class="icon" aria-hidden="true" viewBox="0 0 24 24"><circle cx="11" cy="11" r="7"/><path d="M20 20l-3.5-3.5"/></svg>
    <input class="input" id="documents-search" type="search" placeholder="Search by title"
           autocomplete="off" spellcheck="false">
    <button class="btn btn--ghost btn--icon search__clear" type="button" aria-label="Clear search">…</button>
  </div>
</div>

Users

Toolbar: the label is visually hidden because the page title and the magnifier already say what the box searches. The placeholder repeats the label so sighted people see it too.
HTML
<div class="field" role="search">
  <label class="field__label visually-hidden" for="users-search">Search users</label>
  <div class="search">… placeholder="Search users" …</div>
</div>

Sizes

One size, medium (44px). The clear button needs the room, so .input--sm is not used inside .search.

States

Hover and focus are forced with data-state. The clear button appears by itself once the box has text.

Users

Both themes

  • Invalid and read-only do not apply: any text is a valid search, and nothing is saved.
  • Disabled is not used by the admin. Keep the search usable while the list loads; the list shows its own loading row.

No results

When the list has items but none match, say what was searched and offer the way back. Keep the words in the box. This is a different message from an empty list ("No users yet").

Responsive behaviour

  • In a page header the field takes the free width beside the title and the primary button (flex: 1 1 14rem; min-width: 0). Below about 40rem the header wraps: title first, then the search on its own full-width row, then the button.
  • In the Messages conversation list the field is the full width of the list panel.
  • At 320px or 400% zoom the field stays full width and the placeholder may be cut off at the end; keep placeholders to two or three words so the start always shows.
  • The value is 16px, so phones do not zoom the page when the box gets focus.

Theming

The input inherits --field-bg and --field-border from .input, so its states match the text field in both themes. The search adds a pill radius (--radius-full), a magnifier in --color-fg-subtle and a ghost clear button that reads --btn-fg. Re-theme it by overriding the field tokens, not the wrapper.

Accessibility

Role and pattern

Native <input type="search"> (a searchbox) inside a field with role="search", which makes it a search landmark people can jump to. The clear control is a native <button type="button"> with aria-label="Clear search".

Keyboard

KeyAction
Tab / Shift+TabMoves into the box, then to the clear button when it is shown.
TypingFilters the list below; focus stays in the box.
EscEmpties the box in most browsers (built into type="search"). The clear button does the same in every browser.
Enter / Space on the clear buttonEmpties the box, shows the whole list again and moves focus back into the box.

Focus

The box shows the focus border and the shared ring with no offset; the clear button shows the shared ring. Clearing never leaves focus on a button that has just disappeared.

Labelling

Every search has a <label for>: "Search users", "Search documents", "Search assets", "Search conversations". In a toolbar the label may be visually hidden, never removed. The placeholder is a hint only. Result counts and "No users match …" go in a polite role="status" region (WCAG 4.1.3), so someone using a screen reader knows the list changed.

Motion

Border and ring transition over --duration-fast; zeroed under reduced motion. The clear button appears without animation.

Touch

The box is 44px tall. The clear button is 36px square, well over the 24px minimum, and sits inside the box so it cannot be confused with the button beside the field.

Content

  • Label: "Search" plus what is searched, in sentence case: "Search users". No trailing "...".
  • Placeholder: a short hint of what can be typed ("Search by title"), or the label itself when the label is hidden.
  • No results: name the search and give a next step: "No users match “neri.x”. Check the spelling, or search for part of the username."
  • Empty list (nothing to search yet) keeps its own words: "No documents yet".

Drift from the implemented admin

The implemented admin is green, set in Outfit, light theme only; this page adopts the system's violet, rounded system fonts, stroke icons and both themes. Search-specific drift:

  • Control. .search-input and .conv-search-input are plain type="text" boxes, 14px, about 35px tall with 8px by 14px padding, an 8px radius and a pale 1px border under 3:1, with no magnifier and no clear button. The system uses .search: type="search", 16px, 44px, pill radius, --color-border-strong, a magnifier and .search__clear.
  • Focus. The admin sets outline: none and shows focus only as a green border. The system adds the shared focus ring.
  • Label. No admin search has a <label>; each has an aria-label copied from its placeholder, trailing dots included ("Search users..."). The system requires a <label for>, visible or visually hidden, and role="search".
  • No results. Users shows "No users found" in a table row for both its empty and no-results states; Documents shows "No documents found"; Assets shows "No assets uploaded yet" and Messages "No conversations yet" in their no-results states. None names the search or offers a way back, and the captured no-results pages show an empty search box. The system's no-results message names the search, keeps it in the box and offers "Clear search".
  • Announcements. The admin does not announce result counts. The system adds a polite role="status" line.
