Description list

A description list shows the attributes of one thing as label and value pairs: a muted label on the left, a medium-weight value on the right, a hairline between rows. In the mocks it is the .info-row.

Overview

Use a description list for the facts about a single record, shown once and read in order: the public profile page (username, email, phone, unit), which is also reused in the profile-switcher screen. Use a table to compare the same facts across many records, and a form when the values are editable.

The mocks build it from div.info-row with two spans. The design system requires a real <dl> with <dt> and <dd>, so the relationship between each label and value is exposed to assistive technology.

Anatomy

  1. ListA <dl> with no browser margins.
  2. Row.info-row: a <div> grouping one dt and its dd; flex, label and value pushed apart, 12px vertical padding, hairline below (none on the last row).
  3. Label<dt class="info-label">: --text-body-sm, --color-fg-muted.
  4. Value<dd class="info-value">: --text-label (medium weight), right-aligned.

Sizes

The implemented description list has no size variants.

States

The mocks show no hover, selected or editable state for these rows; a value that is not available is shown as "Not provided" text.

Responsive behaviour

  • The mocks have no @media rule for the row. Label and value share one line with a 16px gap (--space-4) at every width.
  • A long value wraps inside its own half and stays right-aligned. Email addresses and file names are the long values in the mocks; allow them to break (overflow-wrap: anywhere) so a 360px viewport does not scroll sideways. This is a requirement; the mock does not set it.

Theming

The row uses semantic text and border tokens only.

Accessibility

Role and pattern

A native <dl> with <dt> terms and <dd> descriptions. Grouping a pair in a <div> inside the <dl> is valid HTML and lets the row carry the divider. No ARIA is needed. The source mocks used div and span elements, which expose no relationship; the system requires the <dl>. Do not recreate the structure with role="term" or role="definition".

Keyboard

No interaction. The list is read in document order; it contains no focusable elements unless a value is a link or button.

Focus

A link inside a value gets the shared focus ring (2px --color-focus-ring). The rows themselves never take focus.

Labelling

Each value is described by its dt, so there is no need for aria-label. Give the list a heading nearby (the card or dialog title); name it with aria-labelledby only when several lists share a page.

Motion

None.

Touch

Not interactive, so target size does not apply. Rows are at least 44px tall.

Content

  • Labels are single nouns in sentence case without a colon: "Username", "Unit".
  • Values are plain text. Keep dates in one format and units on numbers.
  • Order rows by importance: identity first, then contact, then status.
  • For a missing value write "Not provided" rather than leaving the row empty.
