Description list

A description list pairs a label with a value for the facts of one thing: an asset's file name, size and upload date, a member's username, e-mail and phone, or where a maintenance request is and who sent it.

WCAG 2.2 AAStatus: stableNative <dl>

Overview

Use a description list to show what is known about one thing, read-only, where every value needs its label to make sense: "555-0101" means little until it says "Phone". It is the read view of a form; the form's labels and the list's labels match word for word.

  • Asset details dialog: file name, size and when it was uploaded.
  • Profile: username, e-mail, phone and address.
  • Maintenance request details: who sent it and when, priority, address, phone and whether staff may enter when no one is home.

Do not use it for many things with the same fields; that is a table or a list. Do not use it for things people edit in place; editing opens a dialog or a form.

Anatomy

  1. Term<dt>, --text-label in --color-fg-muted. The label, in the same words as the form field.
  2. Value<dd>, --text-body in --color-fg-default. Wraps anywhere, so a long e-mail address never pushes the page sideways.
  3. Rule (horizontal only)A hairline --color-border-default under each pair from 640px, with 8px above and below.

Variants

Two layouts of the same markup. Choose by the space the list lives in, not by the data.

Vertical (.dl)

The label sits above its value at every width. Use it in dialogs and narrow panels, where a label column would squeeze the values.

Asset details

HTML
<dl class="dl">
  <dt>File name</dt><dd>Courtyard plan.pdf</dd>
  <dt>Size</dt><dd>2 KB</dd>
  <dt>Uploaded</dt><dd>Tue 13 Oct, 8:00 am</dd>
</dl>

Horizontal (.dl--horizontal)

From 640px the labels form a column and the values line up beside them, with a rule under each pair. Below 640px it stacks exactly like the vertical list. Use it on pages and wide panels.

Sizes

One size. Labels are 14px medium, values 16px regular, so the value is always the bigger, easier read.

States

A description list is not interactive, so it has no hover, focus or disabled state. A link inside a value has its own (see link). The list's states are about its values.

  • Missing values keep their label and say "Not given" in --color-fg-muted. Never leave a blank line or drop the row: a blank looks like a fault, and a dropped row hides that something is missing.
  • Loading shows one spinner row with a sentence in role="status" in place of the list, never empty labels.

Responsive behaviour

  • .dl is one column at every width: label, then value, then 12px before the next label.
  • .dl--horizontal is the same one column below 640px (40rem). From 640px it becomes two columns: labels at least 8rem and as wide as the longest label, values in the rest.
  • Because the breakpoint is in rem, zooming to 400% brings back the one-column layout. Values wrap anywhere, so nothing scrolls sideways at 320 CSS px.

Theming

The list reads --color-fg-muted for labels, --color-fg-default for values and --color-border-default for the horizontal rules. It has no background of its own, so it takes the surface it sits on: a card, a dialog panel (--color-bg-surface-raised) or the page.

Accessibility

Role and pattern

A native <dl> with <dt> and <dd> pairs as its direct children. Screen readers announce a description list and read each term with its value. No ARIA role. Keep each pair together and in order: one <dt>, then its <dd>.

Keyboard

KeyAction
TabPasses over the list, stopping only on links inside values (an e-mail or phone link).
EnterFollows the focused link.

Focus

Nothing in the list takes focus except links, which show the shared ring.

Labelling

Put a heading before the list that names the thing it describes ("Kitchen tap leak", "Asset details"). Labels are words, not icons, and carry no trailing colon; the layout already shows the pairing.

The horizontal rules are decorative grouping; 1.4.11 does not apply.

Motion

None.

Touch

Only links in values are targets. A phone or e-mail link is a full line of 16px text; keep one per value so neighbouring links are a whole row apart.

Content

  • Labels in sentence case and plain words, the same as the form that sets the value: "File name", "Uploaded", "Phone", "Entry when no one is home".
  • No colon after a label, and no label repeated in the value ("Phone: 555-0101" is wrong in a value).
  • Values as people would say them: "2 KB", "Tue 13 Oct, 8:00 am", "Unit 101", "No".
  • A missing value says "Not given". A value that cannot be shown to this person is left out with its label, never shown as "Hidden".

Sources

Extracted from these admin mocks:

  • dialogs/admin-asset-detail/default (file name, size, uploaded)
  • pages/admin-profile/default, pages/admin-profiles/default and empty (profile details)
  • pages/admin-maintenance/detail-new, detail-received and detail-completed (request meta and info grid)

Drift from the implemented admin

  • Asset details use a real <dl class="asset-detail-fields"> but wrap each pair in a <div> and pad values with spaces. The system uses .dl with bare pairs.
  • The profile view (.profile-info) shows username, e-mail, phone and address as unlabelled <p> lines; the empty profile shows blank lines and an empty heading. The system labels every value and says "Not given".
  • Maintenance details split the facts between .detail-meta spans ("Submitted by: Mira Fern", "Priority: High") and .detail-info-grid divs with <strong>Address:</strong>. The system puts them in one .dl--horizontal, labels without colons.
  • Labels are title case and jargon ("Unattended Entry"); the system uses sentence case and plain words ("Entry when no one is home"). The address shows a bare "101"; the system says "Unit 101".
  • Dates read "Oct 13, 2026, 8:00 AM"; the system writes "Tue 13 Oct, 8:00 am".
  • Global: the implemented admin uses Outfit, Material Icons and a light theme only.
