Tooltip

A small label that appears when the pointer rests on, or the keyboard reaches, an icon-only button, and says in words what the icon does: "Delete mira.fern", "Close". It adds visible text; it never holds anything you need to click.

Overview

The Coop admin has no tooltips today. The tooltip is part of the core set so that icon-only buttons, where they cannot be avoided, can show their meaning in words.

  • Icon-only buttons rely on aria-label for their name. A screen reader announces "Delete mira.fern, button" from the label alone; the tooltip is not what names the button.
  • Tooltips add visible text for sighted people who do not recognise an icon, which is common with a pencil, a bin or a cross when you are new to a screen or your eyesight is not what it was.

Use a tooltip on the icon buttons in a table row (Edit, Delete), on a card's Delete, and on a dialog's Close. Where there is room for a word, use a button with a visible label instead, as the page and director cards already do ("Edit", "Remove"); that is clearer than any tooltip. Do not use a tooltip for help with a field (use the field's help text), for errors, or for anything with a link or button in it (use a dialog).

Anatomy

  1. Anchor.tooltip-anchor: an inline wrapper around the trigger and its tooltip; it positions the tooltip and shows it on :hover and :focus-within.
  2. TriggerAn icon-only button with aria-label. It must work and be named without the tooltip.
  3. Bubble.tooltip: --color-bg-inverse with --color-fg-inverse, --radius-sm, --text-body-sm, 4 × 8px padding, at most 16rem wide, centred 8px above the trigger at --z-tooltip.

Variants

Two variants, chosen by whether the tooltip says the same as the button's name or adds to it.

Name echo: the same words as the label

Edit mira.fern Close
The usual case. The button's aria-label already says it, so the bubble is aria-hidden="true" and is not announced twice.
HTML
<span class="tooltip-anchor">
  <button class="btn btn--ghost btn--icon" type="button" aria-label="Edit mira.fern"><svg class="icon" aria-hidden="true" …></svg></button>
  <span class="tooltip" aria-hidden="true">Edit mira.fern</span>
</span>

Description: adds to the label

Delete (asks you first)
When the bubble says something the name does not, give it role="tooltip" and an id, and point the trigger's aria-describedby at it. It is read after the name: "Delete Autumn courtyard gathering, button, Delete (asks you first)".
HTML
<span class="tooltip-anchor">
  <button class="btn btn--ghost btn--icon" type="button"
          aria-label="Delete Autumn courtyard gathering" aria-describedby="tip-doc-delete">…</button>
  <span class="tooltip" role="tooltip" id="tip-doc-delete">Delete (asks you first)</span>
</span>

There is no keyboard-shortcut variant: the admin has no shortcuts to show.

Sizes

One size: --text-body-sm, 4 × 8px padding, up to 16rem wide; longer text wraps.

States

Hidden until its trigger is hovered or focused. Forced here with data-state="visible" on the bubble and data-state on the trigger.

Responsive behaviour

  • The bubble sits centred above its trigger at every width and wraps at 16rem, so it never runs wider than a 320px screen.
  • It does not flip or shift near the edge of the screen. Keep the words short, and do not put a tooltip on a button that touches the screen edge.
  • Phones and tablets have no hover. A tap may focus the button and show the tooltip for a moment, but nobody can rely on that, which is one more reason the button must be named without it and why a visible word is better on small screens.
  • At 400% zoom the text grows with the page and wraps inside the bubble.

Theming

The bubble is the inverse pair: --color-bg-inverse behind --color-fg-inverse. In the light theme the bubble is near-black with white text; in the dark theme it turns light grey with dark text, so it always stands apart from the page. There are no tooltip-specific tokens.

Accessibility

Role and pattern

The WAI-ARIA APG Tooltip pattern. The trigger is a real <button> named by aria-label. A tooltip that adds information has role="tooltip" and is joined to the trigger by aria-describedby; one that repeats the name is aria-hidden="true". A tooltip never takes focus and never contains a link, button or field.

Known gap: WCAG 1.4.13 asks that a pointer can move onto the tooltip without it vanishing. The stylesheet sets pointer-events: none on .tooltip, so today it hides when the pointer leaves the button. Keep tooltip text short enough to read from the button until the stylesheet is changed.

Keyboard

KeyAction
Tab / Shift+TabFocusing the trigger shows its tooltip; leaving it hides the tooltip.
EscHides the tooltip; focus stays on the button (WCAG 1.4.13, dismissible).
Enter / SpaceActivates the button as usual; the tooltip plays no part.

Focus

Focus stays on the trigger, which shows the shared 2px ring. The bubble sits above the button and never covers it or its focus ring (WCAG 2.4.11).

Labelling

Icon-only buttons rely on aria-label for their accessible name; the tooltip adds visible text and never replaces the label. Do not use the title attribute as a stand-in: it does not appear on keyboard focus or on touch, and it shows up late and small.

Motion

The bubble fades in over --duration-fast after a 300ms delay, so it does not flash while the pointer passes over a row of buttons, and disappears at once. Reduced motion zeroes the fade; the short delay stays.

Touch

Hover does not exist on touch screens, so nothing may depend on a tooltip. The trigger keeps its own 40px target; the bubble is not a target.

Content

  • Say what the button does, as a verb and its object, in sentence case and without a full stop: "Edit mira.fern", "Delete Meeting notes.pdf", "Close".
  • Use the same words as the button's aria-label, so what people see matches what a screen reader says.
  • Keep it to a few words. If it needs a sentence, it belongs in help text on the page, not in a tooltip.
  • Never put something people must know only in a tooltip, such as a warning, a rule or why a button is disabled.

Code

<span class="tooltip-anchor">
  <button class="btn btn--ghost btn--icon" type="button" aria-label="Delete mira.fern">
    <svg class="icon" aria-hidden="true" viewBox="0 0 24 24">…</svg>
  </button>
  <span class="tooltip" aria-hidden="true">Delete mira.fern</span>
</span>

<script>
  // Esc hides a visible tooltip and leaves focus where it is (WCAG 1.4.13).
  document.addEventListener('keydown', function (event) {
    if (event.key !== 'Escape') return;
    var anchor = document.activeElement && document.activeElement.closest('.tooltip-anchor');
    var tip = anchor && anchor.querySelector('.tooltip');
    if (tip) tip.hidden = true;
  });
  // Show it again the next time the button is focused or hovered.
  ['focusin', 'pointerover'].forEach(function (type) {
    document.addEventListener(type, function (event) {
      var anchor = event.target.closest && event.target.closest('.tooltip-anchor');
      if (anchor) anchor.querySelector('.tooltip').hidden = false;
    });
  });
</script>

Sources

The tooltip is a core component of the adopted system (first written for Shelfie). No admin mock has one; these are the admin screens whose icon-only buttons it is meant for:

  • pages/admin-users/default (Edit and Delete in every row)
  • pages/admin-documents/default (Delete on every document card)
  • dialogs/admin-document-viewer/default (Close)
  • dialogs/admin-document-delete/default (Close, the one named icon button)

Drift from the implemented admin

  • No tooltips and no names: the admin has no tooltips and no title attributes. Its .icon-btn buttons (Edit and Delete in Users, Delete on document cards, Close in the document viewer) have no accessible name and no visible word. Only .form-dialog__close in Delete document has aria-label="Close". The system names every icon button with aria-label and adds a tooltip with the same words.
  • Icons: the icons are Material Icons font ligatures ("edit", "delete", "close") without aria-hidden, so a screen reader may read the ligature word. The system uses inline stroke SVGs with aria-hidden="true".
  • Targets: .icon-btn is a 24px icon with 4px padding (32px). The system's icon button is 40px.
