Tabs

A row of segmented buttons that switches between sibling views of one record; the selected tab is filled with the accent colour.

WCAG 2.2 AAStatus: stableWAI-ARIA Tabs

Overview

Tabs switch between views of one record, for example the Details and Comments views of a maintenance request. Only one is active at a time and the active tab is filled with the accent colour.

  • Use tabs for two to four sibling views of the same thing. Use filter chips to narrow a list and the sidebar or bottom tab bar to move between areas.
  • In the mocks, .tab-btn is a button that loads the other view as a separate page (data-mock-href). If a tab loads a new URL it is navigation and should be a link with aria-current="page"; if it swaps a panel on the same page it is a tablist. The design system specifies the tablist form below.

Anatomy

  1. Tab listRow of tabs with --space-1 gap and a hairline rule below (.detail-tabs in the mocks). role="tablist" with a label.
  2. Tab (.tab-btn)Button, --space-2 by --space-4 padding, --radius-sm corners, --text-body-sm label.
  3. Selected tabFilled --color-accent with --color-fg-on-accent text.
  4. PanelContent for the selected tab, role="tabpanel", labelled by its tab.

Variants

One variant: segmented buttons with a filled selected tab. No underline, icon or closable tab is implemented.

Details selected. The tab list sits above the panel it controls.
HTML
<div role="tablist" aria-label="Request views" class="detail-tabs">
  <button class="tab-btn" type="button" role="tab" id="tab-details" aria-selected="true" aria-controls="panel-details">Details</button>
  <button class="tab-btn" type="button" role="tab" id="tab-comments" aria-selected="false" aria-controls="panel-comments" tabindex="-1">Comments</button>
</div>

Sizes

Tabs have one size: 14px label with 8px by 16px padding.

States

Hover and focus are forced with data-state.

DefaultHoverFocusSelected
  • Selected state is aria-selected="true"; the stylesheet also styles the mocks' .active class.
  • Hover does not change a selected tab. No disabled tab is implemented.

Responsive behaviour

  • No @media rule changes tabs. The mocks' list is a flex row; two or three short labels fit at 320px.
  • Do not wrap or scroll the tab list: keep labels short. If more tabs are ever needed, that behaviour is not implemented and must be specified first.

Theming

The product ships one light appearance; there are no theme variants.

Accessibility

Role and pattern

WAI-ARIA Tabs pattern. The mocks render plain buttons with no roles; the design system requires role="tablist" on the container, role="tab" and aria-selected on each tab, aria-controls pointing to the panel, and role="tabpanel" with aria-labelledby on the panel. This is a requirement, not current behaviour.

Keyboard

KeyAction
TabMoves focus into the tab list on the selected tab, then to the panel. Unselected tabs have tabindex="-1" (roving tabindex).
← / →Moves focus to the previous or next tab and wraps; automatic activation selects it.
Home / EndMoves to the first or last tab.
Enter, SpaceActivates the focused tab (needed only if activation is manual).

Implemented in the mocks: each button is its own tab stop and Enter or Space activates it. Arrow keys, Home and End are requirements.

Focus

Shared focus ring on :focus-visible; the mocks suppress it. The selected tab keeps the ring offset so it is visible against the fill.

Labelling

The visible label is the name. The tab list needs an aria-label ("Request views"). The selected state is conveyed by aria-selected, not colour alone.

Contrast

Label on surface
Selected label on accent
Hover background
Focus ring on surface

Motion

None: the selected fill changes instantly.

Touch

Tabs are about 36px tall (20px line plus 16px padding), above the 24px minimum, with a 4px gap. Extend the hit area on touch if tabs ever become dense.

Content

  • One word, a noun naming the view: "Details", "Comments".
  • Keep the first tab as the default view and the order stable.
  • Counts, if added, go in the label as text ("Comments (3)").

Drift

Where the mocks differ from each other or fail WCAG 2.2 AA, the design system resolves it as follows.

  • Tab buttons carry no role, aria-selected or aria-controls; the system requires the Tabs pattern.
  • Each tab loads another page in the mock, which is navigation rather than a tablist; the system treats it as a tablist when it swaps a panel on one page.
  • Selected fill is #3D8A5A with white text (4.2:1, fails AA); the system uses --color-accent.
  • Padding is 6px 16px in the mocks; the system uses --space-2 by --space-4.
  • Focus outline is removed in the mocks; the shared focus ring is applied.
