Tabs

Tabs show one part of a page at a time without leaving it: the Theme, Content or Account part of Settings, or a request's Details and Comments. Pill tabs do the same job for a list, showing all requests or only the new ones.

Overview

Use tabs when one page holds a few views of the same thing and people only need one at a time. Selecting a tab changes what shows below it; it does not go to another page.

  • Underline tabs (.tabs) split a page or panel into sections: Settings into Theme, Content and Account; a maintenance request into Details and Comments.
  • Pill tabs (.tabs--pill) filter one list: maintenance requests by status (All, New, Received, Started, Completed) and documents by kind (All documents, Notices, Bylaws, Reports).
  • Use the sidebar or tab bar to go to another section. Those are links; these are tabs.
  • Use two to five tabs. With one, there is nothing to choose; with more, people lose track, so split the page instead.
  • Do not use tabs for steps in order, such as onboarding; use the step indicator.

Anatomy

  1. Tab list.tabs with role="tablist" and an aria-label; a hairline rule underneath. Scrolls sideways if the tabs do not fit.
  2. Selected indicatorA 2px --color-accent bar under the selected tab, which also turns --color-fg-accent.
  3. Tabbutton.tabs__tab with role="tab", aria-selected and aria-controls; 44px tall, label in --text-label.
  4. Count (optional).tabs__count: a small number after the label, in a pill.
  5. Panel.tabs__panel with role="tabpanel", aria-labelledby and tabindex="0"; --space-6 above its content.

Sizes

Each variant has one size. Underline tabs are a comfortable 44px; pills are smaller because they sit in a row above a list, and stay well above the 24px minimum.

Heights: --target-comfortable and --control-height-sm; padding --space-4 and --space-3.

States

Hover and focus are forced with data-state; selected and disabled use the real aria-selected="true" and disabled.

Both themes

  • Selected: exactly one tab per list. Underline tabs turn accent with a 2px bar; pills fill with --color-accent-subtle and take an accent border, so the state never depends on colour alone.
  • Disabled: avoid it. If a view cannot be shown, leave the tab out or explain inside its panel. When one is unavoidable, use disabled (or aria-disabled="true" to keep it focusable and explain why).
  • Empty panel: a filter with no matches shows the list's own empty state ("No completed requests"), never an empty tab.
  • Loading: when a filter fetches its list, the panel shows a spinner and the selected tab does not change back.

Responsive behaviour

  • Underline tabs stay on one row at every width. If they do not fit (with large text or 400% zoom), the tab list scrolls sideways inside itself; the page never scrolls sideways. Labels never wrap or truncate.
  • Pill tabs wrap onto as many rows as they need, with --space-2 between pills, so all filters stay visible on a 320px screen.
  • The panel is full width at every size; its content follows its own layout rules.
  • No breakpoint changes the tabs. At 320px "Theme", "Content" and "Account" fit on one row; so do "Details" and "Comments".

Theming

Tabs read --color-fg-muted for unselected labels, --color-bg-subtle on hover, --color-fg-accent and an --color-accent bar when selected, and --color-border-default for the rule under the list. Pills add a --color-border-strong outline on --color-bg-surface, and fill with --color-accent-subtle when selected. Counts read --color-fg-muted on --color-bg-subtle. The dark theme swaps only those semantic tokens.

Accessibility

Role and pattern

The APG Tabs pattern with manual activation: arrow keys move focus between tabs, and Enter or Space selects one. Manual activation means a filter does not reload the list each time focus passes over a pill, and nobody loses their place in Settings by pressing an arrow key. Tabs are <button role="tab"> in a role="tablist" with an aria-label; each points at its panel with aria-controls, and the panel has role="tabpanel" and aria-labelledby. All pill tabs in a filter control the same list panel.

Keyboard

KeyAction
TabMoves into the tab list onto the selected tab, then on into the panel. Only the selected tab is in the Tab order (tabindex="-1" on the others).
← / →Moves focus to the previous or next tab, wrapping at the ends. Does not select.
Home / EndMoves focus to the first or last tab.
Enter, SpaceSelects the focused tab and shows its panel.

The live examples on this page are static: every tab is reachable with Tab and the arrow keys do nothing. The code samples show the roving tabindex the product uses.

Focus

The shared 2px --color-focus-ring. On underline tabs the ring is drawn inside the tab (negative offset) so the scrolling tab list does not clip it; on pills it sits outside. Focus stays on the tab after selecting; it does not jump into the panel.

Labelling

The tab list is named for what it switches ("Settings", "Filter requests by status"). Each tab's visible word is its name. A count has an aria-label that says what it counts ("1 comment"), so the tab reads "Comments, 1 comment, tab, selected".

Disabled tabs use --color-fg-disabled, which is exempt from contrast minimums (WCAG 1.4.3) and is one reason to avoid disabled tabs.

Motion

Label colour and background fade over --duration-fast. The indicator does not slide between tabs. Reduced motion zeroes the fade. Panels swap instantly.

Touch

Underline tabs are 44px tall (--target-comfortable) with 16px side padding. Pills are 36px tall (--control-height-sm) with 8px between them, above the 24px minimum with room to spare.

Content

  • One or two words per tab, in sentence case: "Theme", "Comments", "All documents", "Bylaws".
  • Name the view, not an action: "Comments", not "View comments".
  • Filter pills use the same words as the status badges they filter: New, Received, Started, Completed. Put "All" first.
  • Counts are plain numbers; leave the count off rather than show "0".
  • The panel's heading can repeat the tab name with more detail ("Theme customisation"), but the tab itself stays short.

Drift from the implemented admin

  • Four styles for one control: Settings uses .tabs .tab.active .tab-content (bordered boxes, 10px radius); a request uses .detail-tabs .tab-btn.active (borderless, 8px radius); Maintenance filters use .filters .filter-btn.active and Documents filters .filter-tabs .filter-btn.active (20px-radius pills). Every selected state is a solid green fill with white text. The system has one underline style and one pill style.
  • No tab semantics: all four are plain <button>s with an .active class: no role="tab", aria-selected, aria-pressed or labelled panel, and no arrow-key support. The system uses the APG Tabs pattern with manual activation.
  • Wording: Documents filters read "All Documents" and "By-Laws", and the Settings panels are titled "Theme Customization", "Content Management" and "Account Settings". The system uses sentence case, "Bylaws" and "customisation".
  • Sizes: the admin's tabs are about 30 to 36px tall with 14px Outfit labels. The system's underline tabs are 44px and pills 36px.
  • Theme: the admin is light only. The system adds the dark theme.
  • No admin tab shows a count today; .tabs__count is available for when one is wanted.
