Radio group

Pick one from a short list when seeing every option helps the choice. Native radios in a fieldset, each with a full-width label. A core component: no admin screen uses radios today.

Overview

A radio group is a <fieldset> with a <legend> and two to four <label class="choice"> rows. Each row wraps its <input type="radio"> and a .choice__text, which can carry a one-line description in <small>.

The Coop admin has no radios. Every pick-one choice in the implemented admin is a select: Role, Type, Status, Priority, Category and Scope. The radio group stays in the system as a core component so that a short choice has a ready, accessible form when a screen needs one. The examples on this page reuse option sets from those selects and from Roles & Privileges so the copy is real; they do not describe screens that exist.

Use a radio group when the options are few (two to four), known and mutually exclusive, and comparing them helps the choice, for example when each needs a short description. Use a select for five or more options or when space is tight, a checkbox for a yes-or-no choice, and a switch for an on-or-off setting that takes effect at once.

Anatomy

  1. LegendNames the group; --text-label, or --text-h4 when the fieldset is a card.
  2. Radio--size-icon-md circle, appearance: none, hairline --color-border-strong; filled --color-accent with a --space-2 dot when checked.
  3. Label text.choice__text; the whole row is the click target.
  4. Description (optional)<small> in --color-fg-muted.

Variants

The same rows sit either on their own, inside a dialog's form, or in a fieldset that is itself a card on a settings page.

Plain

Priority
A bare fieldset with a label-sized legend, using the four maintenance priorities in their natural order.
HTML
<fieldset><legend>Priority</legend>
  <label class="choice"><input type="radio" name="priority" value="Low"><span class="choice__text">Low</span></label>
  <label class="choice"><input type="radio" name="priority" value="Medium" checked><span class="choice__text">Medium</span></label>
  <label class="choice"><input type="radio" name="priority" value="High"><span class="choice__text">High</span></label>
  <label class="choice"><input type="radio" name="priority" value="Urgent"><span class="choice__text">Urgent</span></label>
</fieldset>

As a card, with descriptions

Status

You can change this later from Documents.

fieldset.card: the legend sits at the top of the card, and help is joined to the fieldset with aria-describedby. The options are the two document statuses.
HTML
<fieldset class="card stack" aria-describedby="status-help">
  <legend style="font: var(--text-h4); margin-bottom: var(--space-2);">Status</legend>
  <p class="field__help" id="status-help">You can change this later from Documents.</p>
  <label class="choice"><input type="radio" name="status" value="Draft" checked>
    <span class="choice__text">Draft<small>Not shown to members yet</small></span></label>
  <label class="choice"><input type="radio" name="status" value="Published">
    <span class="choice__text">Published<small>Shows on the home page and the members' documents page</small></span></label>
</fieldset>

There is no horizontal variant. Options side by side break apart at 320px and at 400% zoom, and are harder to scan; rows always stack.

Sizes

One size: a 20px radio (--size-icon-md) in a row at least --target-min tall.

States

Hover and focus are forced on the input with data-state; checked, invalid and disabled use the real attributes.

Both themes

Priority
Priority
  • Disabled is the saving state: every radio in the form is disabled while it saves, and the label text turns --color-fg-disabled.
  • Invalid only happens when a required group starts with nothing checked and is sent that way. Prefer a sensible default so it never happens; if it does, mark every radio aria-invalid="true" and put a .field__error under the group.

Responsive behaviour

  • Rows always stack, one option per line, at every width.
  • Label and description wrap under the text start, not under the radio, because the row is a flex container with the radio aligned to the top.
  • In a dialog that becomes a bottom sheet under 640px, the group keeps its layout and stays full width.

Theming

The radio reads --color-bg-surface and --color-border-strong unchecked, --color-fg-muted for the hover edge, --color-accent and --color-fg-on-accent checked, and --color-bg-subtle with --color-border-default disabled. In dark the checked fill becomes the light violet and the dot turns dark, so the checked mark keeps its contrast.

Accessibility

Role and pattern

Native radios in a fieldset and legend, which give the WAI-ARIA APG Radio Group behaviour for free. All radios in a group share one name, and each has its own value.

Keyboard

KeyAction
Tab / Shift+TabMoves into the group, landing on the checked radio, and out again. The group is one tab stop.
↓ / →Checks the next option, wrapping to the first.
↑ / ←Checks the previous option, wrapping to the last.
SpaceChecks the focused option if it is not already checked.

Focus

The shared ring is drawn around the circle on :focus-visible. Arrow keys move focus and selection together, so the ring is always on the checked option.

Labelling

The legend names the group ("Status", "Priority") and is read on entry. The label text names each option, and its <small> description is part of the label. Help for the whole group goes on the fieldset with aria-describedby.

Contrast

Motion

Fill and edge colours fade over --duration-fast; reduced motion sets it to zero.

Touch

The whole row is the label, at least --target-min (24px) tall with --space-1 above and below, and as wide as the fieldset.

Content

  • The legend is a short noun or a question: "Status", "How soon should someone come?"
  • Options are parallel and short, in sentence case: "Draft", "Published". Put the safest or most common option first and check it.
  • Add a description only when the option needs one: "Published" says where the document will appear.
  • Option text is plain words; keep system names in the value.
  • No full stop at the end of an option.

Sources

No admin mock contains type="radio". The option sets in the examples come from the admin selects in:

  • dialogs/admin-document-create/default (Status: Draft, Published)
  • dialogs/admin-maintenance-create/default (Priority: Low, Medium, High, Urgent)
  • pages/admin-roles/default (the five roles)

Drift from the implemented admin

  • Not used. The admin has no radio groups and no styles for them; every pick-one choice is a select. The system keeps the radio group as a core component and does not ask any admin screen to change.
  • Grouping. Where the admin groups controls it uses a <label> with no for, never a fieldset and legend. Any radio group the admin adds should use a real legend.
  • Look. If the admin drew radios today they would be browser radios in green Outfit forms. The system's radio is a 20px violet .choice that follows both themes.
