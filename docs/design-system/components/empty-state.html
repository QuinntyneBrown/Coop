Empty state

What a list shows when there is nothing in it: a round icon, a short heading, one plain sentence, and the one thing to do next. Nobody should be left wondering whether the page is broken.

WCAG 2.2 AAStatus: stableComposition

Overview

Use an empty state in place of a list, table or panel that has nothing to show: the Assets library before the first upload, a Users search with no match, the Messages panel before a conversation is chosen. It always says why it is empty and, where there is one, offers the way forward.

  • First use (.empty): nothing has been added yet, and that is fine. Accent icon and the main action ("Upload a file", "New document").
  • No results (.empty): a search or filter matched nothing. Repeat what was searched and offer Clear search.
  • Nothing selected (.empty, compact): a panel waiting for a choice, such as the chat panel in Messages.
  • Error (.empty.empty--error): a region that did not load. Danger icon and Try again. A short banner alert above the list also works; the admin uses one on Board, Pages and Website.

Whole-page problems (page not found, no access, server error, offline) are an error page. A failed action, as opposed to a failed load, is an alert or a toast.

Anatomy

  1. Icon.empty__icon: 64px circle in --color-accent-subtle (--color-danger-bg for errors) around a 24px stroke icon, aria-hidden.
  2. Heading.empty__title: a real heading (an <h2> under the page <h1>) in the h3 style; says what is, or is not, here.
  3. Text.empty__text: one or two sentences, muted, 36 characters wide at most.
  4. Actions.empty__actions: one primary action, optionally one secondary. Omit when there is nothing to do.

The layout stays the same; the icon, words and action change with the reason the list is empty.

Sizes

Full (48px above and below, 24px at the sides) replaces a whole list or table. Compact (24px and 16px) sits in a panel or a dashboard card, and may drop the icon and the action when space is short.

  • Retrying: Try again becomes a busy button (aria-busy="true"); on success the real list replaces the whole block.
  • No results clears itself: when the search is cleared, the list comes back.
  • Examples here use <h3> because this page already has its headings; in the admin the heading is an <h2> under the page's <h1>.

Responsive behaviour

  • Centred at every width, inside the card or panel the list would fill.
  • Text stops at 36 characters wide so it never runs the width of a desktop, and wraps freely at 320px and at 400% zoom.
  • Two actions sit side by side and wrap, centred, when they do not fit.
  • In Messages on phones, the list and the chat panel show one at a time, so the "Choose a conversation" state only appears on wider screens.

Theming

The icon reads --color-accent-subtle with --color-fg-accent; the error icon --color-danger-bg with --color-danger-fg. Heading and text read --color-fg-default and --color-fg-muted on whatever surface holds them (a card or the page). All are theme tokens; nothing in the component changes between themes.

Accessibility

Role and pattern

Plain content: a heading, a paragraph and native buttons or links. No ARIA widget pattern. When a search returns nothing, the result count ("0 users") is announced through the page's role="status" region; the empty block itself is not a live region.

Keyboard

KeyAction
TabMoves to the primary action, then the secondary.
Enter (and Space on buttons)Runs the action.

Focus

Focus does not jump to the empty state. After Clear search, focus returns to the search field. After Try again fails, focus stays on the button.

Labelling

The icon is decorative. The heading is a real heading, so it shows in the heading list. "Try again" and "Clear search" are <button>s (they act); "Upload a file" and "New conversation" may be links when they open a dialog route, or buttons when they open a dialog in place.

Content

  • Heading says what is here in plain words: "No documents yet", "No maintenance requests", "Choose a conversation". Avoid "found" and "data".
  • For no results, repeat the search: "No users match “tavi.m”". Never reuse the first-use message ("No assets uploaded yet") for a search with no match.
  • Text says what the list is for or what to try: "When a member reports a problem, such as a kitchen tap leak, it appears here."
  • The action uses the same words as the page's main button, in sentence case: "Add user", "New document", "Upload a file", "New conversation".
  • Errors never blame the person using the admin: "Nothing has been lost. Check your connection and try again."

Drift from the implemented admin

  • Users: "No users found" is a .empty-row cell spanning the table, under "Showing 0-0 of 0 users", with no heading and no action. The system replaces the table with an .empty block.
  • Documents, Maintenance, Assets: .empty-state.card holds a 48px Material Icons glyph and one muted paragraph ("No documents found", "No maintenance requests found", "No assets uploaded yet"), with no heading and no action. The system adds an <h2>, a reason and the page's main action.
  • No results: on Users, Documents, Maintenance, Assets and Messages the no-results capture is identical to the empty one; the search term is not repeated and there is no Clear search. Assets even says "No assets uploaded yet" after a search. The system has a separate no-results variant.
  • Messages: two empty states show at once ("No conversations yet" and "Select a conversation to start chatting"), and the button that opens New Conversation is an icon-only "add" with no accessible name. The system gives the chat panel a compact "Choose a conversation" state with a named New conversation action.
  • Look: implemented empty states use 40px or 48px × 20px padding, muted text in the green-and-Outfit palette, and icon-font glyphs with no circle. The system uses the 64px accent circle, stroke SVG icons and token spacing.
  • Already aligned: the hand-written Board and Pages empty states (.board-empty, .pages-empty) already follow the formula: icon, <h2>, sentence, primary action.
  • CSS gap: components.css has no compact modifier, so compact padding is set inline with tokens.
