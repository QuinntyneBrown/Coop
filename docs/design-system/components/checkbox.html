Checkbox

A yes-or-no choice that is saved when the form is sent: "Remember me" when signing in, agreeing to the terms when registering, sending a new notice to members. A native checkbox in a full-width label.

WCAG 2.2 AAStatus: stableNative <input type="checkbox">

Overview

A checkbox is a <label class="checkbox"> that wraps an <input type="checkbox"> and a .checkbox__text. The text can carry a one-line description in <small>. Because the label wraps the input, the whole row is the click target.

The admin has three checkboxes, each saved with its form:

  • Remember me on Sign in.
  • I agree to the terms and conditions on Create account, which must be ticked.
  • Also send to members by email and text in the New Document dialog, shown when a Notice is Published, with a one-line hint.

Roles & Privileges also draws its access rights (Read, Write, Create, Delete) as checkboxes today, but each one saves the moment it is clicked. A choice that takes effect at once is a switch; that is how the system draws the privilege grid.

Use a checkbox when the person can say yes or no and nothing happens until they press the form's button. Group related checkboxes in a <fieldset> with a <legend>. To pick exactly one of a few options, use a radio group or a select.

Anatomy

  1. Box--size-icon-md square, appearance: none, --radius-sm, hairline --color-border-strong. Checked: --color-accent fill with a --color-fg-on-accent tick.
  2. Label.checkbox__text in --text-body; clicking it ticks the box.
  3. Description (optional)<small> in --color-fg-muted, one short line.

Variants

Single

One choice with a short label. On Sign in it sits on a row with the "Forgot password?" link.

Forgot password?
Sign in: the checkbox and the link share a row, and wrap onto two lines when there is no room.
HTML
<div class="cluster cluster--between">
  <label class="checkbox"><input type="checkbox" name="remember" value="1">
    <span class="checkbox__text">Remember me</span></label>
  <a href="/forgot-password">Forgot password?</a>
</div>

With a description

Add a <small> line when the label needs one more fact to decide. New Document uses it to say who will receive the notice.

New Document, when the type is Notice and the status is Published. It starts unticked.
HTML
<label class="checkbox"><input type="checkbox" name="send" value="1">
  <span class="checkbox__text">Also send to members by email and text
    <small>Only members who asked for new notices on their profile get one.</small></span></label>

Required

A box that must be ticked before the form can be sent. It carries required, and a .field__error below it when it was left empty.

Tick this box to agree to the terms and conditions.
Create account, after pressing the button with the box empty.
HTML
<div class="field">
  <label class="checkbox"><input type="checkbox" name="terms" value="1" required
      aria-invalid="true" aria-describedby="terms-error">
    <span class="checkbox__text">I agree to the terms and conditions</span></label>
  <div class="field__error" id="terms-error">Tick this box to agree to the terms and conditions.</div>
</div>

Group in a fieldset, with an indeterminate "all" box

Related choices that are saved together go in a <fieldset> whose <legend> asks the question. An "all" box can tick or clear the whole group; when only some are ticked it shows a dash (indeterminate). No admin form has a checkbox group today. This example reuses the four access rights to show the shape, with a Member's maintenance request rights (Read and Create) as the data; on Roles & Privileges itself these rights save at once and are switches.

What can members do with maintenance requests?
Two of four ticked, so "All four" is indeterminate. The four rights are indented by --space-8 under it.
HTML
<fieldset><legend>What can members do with maintenance requests?</legend>
  <label class="checkbox"><input type="checkbox" id="maint-all" aria-controls="maint-rights">
    <span class="checkbox__text">All four</span></label>
  <div id="maint-rights" style="padding-left: var(--space-8);">
    <label class="checkbox"><input type="checkbox" name="maint" value="Read" checked><span class="checkbox__text">Read</span></label>
    …
  </div>
</fieldset>
<script>
  // Indeterminate is a property, not an attribute: set it from script.
  document.getElementById('maint-all').indeterminate = true;
</script>

Sizes

One size: a 20px box (--size-icon-md) in a row at least --target-min tall.

States

Hover, focus and indeterminate are forced on the input with data-state; checked, invalid and disabled use the real attributes.

ValueDefaultHoverFocusInvalidDisabled
Unchecked
Checked Not used
Indeterminate As checked As checked Not used Not used

Both themes

  • Invalid only applies to a required box left empty. The edge turns --color-danger-solid and a .field__error below says what to do.
  • Disabled is the saving state: while Sign in or New Document is sending, the checkbox is disabled so it cannot change under the request, and the label turns --color-fg-disabled.
  • Indeterminate only appears on an "all" box. Pressing it ticks every box in the group; pressing again clears them.

Responsive behaviour

  • Each checkbox is its own row at every width; a group never sits side by side.
  • A long label wraps under its own first word, not under the box, because the row is a flex container with the box aligned to the top.
  • On Sign in, the "Remember me" and "Forgot password?" row is a wrapping .cluster, so at 320px or 400% zoom the link drops below the checkbox instead of overflowing.

Theming

The box reads --color-bg-surface and --color-border-strong when empty, --color-fg-muted for the hover edge, --color-accent with a --color-fg-on-accent tick or dash when checked or indeterminate, and --color-bg-subtle with --color-border-default when disabled. In dark the fill becomes the light violet and the tick turns dark, so the mark keeps its contrast.

Accessibility

Role and pattern

Native <input type="checkbox">, which gives the WAI-ARIA APG Checkbox pattern: dual-state for a single box, tri-state for an "all" box. Its mixed state comes from the indeterminate property, which the browser announces as "mixed" or "partially checked".

Keyboard

KeyAction
Tab / Shift+TabMoves to the next or previous checkbox. Each box is its own tab stop; disabled ones are skipped.
SpaceTicks or clears the focused box. On an indeterminate "all" box, ticks every box in the group.
EnterDoes not tick. In a form it submits, as the browser does.

Focus

The shared ring is drawn around the 20px box on :focus-visible, offset by --focus-ring-offset. After a failed submit, focus goes to the error summary, whose link leads back to the box.

Labelling

The wrapping label names the box; no aria-label is needed. The <small> description is part of that name, so keep it to one line. A group's legend names the question and is read when focus enters the group. An error joins with aria-describedby, and the box gets aria-invalid="true" while it shows.

Motion

Fill and edge colours fade over --duration-fast; reduced motion sets it to zero. The tick does not animate.

Touch

The whole label row is the target: at least --target-min (24px) tall with --space-1 above and below, and as wide as the text. Clicking the words ticks the box.

Content

  • Write the label as what will be true when it is ticked: "Remember me", "Also send to members by email and text".
  • Sentence case, no full stop: "I agree to the terms and conditions", not "I agree to the Terms and Conditions".
  • Never use a negative label ("Don't send"): ticking a box to say no is confusing.
  • An error says what to do: "Tick this box to agree to the terms and conditions." It does not say "You must".
  • When a person is asked to agree to something, put a link to it next to the box, outside the label.

Sources

Extracted from these admin mocks:

  • pages/admin-login/default, invalid, submitting and error (Remember me)
  • pages/admin-register/default, invalid, mismatch, submitting and error (terms, required, with error)
  • dialogs/admin-document-create/send, busy and send-error (send to members, with hint, disabled while saving)
  • pages/admin-roles/default and member (privilege checkboxes, drawn as switches by the system)

Drift from the implemented admin

  • Look. The admin draws browser checkboxes tinted green with accent-color: 24px in .checkbox-label on Sign in and Create account, 22px in .notice-send, 28px in .privilege-toggle. The system draws one 20px box with appearance: none, a --radius-sm corner, a violet fill and a token tick, in both themes.
  • Row height. The admin's .checkbox-label and .notice-send rows are at least 44px tall with 14px or 15px text. The system's .checkbox row is at least --target-min (24px) with 16px text: larger words, smaller row.
  • Errors. On Create account the terms error is a separate .error-message ("You must accept the terms and conditions") that is not joined to the box, and the box has no aria-invalid. The system joins it with aria-describedby and rewrites it as an instruction.
  • Terms. The label says "Terms and Conditions" in title case, and the page never links to them. The system uses sentence case and asks for a link beside the box.
  • Saving. While Sign in submits, "Remember me" stays enabled. New Document does disable its checkbox while saving, which is the system's rule for both.
  • Hint. New Document keeps its hint outside the label and joins it with aria-describedby, which is also accessible. The system puts a one-line hint inside the label as <small>, so the whole row is the target.
  • Privileges. The .privilege-toggle boxes are named privilege-read, privilege-write and so on, the same in every row, and save the moment they change. The system draws them as switches named by their row and column.
  • Focus. .notice-send draws a 3px green outline; the other admin checkboxes rely on the browser default. The system uses the shared 2px --color-focus-ring everywhere.
