Filter chips

Pill-shaped toggle buttons in a row that narrow a list by category, with the pressed chip filled with the accent colour.

WCAG 2.2 AAStatus: stableToggle <button>

Overview

Filter chips are pill-shaped buttons in a row that narrow a list by category: all documents, notices, by-laws, reports. The pressed chip is filled with the accent colour.

  • Two class names exist for the same look: .filter-btn (admin) and .filter-tab (public). Both are documented here; new work uses .filter-btn.
  • Use chips to change what a list shows. Use tabs to switch between different views of one record.
  • In the mocks each chip loads a separate state page of the list (data-mock-href); the app swaps list content.

Anatomy

  1. Group (.filter-tabs)Flex row with --space-2 gap. Admin wraps; public scrolls horizontally (overflow-x: auto).
  2. Chip (.filter-btn / .filter-tab)Pill (--radius-full), 1px --color-border-strong edge, --space-2 by --space-4 padding, no wrapping.
  3. Pressed chipAccent fill and edge with --color-fg-on-accent label.

Variants

One look in two class names. The mocks' public chips use a rounder 12px corner and a muted label; the design system unifies both on the pill shape.

A single-select group: exactly one chip is pressed at a time.
HTML
<div role="group" aria-label="Filter documents" class="filter-tabs"><button class="filter-btn" type="button" aria-pressed="true">All Documents</button><button class="filter-btn" type="button" aria-pressed="false">Notices</button><button class="filter-btn" type="button" aria-pressed="false">By-Laws</button><button class="filter-btn" type="button" aria-pressed="false">Reports</button></div>

Public .filter-tab in a scrolling row

The row scrolls sideways when the chips do not fit, so no chip wraps or truncates.

Sizes

Chips have one size: 14px label with 8px by 16px padding.

States

Hover and focus are forced with data-state.

DefaultHoverFocusPressed
  • Hover changes the edge to --color-accent. The pressed chip does not change on hover.
  • Pressed is aria-pressed="true"; the stylesheet also styles the mocks' .active class.
  • No disabled or loading chip is implemented.

Responsive behaviour

  • The public group has overflow-x: auto, so it scrolls sideways instead of wrapping. The admin group wraps (flex-wrap: wrap).
  • Admin maintenance and documents add a rule at 768px and narrower for the surrounding toolbar; the chips themselves do not change.
  • Chips never shrink: white-space: nowrap. A scrolling row must remain reachable by keyboard, which it is because each chip is focusable.

Theming

The product ships one light appearance; there are no theme variants.

Accessibility

Role and pattern

Native <button type="button"> with aria-pressed: a toggle button. Wrap the row in role="group" with an aria-label. This is the design-system requirement; the mocks use plain buttons with an .active class and no aria-pressed. If the chips are mutually exclusive and replace the whole view, a tablist is the other valid pattern, not both.

Keyboard

KeyAction
Tab / Shift+TabEach chip is a tab stop.
Enter, SpacePresses the chip; in a single-select group, sets it pressed and unsets the others.

Focus

Shared focus ring on :focus-visible. A scrolling row scrolls the focused chip into view.

Labelling

The label is the name. Pressed state is announced by aria-pressed, not colour. Announce the result of filtering in a polite live region ("4 documents").

Contrast

Label on surface

Motion

Edge and background colour change over --duration-base; reduced-motion tokens remove the transition.

Touch

Chips are about 38px tall with an 8px gap, above the 24px minimum.

Content

  • Labels are the category name: "All Documents", "Notices", "By-Laws", "Reports"; one to three words.
  • The first chip is "All" and is pressed by default.
  • Do not put counts or icons in the label; none are implemented.

Drift

Where the mocks differ from each other or fail WCAG 2.2 AA, the design system resolves it as follows.

  • Two class names (.filter-btn and .filter-tab) style the same control; the shared stylesheet keeps both.
  • Admin chips are pills (20px radius, light edge) and public chips use a 12px radius with a muted label; the system uses the pill and --color-fg-default.
  • Chip edge is the light divider colour (1.2:1); the system uses --color-border-strong (3:1) for the control edge.
  • Pressed fill is #3D8A5A with white text (4.2:1, fails AA); the system uses --color-accent.
  • Pressed state is an .active class with no aria-pressed and no group label; both are required.
  • Admin wraps and public scrolls sideways; both are kept as implemented.
