Card

A raised surface that holds one thing the co-op looks after: a maintenance request, a document, a page of the website, a director on the board. The card names its subject in a heading; anything you can do with it is a real link or button inside.

Overview

Use a card when each item on a screen has its own name, a few facts and its own actions, and people look at one item at a time. The Coop admin has seven kinds, all built from the same .card:

  • Request card (Maintenance): the request's title as a link, a status badge, the description and when it was reported.
  • Document card (Documents): a type icon, the title as a link, the type and date, a Draft or Published badge and a Delete icon button.
  • Asset card (Assets): a file icon, the file name as a link, its size and upload date.
  • Page card (Pages): the page title, its web address, "Open on the website", and Edit and Remove buttons.
  • Director card (Board): a photo or initials avatar, the name and role, and Move up, Move down, Edit and Remove.
  • Block card (Website): the block's name, a one-line summary of what it says, and Edit.
  • Profile card (Profiles): a profile's name and type; the one in use carries an "Active" badge.

A card is never the button itself. When a card opens something, its title is a real link; other actions are buttons beside it. Do not use a card when people compare the same facts down a column (use a table), for a single dashboard count (use a metric card), or for a short list of one-line rows (use a list).

.card--success and .card--warning, the tinted surfaces, remain in the stylesheet, but no admin screen uses them yet.

Anatomy

  1. Surface--color-bg-surface through --card-bg, hairline --color-border-default, --radius-lg, --shadow-1, --space-6 padding.
  2. Title.card__title (--text-h4) on a real heading. When the card opens something, the heading holds the link.
  3. Status (optional)A badge with a word: New, Received, Started, Completed, Draft, Published, Active.
  4. BodyOne or two short lines in --text-body. A .stack spaces the parts.
  5. Meta and actionsDates and sizes in .text-caption; buttons in a .cluster that wraps.

Variants

The variants differ in what the card holds, not in the surface. Pick by what people do with the item: open it (title link), change it (buttons), or both.

Sizes

One padding (--space-6), or none with .card--flush. A card's width comes from the layout it sits in.

Responsive behaviour

  • Phones: every card is full width and cards stack with --space-3 to --space-4 between them.
  • Collections of small cards (requests, documents, assets) sit in .grid--auto, which fits as many 18rem columns as the width allows and falls back to one column.
  • Inside a card, .cluster wraps: the badge drops under the title and the director's four buttons wrap onto two rows rather than shrinking.
  • Padding stays --space-6 at every width. Long titles and web addresses wrap; nothing is cut off.
  • At 400% zoom (320 CSS px) each card is one column of title, facts and buttons, with no sideways scrolling.

Theming

The card reads one component token, --card-bg (default --color-bg-surface), plus --color-border-default, --radius-lg and --shadow-1. In the dark theme the surface lifts above the canvas, the shadow deepens and the hairline keeps the edge visible. Re-point --card-bg to restyle a card; do not add a new class for a colour.

.card { --card-bg: var(--color-bg-surface); }

Accessibility

Role and pattern

No ARIA widget pattern: a card is content. Use <article aria-labelledby> for a self-contained item (a request, a document, a director) inside a <ul> or <ol> when there are several, and <section aria-labelledby> when the card is a named region of the page. The board list is an <ol> because its order is what the home page shows.

Keyboard

KeyAction
Tab / Shift+TabMoves through the title link and the buttons inside each card, in reading order. The card itself is not a tab stop.
EnterFollows the title link or activates the focused button.
SpaceActivates the focused button.

Focus

The shared 2px --color-focus-ring appears on the link or button, never around the whole card. After Move up or Move down, focus stays on the moved director's button in its new place. After Remove, focus goes to the next card, or to the page heading if none is left.

Labelling

The heading names the card through aria-labelledby. Repeated buttons ("Edit", "Remove", "Move up") carry the item's name in visually hidden text so a list of controls reads "Edit About us", "Remove Rosalind Achebe". Keep the visible word at the start of the name (WCAG 2.5.3). The type icon is aria-hidden; the type is also written out ("Notice"). Status is a word in a badge, never colour alone.

Contrast

Title and body on card
Meta text on card
Title link on card
Type icon on its circle
Focus ring on card

The card's edge (hairline on canvas) is decorative and need not reach 3:1; the heading and spacing mark where one card ends.

Motion

None. Links and buttons change colour over --duration-fast, which reduced motion zeroes.

Touch

Buttons in a card are at least 40px tall with 12px between them, above the 24px minimum. The title link is the whole heading line. Nothing depends on hover.

Content

  • The title is the item's own name, as a person would say it: "Kitchen tap leak", "Autumn courtyard gathering", "About us", "Rosalind Achebe".
  • One status word in sentence case: New, Received, Started, Completed; Draft, Published; Active.
  • Meta lines are short and use the system's dates: "Notice · Tue 13 Oct", "2 KB · uploaded Tue 13 Oct".
  • Button words are plain verbs: Edit, Remove, Move up, Move down. "Open on the website" says where the link goes.
  • Summaries on block cards show the block's own first words, cut after two lines, so staff recognise the block.

Sources

The look comes from the adopted system (first written for Shelfie); the content and the seven card kinds come from these admin mocks:

  • pages/admin-maintenance/default, empty, loading (request cards)
  • pages/admin-documents/default, notices (document cards)
  • pages/admin-assets/default (asset cards)
  • pages/admin-pages/default (page cards)
  • pages/admin-board/default (director cards)
  • pages/admin-website/default (block cards)
  • pages/admin-profiles/default and pages/admin-profile/default (profile cards)

Drift from the implemented admin

  • Look: the admin's .card is white with a 12px radius (14px on some screens), 20px padding and a faint shadow, in green and Outfit. The system uses --color-bg-surface, --radius-lg, --space-6 and --shadow-1, in violet and the system's rounded fonts, light and dark.
  • Repeated card styles: .page-card, .director-card and .block-card do not use .card; each repeats its own background, border, radius and shadow in feature CSS. In the system they are all .card with .stack and .cluster inside.
  • Clickable cards: .request-card, .document-card and .asset-card are <div role="link" tabindex="0"> with a click handler and no href. The system makes the title a real <a href>.
  • Control inside a control: the document card's .icon-btn.delete-doc-btn sits inside the role="link" card and has no accessible name (only the Material Icons ligature "delete"). The system puts a named Delete button beside the link.
  • Profile cards: .profile-card.selected marks the profile in use with a green left border and tint; the cards have a pointer cursor and hover colour but are plain <div>s a keyboard cannot reach. The system uses an "Active" badge and aria-current="true"; choosing a profile, if it is an action, belongs on a real button.
  • Hover: the document card's border turns green on hover. Cards have no hover in the system; links and buttons do.
  • Statuses: request cards show four statuses (New, Received, Started, Completed), with Received in a grey badge. This page uses the same words.
  • Labels in the name: page and director buttons use aria-label="Edit About us". That passes 2.5.3 because the visible word comes first; the system prefers visually hidden text so the name survives translation tools.
  • Icons: type icons (campaign, gavel, assessment, insert_drive_file) are Material Icons font ligatures without aria-hidden, so screen readers can read the ligature word. The system uses inline stroke SVGs with aria-hidden="true" and writes the type out.
