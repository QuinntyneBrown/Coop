Component · Containers

Card

A card is a white, bordered, rounded surface that groups one subject: a notice, a form, a table, a maintenance request. Two variants are selectable (the request and document cards), and the quick-action tile is a small related surface.

Overview

The card is the product's one container. Pages are a stack of cards on the canvas background; dialogs and tables are cards too (.modal-content.card, .table-card).

  • Static card (.card) holds content that is read or edited in place: a notice, a settings form, a profile.
  • Interactive card (.card-interactive) is a whole summary that opens a detail view: the request card on the maintenance page and the document card on the documents page.
  • Quick-action tile (.quick-action-btn) is a small subtle tile with an icon above a label, used for dashboard shortcuts.

Use a list item for dense, repeating one-line rows, and a metric card for a single number.

Anatomy

  1. Container.card: --color-bg-surface fill, 1px --color-border-default edge, --radius-lg corners, --space-5 padding.
  2. Header (optional).card-header: title left, status or action right, separated from the body by a hairline. Set the container padding to zero when a header or body is used.
  3. TitleAn h3 in --text-h3. Choose the heading level for the page outline.
  4. Body.card-body: paragraphs in --text-body-sm, muted.
  5. Meta line (optional).card-meta: date or type in --text-caption, muted.

Sizes

The implemented card has no size variants.

States

Only the interactive card and the quick-action tile have states. The static card never changes. Hover and focus are forced here with data-state; real pages use :hover and :focus-visible.

  • Hover (interactive card): edge becomes --color-accent and --shadow-2 appears, over --duration-base. (Tile) the fill steps from --color-bg-subtle to --color-bg-subtle-hover.
  • Selected: edge --color-accent plus a 2px --shadow-selected halo. The mock used a .selected class only; the design system sets aria-current="true" so assistive technology hears the state. .selected is kept as an alias.
  • Disabled, loading and error states are not implemented for cards.

Responsive behaviour

  • The card is fluid: it fills its container and has no breakpoint of its own.
  • The documents page lays document cards in a grid that becomes one column at max-width: 640px (the only card-related @media rule in the mocks).
  • The dashboard's metric cards become one column at max-width: 768px; see metric card.
  • Padding does not change on phones: --space-5 (20px) container, --space-4 (16px) for interactive cards.

Theming

Card colours come from semantic tokens only, so a future theme would not require changes to this component.

Accessibility

Role and pattern

A static card is a generic container with no role; give it an <article> or <section> only when it is a standalone, titled unit. An interactive card follows the "card" convention: one real <a href> inside the title is the control, and the rest of the card is a larger pointer target for the same link. The mocks used <div role="link" tabindex="0"> with no key handler. That is a requirement gap: the design system requires a native link.

Keyboard

KeyAction
Tab / Shift+TabMoves to the card's title link. A card has one tab stop.
EnterFollows the title link (required; the mock's role="link" div did not respond to it).
SpaceNo action on a link.

Focus

The shared focus ring (2px --color-focus-ring, 2px offset) shows on the title link and on the quick-action tile. The mocks removed the outline on cards; the design system restores it.

Labelling

The card is named by its title heading. Selection is exposed with aria-current="true". Decorative icons are aria-hidden; the tile's accessible name is its visible label. Meta text (type, date) must stay in the reading order after the body.

The default card edge (--color-border-default) is decorative; the card is identified by its content and surface, not by the border.

Motion

Edge colour and shadow transition over --duration-base (200 ms). There is no movement or scaling.

Touch

An interactive card is far larger than 44px. The quick-action tile is 16px padded around a 24px icon and a label, about 74px tall.

Content

  • Titles are short noun phrases: "Courtyard lighting", not "There is a problem with the lighting".
  • Body text is one or two sentences. Long text belongs in the detail dialog the card opens.
  • Meta shows type and date in that order, separated by a middle dot. Dates use the same format throughout a page.
  • Quick-action labels are verb phrases or destinations of one to three words, in title case as the mocks have them ("New Maintenance").

Drift

  • Request and document cards were div role="link" tabindex="0" with no Enter or Space handling; the system requires a native link in the title.
  • Hover differed: request cards on the maintenance page changed the edge, on the messaging page the shadow. The system applies both (--color-accent edge and --shadow-2).
  • Selected used only a .selected class; the system adds aria-current="true".
  • Card radius was 14px or 16px and padding 16px, 20px or 24px per screen; the system uses --radius-lg and --space-5 (--space-4 when interactive).
  • The document card's coloured top bar (.card-color-bar) is only in the documents mock and is not part of this system's card.
  • The mocks removed the focus outline from cards; the shared focus ring is restored.
