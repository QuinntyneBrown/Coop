Badge

Badges state a status or priority in one word. Five variants carry the meaning; the word always carries it too.

Overview

A badge is a small pill that states a status or priority in one word: request status, document status, user status, invitation status and priority. It is read-only and sits beside the thing it describes.

  • Colour supports the word, never replaces it; every badge carries text.
  • Five variants map to meaning: success, info, warning, danger and gray.
  • The mocks also contain .status-badge, .priority-badge and .active-badge; the design system unifies them into .badge (mapping in Variants).

Anatomy

  1. ContainerInline pill, --radius-full, padding --space-0-5 by --space-3, tinted background.
  2. LabelOne word, --text-caption (12px) at medium weight, never wraps.

Variants

Pick the variant by meaning. The unmodified .badge is a neutral subtle fill and is not used by the mocks on its own.

Sizes

The mocks use one badge size (12px text, 2-3px by 8-10px padding), so the design system has one size. Do not add sizes.

States

A badge is read-only. It has no hover, focus, active or disabled state and is not a button. Status changes by replacing the badge with the next variant.

Responsive behaviour

No breakpoint rules apply to the badge. It is inline-flex with white-space: nowrap, so a row that is too narrow wraps the badge to the next line as a whole rather than breaking its label.

Theming

The product ships one light appearance; there are no theme variants. Each variant reads a matching foreground and background token pair.

Accessibility

Role and pattern

Plain inline text in a <span>; no role. No WAI-ARIA widget pattern applies. The text carries the meaning so colour is never the only signal (WCAG 1.4.1). The badge is not announced as a live change.

Keyboard

KeyAction
Not applicableThe component takes no focus and has no key handling.

Focus

None.

Labelling

Place the badge next to the item's name, in reading order ("Leaking tap" then "Started"). If the badge sits in a table cell, the column header gives it context.

Content

  • One word in sentence case ("Completed", "Draft"). The mocks capitalise statuses with CSS in one place; write the word in the right case instead.
  • Use the same word for the same state everywhere: "New", "Received", "Started", "Completed" for requests.
  • Do not put counts in a status badge.

Drift

  • Mocks: .status-badge, .priority-badge and .active-badge duplicate .badge with different radii (10 to 12px against 20px) and padding. Unified into .badge.
  • Mocks: .status-badge.new is green while .badge-warning is used for New elsewhere. Resolved to warning.
  • Mocks: priority "low" is indigo, which has no semantic token. Resolved to info.
  • Mocks: .active-badge is 11px; the system uses the 12px badge size.
