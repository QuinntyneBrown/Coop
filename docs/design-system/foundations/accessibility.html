Accessibility

WCAG 2.2 AA in both themes, built for older eyes and hands: 44px controls, one clear focus ring, words beside every icon, plain-language errors and no time pressure.

Overview

OWN Housing Co-op is home to retired, older women, and the staff and board members who run it through the admin are often older too. Some read with reading glasses or zoom the browser, some have shaky hands or arthritis, some use a screen reader or a magnifier, and some came to computers late in life. Accessible is therefore the baseline, not an extra. The system commits to WCAG 2.2 level AA in both themes. This page lists the commitments, the tokens that enforce them, how each component page proves them, and, plainly, what has not been checked yet.

Designing for an older audience

  • Big targets. Every button, field, link in the sidebar, tab and page number is at least 44px tall. Small hands and steady hands both hit it first time.
  • Strong contrast. Body and secondary text reach 4.5:1 or more on every surface, and field edges reach 3:1, because contrast sensitivity drops with age.
  • Words with icons. An icon never stands alone in navigation; "Maintenance" is always written next to the wrench.
  • One thing at a time. One primary action per screen, dialogs for editing, and nothing that moves on its own.
  • Forgiving. Errors say what to do, nothing is lost on a failed save, and removing anything asks first and says what it removes.
  • Zoom friendly. Every screen works at 400% zoom with nothing cut off; see Reflow and zoom.

Targets and controls

2
Control heights sm 36px, md 44px, lg 52px; the icon button is 44px square. The count badge is the smallest element at 24px (--target-min) and is not a target on its own.
  • 44px is the default (--control-height-md = --target-comfortable): buttons, fields, selects, sidebar links, tabs, page numbers, the tab bar.
  • 36px small controls (--control-height-sm) only in dense rows (Move up, Move down, Edit, Remove on the Board and Pages lists) with 8px or more between them.
  • 52px large controls (--control-height-lg) for the one action on sign-in and onboarding screens.
  • Checkboxes and switches draw a 20px box but the whole label is the target, so the hit area is the full row.

Focus

The ring is an outline, not a shadow, so it survives forced-colours mode (where it becomes Highlight). Text fields draw it with no offset and also colour their border, so the ring hugs the field. Tabs draw it inside their edge so it is not clipped by the scrolling tab row.

Type size: an open question

The type scale is kept as adopted: body text is 16px (--font-size-md), secondary text and table cells 14px (--font-size-sm) and captions and badges 12px (--font-size-xs). That passes WCAG, which sets no minimum size, and it already makes body text larger than the implemented admin, where most text is 14px.

For an older audience it may still be small. Raising body text to 18px and secondary text to 16px would help many readers but would make tables and the sidebar longer and would change every component. This is a deliberate choice, recorded as an open question for the co-op to decide, ideally after watching staff use the admin. Until then:

  • Never set body text, labels or field values below 16px.
  • Use 14px only for metadata that repeats something visible elsewhere (dates in a list, file sizes, "Showing 1–2 of 4 users").
  • Use 12px only for badges and captions, never for anything a person must read to finish a task.
  • Every size is in rem, so a person who sets a larger default font in the browser gets larger text everywhere.

Component contract

Every component page's Accessibility section answers the same seven questions:

  1. Role and pattern: the native element or WAI-ARIA Authoring Practices pattern used.
  2. Keyboard: a table of keys and what they do.
  3. Focus: where focus starts, where it goes on close, how the ring looks.
  4. Labelling: what is labelled, how, and what is announced.
  5. Contrast: the token pairs involved, measured live in both themes.
  6. Motion: what moves and what happens under reduced motion.
  7. Touch: target sizes and the alternative to any hover.

Testing and what is not verified

Checked

  • check_contrast.py passes every pair in contrast-pairs.json in both themes.
  • check_design_system.py checks these pages for labels, accessible names, alt text, one <h1>, landmarks, links and raw colours.

Not verified yet

  • No screen-reader pass has been done. Nobody has yet used NVDA, JAWS or VoiceOver on the system's dialog, form, table, tabs or sidebar. The ARIA patterns are documented, not proven.
  • No forced-colours check has been done. The forced-colors: active rules exist in tokens.css and components.css, but no one has looked at the components in Windows High Contrast.
  • Nothing here has been tried by the co-op's own staff or board members.

How to test

  • Tab through every example on a component page; nothing is skipped and nothing traps.
  • Use a screen reader on one dialog (Remove page), one form (New page) and one table (Users).
  • Zoom to 200% and 400%; emulate prefers-reduced-motion, prefers-contrast: more and forced-colors: active in Chrome DevTools.
  • Playwright acceptance tests assert accessible names and roles through page objects, in Chromium.

Sources and drift

The commitments follow the project rule that the whole site meets WCAG 2.2 AA for retirees and works at 400% zoom. Evidence comes from pages/admin-users/default, pages/admin-roles/default, pages/admin-login/invalid, pages/admin-change-password/invalid, dialogs/admin-page-editor/invalid, dialogs/admin-asset-delete/default and dialogs/admin-page-remove/default.

Drift from the implemented admin

  • Focus: 18 rules in the admin's styles set outline: none. Form fields replace it with a faint green glow at 10% opacity, which does not reach 3:1. The system never removes the outline.
  • Targets: .icon-btn is about 32px (4px padding around a 24px glyph) and a sidebar .nav-item about 41px (14px text with 10px padding). The tab bar's .tab-item already has min-height: 44px. The system makes every control 44px.
  • Type: most admin text is 14px. The system's body is 16px; going larger is the open question above.
  • Labels: search fields (.search-input) have no visible label, only aria-label and a placeholder ("Search users..."). Privilege toggles (.privilege-toggle) are named "privilege-read", "privilege-write" and so on, without the record type.
  • Icons: Material Icons ligatures are mostly not hidden, so screen readers read "build" before "Maintenance"; the document and user edit and delete buttons have no name except that ligature.
  • Errors: the Pages, Board and Website editors use aria-invalid, aria-describedby and an error summary. The sign-in, register, change-password and profile forms show .field-error text without aria-invalid or aria-describedby.
  • Dialogs: the newer editors use <dialog> or role="dialog" with aria-modal. Older ones (.modal-overlay .modal-content, such as delete asset and add user) have no dialog role.
  • Confirmation: "Confirm Delete · Are you sure you want to delete this asset?" does not name the asset. "Remove “Our garden”?" does, and is the model.
