Accessibility

Overview

The design system targets WCAG 2.2 level AA. Every component page answers the same questions (pattern, keyboard, focus, labelling, contrast, motion, touch) and the checkers in .claude/skills/extracting-design-systems/scripts/ enforce the mechanical parts. The implemented mocks fall short of this in several places; those are listed under Known gaps and written as requirements the system sets, not as behaviour that exists today.

Commitments

The commitments below are trimmed to what applies to Coop's components: forms, navigation, dialogs, lists and tables, notices. Charts, media players, carousels and auto-dismissing toasts do not exist in the product and have no rules here.

Perceivable

RequirementSCRule in this system
Text contrast1.4.3Body, label and secondary text at least 4.5:1 on every surface it sits on; large text at least 3:1. Pairs are declared in tokens/contrast-pairs.json and shown live on each component page.
Non-text contrast1.4.11Input borders, the focus ring and meaningful icons at least 3:1 against adjacent colours. Card edges and dividers are decorative and exempt.
Use of colour1.4.1Status is colour plus text (badges say "Completed", errors say what is wrong). Invalid fields show message text as well as a red border.
Reflow, resize, spacing1.4.10, 1.4.4, 1.4.12Sizes in rem; layouts reflow to 320px; nothing breaks with increased text spacing.
Images and icons1.1.1Decorative icons are aria-hidden="true"; icon-only controls have aria-label. See Iconography.
Motion2.3.3Durations are tokens and are shortened under prefers-reduced-motion. See Motion.

Focus indicator

Every interactive element shows the same indicator on :focus-visible: a solid ring of --color-focus-ring, --focus-ring-width thick, offset --focus-ring-offset from the element. It is defined once in components.css for links, buttons, inputs, selects, textareas, summary and anything with tabindex. Components must not remove it or draw their own.

  • Under forced-colors: active the ring becomes the system Highlight colour.
  • The mocks remove the browser outline (outline: none in 23 declarations) and only change a form input's border to brand green, with a faint green halo on some. A one-pixel border change is not a sufficient indicator; the system requires the ring on inputs as well.
  • The ring must not be clipped by overflow: hidden on a parent; leave room or move the overflow.

The mocks' brand green gives a white label only about 4.2:1, which fails AA, so the system uses a darker accent for actions and keeps the brand green for marks. Disabled controls are exempt from contrast (WCAG 1.4.3) but must not rely on colour alone.

Testing procedure

  1. Run python .claude/skills/extracting-design-systems/scripts/check_design_system.py docs/design-system for labels, names, alt text, landmarks, headings and links, and the contrast script for every declared pair.
  2. Tab through every page from the top. Check the skip link is first, order matches the visual order, every stop shows the ring, and nothing is a trap.
  3. Open one dialog, one form with errors and one table with a screen reader. Confirm names, roles, error announcements and focus return.
  4. Zoom to 200% and 400%, and resize to 320px wide. Confirm no horizontal scrolling and no clipped content.
  5. Emulate prefers-reduced-motion, prefers-contrast: more and forced-colors.
  6. Check phone targets are at least 24px, and primary actions 44px.

Known gaps in the implemented mocks

The mocks capture the shipped UI as it is. These gaps are documented in docs/mocks/README.md and docs/mocks/verification.md. The design system does not copy them; each one is a requirement.

Gap in the implemented mocksRequirement the design system sets
Dialogs have no focus trap, the page behind is not inert and Escape does not generally dismiss them. No mock uses role="dialog" or aria-modal.Dialogs use role="dialog" (or alertdialog for confirmations) with aria-modal="true" and a name from their heading. Focus moves into the dialog on open, Tab is trapped, the background is inert, Escape closes, and focus returns to the trigger. See Dialog and Dialogs pattern.
Some controls are unnamed (icon-only buttons such as notifications, menu, close, send) and some labels are not associated with their inputs. The review copy added labels that the source lacks.Every control has an accessible name; every input has a programmatically associated visible label. Icon-only buttons use aria-label.
The admin dashboard renders two h1 elements (page title and greeting); some screens have no h1 or no main landmark.Exactly one h1 and one main per page, headings in order.
The focus outline is removed on form controls and replaced with a border colour change.The shared focus ring applies everywhere; see Focus indicator.
No mock uses aria-invalid, aria-describedby or autocomplete. Several fields show only a red border when touched and invalid, with no message.Invalid fields set aria-invalid="true", show message text and link it with aria-describedby. Identity fields declare autocomplete.
No live regions exist. Success text appears without announcement, and some saves report success even after the API failed.Success and error notices use role="status" or role="alert", and report the true outcome. See Alert and Feedback pattern.
Admin screens overflow horizontally on phones (77 mocks, up to 673px on a 360px screen).No horizontal page scroll at 320px; wide tables scroll inside their own container.
Some controls do nothing (asset Download, Edit Description) or hide failures (failed uploads close the dialog silently).Do not present a control as available unless it works; show failures as errors.
Inline editing forms expand in place on the profile pages.Button-triggered editing opens a dialog or a separate screen (project convention), with focus managed.

Usage

  • Start from native elements. Reach for ARIA only to add what HTML cannot express, and follow the pattern named on the component page.
  • Write the accessible name first when building a component, then style it.
  • Keep --target-min (24px) as the floor for any new control; do not make a smaller one.
  • Never rely on hover or colour alone to convey state.
