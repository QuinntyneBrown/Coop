Iconography

Material Icons ligatures in four sizes, a small inline SVG set in the public shell, and the rules for labelling both.

WCAG 2.2 AALight appearance only
  • Overview

  • Icon catalog

Overview

Coop uses the Material Icons font (filled style, ligature names such as build), bundled locally so the product works offline. The public app also draws a small set of inline SVG icons in its shell. Nothing else (no icon sprite, no icon set from another family, no image icons) is used. Every ligature below appears in the mocks.

Icons are rendered with <span class="material-icons">name</span>. The font family is --font-family-icon; the size comes from the component-level --icon-size property, which defaults to 24px.

Sizes

Four sizes exist, set through modifier classes in components.css. Choose the size by the component that hosts the icon, not by taste.

Icons inherit the colour of the text around them (currentColor), so they take the hover, active and disabled colours of their control. Meaningful state is never carried by icon colour alone.

Inline SVG icons

The public app does not use the Material Icons font in its shell. It draws 24-unit outline icons as inline SVG: viewBox="0 0 24 24", fill="none", stroke="currentColor", stroke-width="2". They render at 24px in the top bar, tab bar and metric tiles, 20px in sidebar links, and the brand mark is a 28px rounded square with a letter.

The two icon systems draw the same destinations differently: the admin app shows build for Requests, the public app a wrench outline; admin description against a public page outline. Both are listed here because both ship. A consolidated set is a future decision, not a rule of this system.

Accessibility and labelling

  • Decorative icons (the icon sits beside a visible text label) carry aria-hidden="true". This is the default for icons in nav items, tab items, and buttons that also show text.
  • Icon-only buttons and links need an accessible name: aria-label on the button, never on the icon. Use the action, not the glyph: "Notifications", "Open menu", "Delete document".
  • Meaningful stand-alone icons (a status shown without text) either get a visually hidden text alternative or are replaced by text.
  • Material Icons are ligatures: if the font fails to load, the ligature name is shown as text. Always keep aria-hidden="true" so assistive technology does not read "inbox" before the real label.
  • Icons that carry meaning must reach 3:1 contrast against their background (WCAG 1.4.11). The brand green and the accent colour both pass on white; see Accessibility.
  • Icon-only buttons meet the 24px minimum target through the 2.5rem (40px) icon button.
Icon-only button named with aria-label; icon plus text with the glyph hidden.

Usage

  • Use only the ligatures listed in the catalog. Adding an icon means adding it to the catalog first.
  • Pick the size modifier from the host component (search bar 18, nav item 20, default 24, empty state 48). Do not size icons with ad hoc font-size.
  • Do not colour icons independently of their text, except the semantic tiles (.icon-tile-success, .icon-tile-info, .icon-tile-warning).

Drift

  • The mocks set icon sizes in pixels (font-size: 24px, hero icons 80px on phones). The system exposes four sizes through --icon-size.
  • Several icon-only controls in the mocks have no accessible name. The system requires one; see Known gaps.

Tokens

This page owns no tokens. Icon size is a component-level property (--icon-size on .material-icons) and the icon font is --font-family-icon, which Typography lists.
