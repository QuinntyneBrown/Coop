Foundation

Layout

Three breakpoints, one 260px sidebar, a 1440px top-bar container and three dialog widths. That is all the layout system the product implements.

Overview

Coop has no grid system. The mocks lay pages out with flexbox and CSS grid directly, with a small set of fixed dimensions: three breakpoints, one sidebar width, one top-bar container width and three dialog widths. This page documents exactly those, and the page shells that use them. It does not define a column grid, gutters or margins, because the implemented product has none.

  • Breakpoints are 640, 768 and 1024 CSS pixels. Rules mix max-width and min-width; see Responsive for what changes at each.
  • Spacing between and inside elements comes from the 4px-based spacing scale, not from layout tokens.
  • The product is light only and has a single set of layouts for both apps; the admin app and the public app use different shells.

Page shells

Four shells exist. Diagrams are schematic; the live strips below them use the real .top-bar and .bottom-tab-bar component classes.

Admin shell: fixed sidebar and main

The admin layout (.layout) is a flex row. The sidebar is position: fixed, 260px wide, full height, and the main area (.layout-main) sits beside it with margin-left: 260px on the canvas colour. At 768px and below the sidebar is hidden and the margin is removed; navigation moves to the bottom tab bar (.mobile-only wrapper). The sidebar stacks above content at --z-sticky.

Public shell: top bar, content, tab bar

The public layout (app-layout) is a flex column at 100vh. The top bar is sticky (--z-sticky) and its inner row is centred and capped at the container width, with 12px by 16px padding. Main content scrolls and reserves 72px at the bottom so the fixed bottom tab bar never covers it. From 1024px a 260px fixed sidebar appears, the main content gets margin-left: 260px and the 72px reserve is removed.

Auth pages: login, register, forgot password

Sign-in and registration pages have no sidebar or top bar. A branded header panel sits above a form body (.login-body, .register-body, .form-container) that is centred, full width up to 400px, with 32px by 24px padding. In the admin app at 768px and below the page becomes a column, the login header is hidden and the form panel gets extra bottom padding (80px) to clear the tab bar.

Dialog widths

Dialogs are a fixed overlay (.modal-overlay) at --z-modal, centring one panel on a half-black backdrop with 16px of overlay padding so the panel never touches the viewport edge. The panel is width: 100% up to one of three maximum widths, scrolls inside when taller than 90% of the viewport, and uses 32px padding. The mocks do not change dialog layout at any breakpoint.

Usage

  • Use var(--layout-sidebar-width) for the sidebar width and the main content offset so the two cannot drift apart.
  • Use var(--layout-container-max) for the public top-bar inner row only. Other content columns keep the per-screen caps above.
  • Use the three dialog tokens through the .modal-md and .modal-lg modifiers rather than writing a new max-width.
  • CSS custom properties cannot be used inside @media conditions. Write the breakpoint value (40rem, 48rem, 64rem) in the query and keep it in step with the token.
  • Reserve space for the fixed bottom tab bar (72px in the mocks) wherever it is shown, and respect the bottom safe area; see Responsive.

Resolutions where the mocks disagree

  • The admin asset delete confirmation renders at 500px in the mocks. The design system sets confirmations to the 400px size.
  • Breakpoints are written as max-width: 768px in most rules and min-width: 1024px or max-width: 1023px in others, so 768px itself and the 1023px to 1024px boundary are treated unevenly. The system names the tokens at 640, 768 and 1024 and expects new rules to use min-width.
