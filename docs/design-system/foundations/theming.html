Theming

Light and dark are the same components reading the same token names; a theme is a block of semantic overrides applied with data-theme or the device setting.

Overview

The Coop admin system ships a light and a dark theme. Both are the same components reading the same token names; only the semantic colour and shadow values change. With no setting, the admin follows the device: someone who has set their tablet or computer to dark mode gets the dark theme, and everyone else gets light. Both themes pass WCAG 2.2 AA for every pair in contrast-pairs.json.

How a theme applies

MechanismWhat it does
:rootLight values; the default.
[data-theme="dark"]Dark values on any element and everything inside it. Set on <html> to force dark.
[data-theme="light"]Light values, even inside a dark page or on a dark device. Set on <html> to force light.
@media (prefers-color-scheme: dark) on :root:not([data-theme="light"])Follow the device: dark when the device is dark, unless light has been forced.
color-scheme: light | darkSet inside each theme so scrollbars, native form controls (the native <select> list, date pickers) and the default canvas match.
@media (prefers-contrast: more)Decorative borders become strong; muted and subtle text become default.
@media (forced-colors: active)The focus ring and borders hand over to system colours; buttons, fields, cards and badges draw a CanvasText border.
 
<!-- Follow the device: no attribute -->
<html lang="en">

<!-- Force one theme -->
<html lang="en" data-theme="dark">
<html lang="en" data-theme="light">

Set the attribute before first paint so there is no flash of the wrong theme. The admin has no appearance setting of its own today, so "follow the device" is the behaviour this system documents. These docs and the mocks also accept ?theme=dark and the t key to preview.

Token tiers

TierExamplesWho reads itChanges per theme?
1 · Primitives--palette-violet-600, --palette-gray-900, --font-size-mdOnly semantic tokensNo
2 · Semantic--color-accent, --text-body, --space-4, --radius-md, --shadow-1Components and pagesColour and shadow do
3 · Component--btn-bg, --field-border, --alert-icon, --sidebar-bg, --avatar-sizeOne component; declared in components.cssNo; they alias semantic tokens

A theme overrides tier 2. A one-off re-skin of a single component overrides tier 3 in a scoped selector. Nothing outside tokens.css names a tier 1 token.

Adding a theme

  1. Copy the [data-theme="dark"] block in tokens/tokens.css and rename the selector, for example [data-theme="high-contrast"].
  2. Point each --color-* token at a palette step. Add a new ramp under Primitives if the theme needs a hue the palette does not have; never put a raw value in the theme block.
  3. Set color-scheme and, for a dark-based theme, --shadow-color and the four shadows.
  4. Run python .claude/skills/extracting-design-systems/scripts/check_contrast.py docs/design-system/tokens/tokens.css; every pair in contrast-pairs.json must pass in the new theme.
  5. Regenerate tokens.json (below) and add the theme to the docs' theme previews.

Adding a theme is a design decision for the whole admin, not a per-user preference. It needs a requirement and a mock before anyone builds it.

Consuming tokens.json

tokens/tokens.json is a DTCG export of tokens.css for tools that cannot read CSS (design tools, tests). Each token has $type, $value (an alias such as {palette.violet.600} or a raw value) and, under $extensions["com.agent-toolkit"], its CSS name, the resolved value and any theme overrides.

"accent": {
  "$type": "color",
  "$value": "{palette.violet.600}",
  "$extensions": {
    "com.agent-toolkit": {
      "css": "--color-accent",
      "themes": { "dark": { "$value": "{palette.violet.300}" } }
    }
  }
}
  • tokens.css is the source of truth; regenerate the JSON with python .claude/skills/extracting-design-systems/scripts/tokens_to_json.py docs/design-system/tokens/tokens.css after every change and never edit it by hand.
  • In the Angular admin, import tokens.css once in the global styles and read tokens with var(); components never import the JSON.
  • Playwright tests that need a value read it with getComputedStyle, so they follow the active theme.

The website theme in Settings

The admin's Settings screen has a "Theme" tab ("Theme Customization": Scope, Primary Color, Background Color, Accent Color, Text Color, Reset to Default, Save Theme). That tab edits the colours of the public website that members and visitors see. It is website content that staff manage, like the pages and the board list. It does not change this design system or the admin's own colours, and the admin's light and dark themes do not read it.

Keep the two apart: a co-op can choose its website colours without touching the admin, and the admin keeps tested contrast whatever the website uses. When documenting the Settings screen, show the tab's controls with the system's components (select, text field, button) and treat its colour values as data, not tokens.

Do and don't

  • Do check both themes for every new colour pair; don't assume a pair that passes in light passes in dark.
  • Do let prefers-reduced-motion, prefers-contrast and forced-colors adjust tokens; don't override them per component.

Tokens

This page owns no tokens. Colour tokens are on Color, shadows on Elevation, layout tokens on Layout, motion on Motion, and the interaction tokens (targets, control heights, focus ring) on Accessibility.

Sources and drift

The theming model and both themes are adopted from the Shelfie design system. The Settings theme tab is in pages/admin-settings/default and notifications/admin-theme-saved/success.

Drift from the implemented admin

  • The implemented admin is light only: it has no dark theme, no data-theme attribute, no prefers-color-scheme rule and no color-scheme declaration. The system adds a dark theme that follows the device.
  • Colours in the implemented admin are hard-coded in each component's styles (green for primary buttons, a warm grey canvas, warm grey borders) rather than read from tokens, so a theme cannot switch them. The system reads every colour from tokens.css.
  • The co-op logo in the sidebar uses its own fixed palette. The system draws the logo mark with accent tokens so it follows the theme.
  • The Settings "Theme" tab is titled "Theme Customization" and says "Choose the colours for the app", which suggests it changes the admin. It changes the public website. The label is content drift, recorded on Content.
