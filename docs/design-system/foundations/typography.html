Overview

The admin uses the system’s rounded face (SF Pro Rounded on Apple devices, Nunito or the platform UI font elsewhere): friendly, clear at small sizes, and free to load. One family does headings and body text; a monospace face is only for invitation tokens and code. Sizes come from a fixed scale in rem, so text grows with the browser’s font setting and with zoom.

  • Set text with a role (font: var(--text-body)), not with loose sizes and weights.
  • The scale is kept as-is from the Shelfie design system, by choice: 16px body text, 14px labels, buttons and table cells, 12px captions and badges.
  • Headings use text-wrap: balance; paragraphs use text-wrap: pretty and stop at the measure.

Open question: size for older eyes

Is this scale large enough for the people who use the admin?The co-op is home to retired, older women, and many of the staff and board members who run it are older too. The scale was adopted unchanged from the source system, where it was tuned for a different audience. It has not been tested with Coop admin users.
  • What is decided: the scale stays exactly as it is for now (16px body, 14px labels and table cells, 12px captions). No token value changes until the question below is answered.
  • What is open: whether body text should be 18px (--font-size-lg) and whether 12px should be used at all. The implemented admin never sets text smaller than 14px; this system’s badges, captions and phone tab-bar labels are 12px, which is smaller than what the admin shows today.
  • Why it is safe to wait: every size is in rem, so anyone who sets a larger default font size or zooms to 400% gets larger text with no loss of content (WCAG 1.4.4 and 1.4.10).
  • How to answer it: watch co-op staff and board members use the admin on their own devices, at their usual zoom, before changing --font-size-*. A change is a token change only; components read roles, not pixel sizes.

Measure and responsive type

  • Measure: paragraphs stop at --layout-measure (65 characters). Empty-state text stops at 36 characters so “No maintenance requests found” and its sentence read as one or two short lines.
  • Fixed steps, no viewport units. Type does not scale with the window, so browser zoom and the user’s font size always win. The one responsive change is the dialog title, which is --text-h4 on a phone sheet and --text-h3 from 640px.
  • Numbers that change in place (metric-card counts, pagination, the unread count badge, “Showing 1–2 of 4 users”) use font-variant-numeric: tabular-nums so they do not jitter.
  • Long text wraps. Request titles, document names and usernames wrap; they truncate with an ellipsis and a title only in one-line table cells (.table td.truncate) and the sidebar user name.

Usage

  • One <h1> per page and headings in order; pick the role for its look and the element for its level (a card title is an <h2> with .card__title).
  • Write headings, labels and buttons in sentence case: “Recent maintenance requests”, “New request”, “Send invitation”.
  • Uppercase only through --text-overline with --letter-spacing-wide; never type copy in capitals.
  • Do not set font sizes in px or add steps between the scale’s steps. If a size is missing, the design is asking for a new role; raise it.

Accessibility

  • Resize text (1.4.4) and reflow (1.4.10): all sizes are rem; every admin screen works at 200% text size and at 400% zoom (a 320 CSS px viewport) with no loss of content and no sideways scrolling.
  • Text spacing (1.4.12): nothing clips when line height is 1.5×, paragraph spacing 2×, letter spacing 0.12em and word spacing 0.16em; containers grow instead of fixing heights.
  • Contrast: body and label text use default or muted colour (4.5:1 or more); large text (24px, or 18.7px bold) may use 3:1 but none currently needs to.
  • Minimum size: 12px is for captions and badges only, never for something a person has to act on. Whether 12px belongs in the admin at all is the open question above.

Drift from the implemented admin

The mocks are captures of the running Angular admin, which does not use this system yet. Each difference below is drift: the system value is the one to build to.

  • Family. The admin loads Outfit as a web font (fonts.css) for everything, including buttons and fields. The system uses the rounded system stack and downloads no font.
  • Sizes. Almost every piece of admin text is 14px: labels, buttons, badges, table cells, secondary lines and phone tab labels. Nothing is smaller than 14px. The system keeps the source scale (16px body, 14px labels and table cells, 12px captions and badges), so badges, captions and tab labels become smaller than today. This is recorded as an open question, not resolved.
  • Headings. The admin’s page title is 24px semibold (the dashboard “Hello, Mira” and list titles) and card titles are about 18px. The system’s h1 is 36px bold and card titles are h4 (20px semibold).
  • Weights. The admin uses 500, 600 and 700 with no rule for which is which. The system ties weight to role.
  • Line height. Most admin text uses the browser default line height; a few blocks set 1.6. The system sets line height in every role.
  • Case. Admin headings, buttons and metric labels are in Title Case (“Recent Maintenance Requests”, “Open Requests”, “New Request”). The system writes them in sentence case.
  • Badges. Admin badges are 14px medium in mixed case. The system’s badges are 12px semibold uppercase overlines.
