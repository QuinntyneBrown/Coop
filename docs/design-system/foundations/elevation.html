Foundation · Elevation

Elevation

Four shadow levels, a matching surface ladder and a fixed z-order, so the tab bar, dialogs and toasts always stack the same way in both themes.

Overview

Elevation tells a person what sits on top of what. The admin uses four shadow levels and a matching set of surface colours: the page canvas, cards and the sidebar on it, raised surfaces (menus and dialogs) above them, and the inverse toast on top. Stacking order is fixed by --z-* tokens so a dialog always sits over the tab bar and a toast is never hidden behind a dialog.

  • Pair each shadow with its surface token; a raised surface is never just a darker shadow on a card colour.
  • Use the z-index tokens; never type a number.

Shadow levels

--shadow-1 · cards, metric cards
--shadow-2 · hovered metric card
--shadow-3 · menus, toasts
--shadow-4 · dialogs
--shadow-focus · focus halo
--shadow-1 · cards, metric cards
--shadow-2 · hovered metric card
--shadow-3 · menus, toasts
--shadow-4 · dialogs
--shadow-focus · focus halo

Shadows are built from --shadow-color (an RGB triplet) at increasing opacity. The dark theme sets the triplet to pure darkness and raises the opacities, because a soft grey shadow disappears on a dark canvas.

Z-order

TokenValueUsed by
--z-baseNormal flow
--z-raisedAn element lifted above its siblings
--z-stickyThe sidebar (from 768px) and the phone tab bar
--z-dropdownMenus
--z-overlayDialog backdrop
--z-modalDialog
--z-popoverReserved in the order; no admin component uses it
--z-toastToast region, above a dialog so a confirmation shows as the dialog closes
--z-tooltipTooltips on icon buttons; the skip link

The tab bar sits at --z-sticky, far below the dialog backdrop, so an open dialog always sits over it. Only one layer holds each job; a dialog never opens another dialog.

Elevation in the dark theme

  • Higher surfaces get lighter: canvas gray 950, surface gray 900, raised gray 800. The colour step does the work a shadow cannot.
  • Shadows stay, darker and more opaque, so edges still read on bright screens.
  • The inverse toast flips to a light surface, which is why its status icons have their own tokens.
  • The backdrop darkens to 65% so the dialog stands clear of the page.

Usage

  • Cards sit at level 1. Do not raise a card to level 2 to make it “important”; use a status alert or the page order instead.
  • Only one modal at a time; a dialog never opens another dialog.
  • Hover lifts are for things that take you somewhere (a metric card that links to its list), not for static cards.

Drift from the implemented admin

The mocks are captures of the running Angular admin, which does not use this system yet. Each difference below is drift: the system value is the one to build to.

  • One faint shadow. Admin cards and metric cards share a single very soft shadow (black at 3% opacity, 2px down, 8px blur) that barely shows on the warm canvas. The system has four levels, each paired with a surface.
  • Z-index numbers. The sidebar is 100, the tab bar 1000, every .modal-overlay 1000 and .modal-overlay--top (the document viewer) 1001. The tab bar and dialogs share a layer. The system uses --z-sticky, --z-overlay and --z-modal.
  • Backdrop. The admin scrim is black at 50% in its only theme. The system uses --color-bg-backdrop, which deepens in the dark theme.
  • Saved messages. The admin shows “saved” messages as inline alerts with screen-specific classes (.board-alert, .pages-alert, .website-alert, .notice-alert, .alert-success) at page level, with no layer of their own. The system’s toast has --z-toast and --shadow-3; which messages become toasts is decided in the notifications pattern.
  • No dark theme. The admin is light only, so elevation is never shown by surface colour. The system’s dark theme lightens raised surfaces.
