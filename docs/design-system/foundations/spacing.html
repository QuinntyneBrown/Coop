Spacing

One 4px scale for every gap and padding, with a simple rule: space inside a group is smaller than the space between groups.

Overview

Every gap, padding and margin in the admin comes from one scale on a 4px base, written in rem so it grows with the user’s font size. The scale skips steps on purpose (no 28px, no 36px) so neighbouring choices are clearly different. Generous space between groups helps people who read slowly or use a magnifier see where one thing ends and the next begins.

  • Use --space-* for padding, gaps and margins; never type a pixel value.
  • Inside is smaller than between: the space inside a group is always less than the space separating groups.
  • Spacing never changes with the viewport except page margins and grid gutters, which are layout tokens.

Usage

  • Reach for the layout primitives first: .stack (vertical, --space-4), .cluster (wrapping row, --space-3), .grid (the column grid). Override their gap with a token when a group needs to be tighter.
  • Use gap on the container rather than margins on each item; it collapses cleanly when an item is missing.
  • Do not add a step between steps. If 16px feels too loose and 12px too tight, the group is wrong, not the scale.
  • Inline style in a page may only nudge layout with a token (style="gap: var(--space-6);"), never a raw length.

Drift from the implemented admin

The mocks are captures of the running Angular admin, which does not use this system yet. Each difference below is drift: the system value is the one to build to.

  • Off-grid values. The admin uses 6px, 10px and 14px throughout: sidebar links are padded 10 × 14px, fields 10 × 14px, the logo and user row have 10px gaps, labels sit 6px above fields and metric cards have a 14px gap. The system snaps every value to the 4px scale.
  • Margins instead of gaps. .form-group adds 16px below every field and admin cards add 24px below themselves, so the last item in a group carries stray space. The system uses gap on .stack, .field and .cluster.
  • Dialog padding. .modal-content is padded 32px on every side at every width, which eats a phone screen. The system pads dialogs 24px (--space-6) and turns them into bottom sheets on phones.
  • Page padding. The dashboard content is padded 24 × 20px and capped at 800px; other screens pick their own padding (16px to 40px). The system takes page margins from --layout-margin.
