Foundation

Color

Warm neutrals, one accent green and four status colours, arranged as primitives and semantic roles. Every text and non-text pairing is checked against WCAG 2.2 AA.

WCAG 2.2 AALight appearance onlyTokens: --palette-*, --color-*

Overview

Coop is a warm neutral surface with one brand green. Colour is defined in three tiers: primitives (--palette-*, raw ramps nobody uses directly), semantic roles (--color-*, the only tokens components consume), and component tokens declared in components.css. The product ships a single light appearance; there is no dark theme and no theme switch.

  • Canvas and surface. Warm off-white canvas, white cards, panels, inputs and sidebar.
  • Text. Near-black default, a warm grey for secondary text, a lighter grey for placeholders and metadata.
  • Accent. Deep green for every primary action, link and selected state. The lighter brand green is for the logo and decorative marks only.
  • Status. Info, success, warning and danger each have a tint, a text colour, an edge and an icon colour.

Six ramps hold every raw value the product uses. Steps are numbered by lightness; only the steps the mocks needed exist. Do not add steps speculatively.

Drift

The mocks were written screen by screen, so the same intent appears in several near-identical values. The design system collapses each cluster to one token. Evidence is the style harvest at docs/design-system/.cache/harvest.md (56 distinct colour values across 193 files) and the compiled CSS in docs/mocks/assets/styles/. Nothing here changes what the product is for; it removes accidental variation.

Usage

  • Use a role, not a ramp step: write var(--color-accent), never var(--palette-green-700) in a component.
  • One accent action per view. Selected and active states use --color-accent-subtle with --color-fg-accent text.
  • Use --color-brand only for the logo, avatars and decorative marks. It does not carry text.
  • Secondary text uses --color-fg-muted; placeholders and metadata use --color-fg-subtle. Never lower text contrast with opacity.
  • Status colours come as a set. Pair --color-*-bg with --color-*-fg; do not mix a tint from one status with the text of another.

Accessibility

Every foreground and background pairing the product relies on is listed in tokens/contrast-pairs.json and rendered below. Ratios are computed live in your browser from the resolved token values. Normal text needs 4.5:1 (WCAG 1.4.3); non-text elements such as control edges, icons and focus rings need 3:1 (1.4.11, 2.4.11). Disabled text is exempt.

  • Two tokens change with the user's contrast preference. Under prefers-contrast: more, --color-border-default takes the strong border colour, and --color-fg-muted and --color-fg-subtle step up to darker greys.
  • Under forced-colors: active, borders and the focus ring take system colours.
  • Colour is never the only signal. Status badges carry words; invalid fields carry an error message and aria-invalid.
