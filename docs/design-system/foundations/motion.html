Foundation · Motion

Motion

Short, calm motion that shows what changed and never makes anyone wait, and none at all when the device asks for reduced motion.

Overview

Motion in the Coop admin explains a change: a dialog rises from where it will sit, a saved message slides into its corner, a switch slides to its new position. Many of the people who use the admin are older, and some find movement distracting or unsettling, so motion here is short, small and quiet. It never decorates, never loops except to show that something is loading, and switches off completely when the device asks for reduced motion.

  • Use a duration token and an easing token together; never a raw ms or s value or a named CSS easing.
  • Nothing animates when a page loads, apart from a loading indicator while content is on its way.
  • Animate opacity, translate, scale and rotate; do not animate layout properties such as width or height.

Durations

Each dot travels the same distance with --ease-standard; only the duration changes. Under reduced motion they jump.
TokenUse in the admin
--duration-instantState changes that must not animate: the selected tab, the current page in pagination, a checked checkbox
--duration-fastHover and colour changes on buttons, sidebar links, table rows, tabs and metric cards; the tooltip fade
--duration-baseThe switch thumb, a saved message entering and leaving, the dialog backdrop fade
--duration-slowA dialog or bottom sheet entering, such as "New page" or "Add director"
--duration-deliberateProgress fills, such as a file upload in the Assets library
--duration-loopOne cycle of a looping indicator; the spinner turns once every half cycle

Easing

The same 320ms with four curves. Spring overshoots a little and settles.
  • Standard for things that change in place: hover colours, progress fills, the switch track colour.
  • Enter (decelerate) for things arriving: dialogs, bottom sheets, menus, saved messages.
  • Exit (accelerate) for things leaving: a dismissed message.
  • Spring for one thing only: the switch thumb, so turning a setting on feels like a physical switch. It overshoots by a few pixels over 200ms; nothing else in the admin uses it.
The switch thumb moves with --duration-base and --ease-spring. Turn it off and on to feel the settle.

Loading loops

Loading the board list…
Loops share --duration-loop (1400ms). The skeleton shimmer runs one cycle per loop; the spinner, inside a busy button or beside a loading message, turns twice as fast.

A loop always sits beside words that say what is loading ("Loading the board list…") or inside a button whose label stays readable to assistive technology. A loop on its own tells nobody anything.

Choreography

  • Dialogs fade the backdrop (base) and slide the panel up from the bottom on phones, or scale it in from 96% from 640px (slow, enter). Closing is instant; nobody waits to get back to the page.
  • Saved messages ("“About us” is now on the website.") slide up 16px into place (base, enter) and fade and drop 8px as they leave (base, exit).
  • Menus and tooltips fade in (fast). A tooltip waits 300ms before showing so it does not flicker as the pointer passes.
  • Sidebar links, tabs and rows change colour on hover (fast, standard). They never move or grow.
  • Sign-in: .stagger in components.css lets the sign-in fields rise in one after another (slow, enter, a third of fast between each). It is the only motion on page load that the system allows, it is optional, and reduced motion removes it.
  • Once a page has settled nothing moves on its own except a loading indicator.

Reduced motion

Under prefers-reduced-motion: reduce, tokens.css sets every duration to 0.01ms, so transitions and entrances become instant without any change to a component. components.css also stops every loop after one pass and turns the skeleton shimmer off. The spinner still shows, as a still ring, because it tells the person that something is happening.

  • Nothing flashes more than three times a second (2.3.1).
  • Smooth scrolling is turned off too.
  • Nothing carries meaning through motion alone: a saved message is also text in a live region, and a busy button also has aria-busy="true".
  • Test it in Chrome DevTools: Rendering, then "Emulate CSS media feature prefers-reduced-motion".

Usage

  • If a motion does not explain a change, remove it.
  • Never hold input behind an animation; a dialog's buttons work while it is still easing in.
  • Keep motion small. Nothing slides across the whole screen, and nothing bounces except the switch thumb.

Sources and drift

Motion values are adopted from the Shelfie design system. The admin screens that move are the dialogs, saved messages and loading states: dialogs/admin-page-editor/default, dialogs/admin-page-editor/busy, pages/admin-board/loading, pages/admin-documents/loading, notifications/admin-page-saved/success and pages/admin-roles/default (the privilege toggles, which the system draws as switches).

Drift from the implemented admin

  • Transitions are raw values: transition: 0.2s on .nav-item, border-color 0.2s on form fields, color 0.2s on .tab-item, and width 0.3s on a progress bar. The system uses --duration-fast or --duration-base with an easing token.
  • The .spin loading icon turns once a second (1s linear infinite); the system spinner turns every 700ms (half of --duration-loop).
  • The implemented admin has no prefers-reduced-motion rule, so its spinners and transitions keep running for people who asked for less motion. The system zeroes every duration in tokens.css.
  • The Shelfie celebration, confetti, sticker and animated sign-in background effects were removed; the admin has no use for them.
