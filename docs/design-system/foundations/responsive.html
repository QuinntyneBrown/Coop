Responsive

Designed at phone width first, readable at 400% zoom, and given a sidebar, columns and room at 768 and 1024px.

Overview

Co-op staff and board members use the admin on an office computer, a laptop at home, a tablet at a board meeting and sometimes a phone in the hallway. Many of them zoom the browser to read comfortably. Every screen is built for a narrow window first and gains a sidebar, columns and room as the window grows. A zoomed-in laptop and a phone get the same layout, so a person who zooms to 400% loses nothing. Breakpoint and grid tokens are on Layout.

  • Base CSS is the phone layout. Add to it with @media (min-width: 40rem | 48rem | 64rem); never undo a desktop layout with max-width.
  • Breakpoints are in rem, so they also respond to a larger default font size, not only to zoom.
  • Prefer intrinsic layouts that need no query: .cluster wraps, .grid--auto and .metric-grid fill, button rows use flex-wrap.
  • Spacing and type do not scale with the viewport; only --layout-gutter, --layout-margin and --layout-columns change.

Reflow and zoom

WCAG 1.4.10 asks that content reflows to a 320 CSS px wide window without scrolling in two directions. A 1280px laptop window zoomed to 400% is exactly 320 CSS px, so this is the test for everyone who zooms. Every admin screen must:

  • Fit 320 CSS px with no sideways page scroll and nothing cut off.
  • Keep every function: everything the sidebar reaches at 1280px is reachable at 320px.
  • Wrap long words, file names and email addresses (overflow-wrap: anywhere) instead of pushing the page wider.
  • Put wide data tables (Users, Invitations, Roles & Privileges) inside .table-wrap, which scrolls on its own. A table is the one allowed exception to one-direction scrolling, and the scroll area is keyboard focusable and labelled.
  • Keep fixed bars small: at 400% zoom the tab bar is still 64 CSS px, so no other bar may be fixed at the same time.

Touch and pointer

  • Every control is at least 44px tall (--control-height-md); small 36px buttons only sit in rows spaced 8px apart or more.
  • Nothing depends on hover. Row highlights and tooltips are extras; the same information is visible or reachable by focus without them.
  • No gestures are required: no swipe, no drag, no long press. Reordering directors and menu links uses "Move up" and "Move down" buttons.
  • (pointer: coarse) is not used to grow targets; they are already large on every device.
  • Fixed bars add env(safe-area-inset-bottom) so the tab bar clears a phone's home indicator.

Accessibility

  • Reflow (1.4.10) at 320 CSS px, which is 400% zoom on a 1280px window.
  • Resize text (1.4.4): all sizes in rem, so text grows with the browser's font setting as well as with zoom.
  • Orientation (1.3.4) is never locked.
  • Target size (2.5.8): 24px minimum everywhere, 44px for every control.
  • Focus not obscured (2.4.11): the fixed tab bar is cleared by .has-tabbar padding and saved messages sit above it.
  • Consistent navigation (3.2.3): the sidebar lists the sections in the same order on every page; the tab bar uses the same names where it overlaps.

Do and don't

Tokens

This page owns no tokens. Breakpoints, columns, gutters, margins, the sidebar width and the tab bar height are on Layout, and the interaction tokens (targets, control heights, focus ring) on Accessibility.

Sources and drift

The breakpoints and grid are adopted from the Shelfie design system; the shell switch comes from the admin's own sidebar and tab bar in pages/admin-dashboard/default, pages/admin-maintenance/default, pages/admin-users/default (a wide table with pagination) and pages/admin-roles/default (a wide grid of privileges).

Drift from the implemented admin

  • The implemented admin is desktop first: 16 rules use @media (max-width: 768px) and the tab bar uses @media (min-width: 769px) to hide itself. The system is mobile first with min-width queries in rem.
  • At 768px and below, the implemented .sidebar does not hide: it becomes a static block with all thirteen links above the page, and the .bottom-tab-bar shows as well. The system shows one or the other.
  • The implemented sidebar is a fixed 260px with margin-left: 260px on the content; the system's sidebar is 256px (--layout-sidebar-width) in a grid, sticky rather than fixed.
  • Full-height layouts use 100vh, which mobile browser bars can cut off; the system uses 100dvh.
  • The implemented tab bar pads the bottom with env(safe-area-inset-bottom, 8px), which matches the system's safe-area rule.
