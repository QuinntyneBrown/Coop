Overview

This page lists what the mocks actually do at each breakpoint, taken from the @media rules in docs/mocks/assets/styles/*.css. The product has three breakpoints (640, 768 and 1024 CSS pixels), no container queries, and no rules beyond those below. Anything not listed here (for example stacking of .form-row or a dialog turning into a bottom sheet) is not implemented.

The queries are not uniform: most use max-width: 768px (applies at 768 and below), the public shell uses min-width: 1024px and max-width: 1023px, and two use max-width: 640px and min-width: 640px. Token values are listed under Layout.

Forms and dialogs

  • Form rows. .form-row is a flex row with a 12px gap. No @media rule stacks it, so two fields stay side by side at phone width.
  • Dialogs. No @media rule changes them. They are fluid (width: 100% up to 400, 500 or 700px) inside an overlay with 16px padding and never become a full-screen sheet. See Layout: dialog widths.

Safe areas

Safe areas appear in one place: the bottom tab bar reserves the device inset under its labels.

  • Public shell and sign-in: padding: 8px 0 calc(8px + env(safe-area-inset-bottom, 0px)).
  • Admin tab bar: padding-bottom: env(safe-area-inset-bottom, 8px) (the fallback is 8px).
  • The profile page reserves 100px at the bottom and the public shell 72px so content clears the bar.

There are no env() uses for the top, left or right insets, and the mocks (and the Angular index.html files) declare width=device-width, initial-scale=1 without viewport-fit=cover, so the insets resolve to zero on devices that need them.

Requirements and drift

Requirements the design system sets

These are requirements, not implemented behaviour.

  • Layouts reflow to 320 CSS pixels without horizontal scrolling (WCAG 1.4.10). The mocks fail this: 77 admin mocks are wider than a 360px screen, by 42px to 313px (Users 462px wide, Messaging 673px). No public mock overflows.
  • Declare viewport-fit=cover wherever env(safe-area-inset-*) is used, so the tab bar actually clears the home indicator.
  • Show the bottom tab bar and the hamburger only where the sidebar is not shown, on both apps.
  • Do not disable zoom (user-scalable=no or maximum-scale); the mocks do not.
  • Keep targets at least 24px (--target-min), and 44px for primary phone actions.

Drift

  • The admin app changes navigation at 768px and the public app at 1024px, and the rules use different query styles (max-width: 768px, max-width: 1023px, min-width: 1024px). The system keeps both because the mocks implement both.
  • The public shell leaves the bottom tab bar displayed at 1024px and above, beside the sidebar; the sign-in page hides it. The system treats the sign-in behaviour as correct.

Usage

  • Design for 360px first, then add rules at 640, 768 and 1024. Prefer min-width queries for new rules.
  • Write the query with the pixel value; custom properties are not allowed inside media conditions.
  • Use rem for sizes; the breakpoints are 40rem, 48rem and 64rem in the tokens.
